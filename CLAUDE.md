# CLAUDE.md — точка входа

**Wander** — файловый проводник для Windows 11 (WPF, .NET 10), замена
Explorer: убрать лишнее, починить его баги, добавить удобств.

## Карта (`docs/<ИМЯ>.md`)

- ARCHITECTURE — код, механизмы, слои; «Настройки — окно и правила» —
  правила и шаги новой настройки
- PLAN — что делаем; DONE — что работает; BACKLOG — отложенное; TECHDEBT —
  мелочь по пути; REJECTED — отказы с причиной
- OPERATIONS — спека «Надёжное копирование» (0.6)
- WORKFLOW — роли (человек, Фабле, Опус), этапы, инструкции и их слова
- FINALIZING, PRERELEASE, RELEASING — финализация, подготовка к релизу,
  релиз
- QA — песочница, харнесс, smoke, чек-листы, матрица «трогал → проверь»
- PERFORMANCE — вес, старт, поставка; `measurements/` — замеры версий
- GUIDE — руководство пользователя; SITE — сайт и правила GUIDE;
  PROMOTION — индексация и продвижение: шаги, площадки, правила
- `deps.txt` — рёбра графа папок; CHANGELOG; CONTRIBUTING; SECURITY;
  README в корне — витрина

Новая сессия: этот файл → PLAN → ARCHITECTURE по задетому. Опус на блоке:
этот файл → WORKFLOW, «Блок по спеке» → свой блок PLAN.

**Списки.** Цель → PLAN; отложенная задача → BACKLOG; мелочь по пути →
TECHDEBT; не делаем → REJECTED с причиной; «когда-нибудь» → Roadmap;
закрытое → DONE, из PLAN **удаляется**, не помечается (FINALIZING, п. 4).
Остальные списки сам не чистить — по согласованию.

**Доки — сжато**: факты, решения, имена; история — CHANGELOG и гит; «см. в
X» — только где карта не отвечает. Решения человека 2026-09-29: даты —
только у решений человека и правил; «раньше было X» — причиной в один
оборот или удалить; заголовки и жирные начала пунктов, на которые
ссылаются другие доки, не переименовывать. Сжимать написанное — по
запросу. GUIDE — по своим правилам (SITE, «Как пишется руководство»).

## Столпы

1. **UX.** Лучше Explorer: без планшетных элементов Win11, OneDrive,
   3D-объектов и его багов (самосворачивающееся дерево, тормоза, потеря
   фокуса после операций). Интерфейс компактный (2026-09-17): понятный
   значок вместо слова, слова — в подсказке; подпись у контрола — только
   если без неё непонятно.
2. **Надёжность.** Деструктивное — диалог с **Cancel по умолчанию**; всё,
   кроме безвозвратного удаления, откатывает `Ctrl+Z`.
3. **Интеграция с системой.** Общий буфер, стандартный drag & drop,
   системные ассоциации и меню, привычные хоткеи. Изоляция — уступка:
   причина и цена — на обсуждение, решение — в BACKLOG. Интеграция не
   работает — остановиться и вынести.
4. **Скорость просмотра** (2026-09-21). Снимок открывается мгновенно на
   глаз: без мельканий, заглушек, смены кадра на виду; ориентир —
   FastStone. Замеры — PLAN AK.

## Правила кода

- Core без Windows и UI: ни `System.Windows.*`, ни COM, ни PInvoke; нужно —
  интерфейс в Core, реализация в `Wander.Platform.Windows`.
- WPF отвинчиваем: вьюмодели берут сервисы Core через `ServiceLocator`;
  композиция одна — `App.OnStartup` →
  `PlatformBootstrapper.RegisterDefaults()`.
- Без DI-контейнеров и MVVM-фреймворков (CommunityToolkit.Mvvm,
  ModernWpfUI, MahApps); без преждевременных абстракций.
- Тесты — только Core, фейки из `tests/Wander.Core.Tests/Fakes/`.
- **Сложность — туда, где её достаёт тест** (2026-09-01): машина состояний
  или вычислимое правило — в Core, «факты на входе, решения на выходе»;
  вью исполняет (`TileLayout`, `FolderChanges`, `FolderSession`).
- **Список не дёргается от изменения параметров**: правка внутри строки
  (оценка, метка, флаг) папку не пересобирает — ни перечитывания, ни
  потери выделения и фокуса, ни пересортировки под курсором; пересборка —
  только при смене **состава**; `Ctrl+Z` правки — так же. Механизм —
  ARCHITECTURE, «Запись оценки не пересобирает папку».
- **Выделенный файл не уходит с экрана сам** (2026-09-28): главная
  выделенная строка, стоявшая на экране, после любой посадки строк — на
  том же месте; отмотанную чужие изменения не возвращают; список в начале
  остаётся в начале. Новая посадка строк — только через модель окна
  (`LandRows`, `LandResults`); проверка — сценарий `follow-row`. Механизм —
  ARCHITECTURE, «Сессия папки».
- **Новая операция с файлами обязана**: `SystemPathGuard`, лог,
  `IUndoableAction` в `UndoService`, деструктивная — подтверждение с
  Cancel по умолчанию. Отступление — осознанное и записанное в доке.
- **Текст для пользователя** — только
  `src/Wander.App/Resources/Strings.resx`; Core — через `ITextSource`.

## Проверка

```pwsh
.\tools\check.bat          # build → format --verify → строки, ключи XAML → сайт → тесты
.\tools\check.bat run      # + smoke (окно за экраном); при финализации обязателен
.\tools\check.bat format   # применить форматирование
.\tools\check.bat qa       # харнесс: selfcheck + smoke-walk — только по просьбе
```

Из PowerShell, из корня; код 0 — зелено, иначе код первого упавшего шага.
Через `cmd /c` из bash не запускать: вернёт 0 и проглотит вывод. Точечно —
`dotnet build` / `dotnet test`, перед коммитом — полный. Сайт глазами —
сборка `--debug`; `--open` — ключ человека. `tools\metrics.ps1` — снимки
структуры «до / после» чистки, одним измерением; `tools\deps.ps1
-UpdateDoc` — после правок `using`-ов и раскладки папок (циклов между
папками нет).

## Экран, ввод, данные человека

- **Ввод не эмулировать, окна поверх экрана не поднимать**: ни
  `SetCursorPos` / `mouse_event` / `SendKeys` / `SetForegroundWindow`, ни
  кликов «проверить» — на этом экране работает человек.
- **Сценарии харнесса** (`Wander.Harness run`, `check.bat qa`) — только по
  словам «прогони / запусти автотесты …» и «готовимся к релизу»
  (2026-09-16); «финализируй» их не запускает: назвать задетые и ждать.
  Из сессии Claude — с `--rebuild`: `%TEMP%` и `%LOCALAPPDATA%` у
  инструментов виртуализированы, старая песочница пуста. Строки
  `HEADLESS` прогона — в отчёт.
- **Данные человека** (2026-09-04): его копия — `C:\Programs\Wander`,
  данные — `%LOCALAPPDATA%\Wander`. Exe запускать только с `--data-dir`
  под `artifacts\` и `--folder` на тестовую папку (`tests\Fixtures`,
  песочница); `publish.ps1 -Run` / `-Install` и голый `Wander.exe` — нет.
  `state.json` и логи человека из сессии видны устаревшей копией —
  спрашивать, не читать.
- Чего не проверить — в отчёт списком «посмотреть глазами».

## Git — только чтение

`status`, `log`, `diff`, `show`, `ls-files`, `ls-tree`, `blame`,
`check-ignore`, `tag` (список). Мутирующее (`add`, `commit`, `reset`,
`revert`, `checkout`, `restore`, `branch`, `merge`, `rebase`, `stash`,
`tag <имя>`, `push`, `pull`, `mv`, `rm`) — человек; без явной просьбы не
делать. Файлы двигать на ФС, не `git mv`; `.gitignore` править, не
`git rm --cached`. Результат незастейджен, в отчёте — что изменилось.
Скрипты `tools\` git-команды печатают, не выполняют.

## Кодстиль

`.editorconfig` + `dotnet format`. 1TBS (`} else {`, `} catch {`), скобки
везде; file-scoped namespace `Wander.<модуль>.<раздел>`; `var`, где тип
виден, примитивы — явным типом; `_camelCase` у private-полей, остальное
PascalCase; 4 пробела; пустая строка после `return` / `continue` / `break`
и между блоками, две — между полями и методами. **Комментарии в коде —
только ASCII** (`-`, `"`, `->`, `...`); типографика — в маркдауне и
`Strings.resx`.

**Порядок членов** (O9, 2026-09-01): константы → поля → конструктор →
свойства и события → публичные методы → приватные помощники → вложенные
типы. Без `#region`. Баннер — только `// --- Заголовок ---`, порядок —
внутри раздела, голова класса — до первого баннера. Исключения: приватное
поле прямо над своим свойством (`_showHidden` + `ShowHidden`); блок
P/Invoke целиком внизу файла (в `ShellContextMenuInterop` порядок членов =
порядок vtable).
