гите, не в снапшотах; «см. в X» — только там, где карта выше не отвечает.

## Столпы

1. **UX.** Лучше встроенного проводника: без планшетных элементов Win11,
   OneDrive и 3D-объектов; без его багов (самосворачивающееся дерево,
   тормоза, потеря фокуса после операций); с удобствами (поддеревья,
   детальный просмотр, много форматов).
2. **Надёжность.** Любая деструктивная операция — диалог с **Cancel по
   умолчанию**. Всё, кроме безвозвратного удаления, откатывается `Ctrl+Z`.
3. **Интеграция с системой.** По умолчанию — общий буфер обмена, стандартный
   drag & drop, системные ассоциации и меню, привычные хоткеи. Изоляция
   «своё внутри» — осознанная уступка: причина и цена выносятся на
   обсуждение, решение и варианты пишутся в BACKLOG (пример — «Буфер
   обмена» там). Обнаружил, что интеграция где-то не работает, —
   остановиться и вынести, а не оставить как есть.

## Архитектурные правила

- `Wander.Core` не зависит от Windows и UI: никаких `System.Windows.*`,
  COM, PInvoke. Нужно — интерфейс в Core, реализация в
  `Wander.Platform.Windows`.
- WPF — отвинчиваемый слой: ViewModel'и дёргают сервисы Core через
  `ServiceLocator`; WPF-специфики в Core нет.
- Одна точка композиции: `App.OnStartup` → `PlatformBootstrapper.RegisterDefaults()`.
- Статический Service Locator, без DI-контейнеров; без MVVM-фреймворков
  (CommunityToolkit.Mvvm, ModernWpfUI, MahApps).
- Тесты — только Core, через фейки из `tests/Wander.Core.Tests/Fakes/`.
- Минимализм: UI ↔ логика минимальным срезом, без преждевременных абстракций.
- **Сложность выносится туда, где её достаёт тест** (2026-09-01). Машина
  состояний или вычислимое правило (листинг, намерения выделения, геометрия
  раскладки, решения сторожа) живёт в Core за чистым контрактом «факты на
  входе, решения на выходе»; вью и code-behind исполняют. Прецеденты:
  `TileLayout`, `FolderChanges`, `FolderSession`.

**Список не дёргается от изменения параметров.** Правка того, что показано
внутри строки (оценка, метка, любой флаг), не пересобирает папку: ни
перечитывания, ни потери выделения и фокуса, ни пересортировки под курсором.
Пересборка — только при изменении **состава** (появились, исчезли,
переименовались). Держится тремя вещами, все обязательны:

- сторож папки сообщает `DirectoryChange` (путь + изменился ли состав),
  решение принимает `FolderSession.DecideWatchTick` поверх `FolderChanges`:
  `Refresh()` либо перечитывание затронутых строк;
- `FileSystemEntry` — record, правка = замена объекта; `ReconcileEntries`
  оборачивает каждую пересборку `Entries` и возвращает выделение без
  прокрутки и переноса фокуса;
- служебные файлы (`TransientFiles`: наш `.wander-tmp`, виндовый
  `~RF….TMP` от `File.Replace`) не считаются изменениями.

`Ctrl+Z` такой правки идёт тем же путём — `IUndoableAction.MetadataTargets`.

**Новая операция с файлами обязана:** пройти `SystemPathGuard`,
залогироваться, положить `IUndoableAction` в `UndoService`, если
деструктивна — спросить подтверждение с Cancel по умолчанию. Отступление —
осознанное и записанное в доке рядом с кодом (пример: восстановление из
корзины без undo).

**Пользовательский текст — только через ресурсы**
`src/Wander.App/Resources/Strings.resx`. Core просит текст через
`ITextSource`, ссылки на App у него нет.

## Проверка

Из PowerShell, из корня репозитория:

```pwsh
.\tools\check.bat          # build → dotnet format --verify-no-changes → сверка строк → тесты
.\tools\check.bat run      # то же + smoke-запуск (окно за экраном, само закрывается)
.\tools\check.bat format   # применить форматирование (пишет файлы)
.\tools\check.bat qa       # сборка + харнесс: selfcheck и smoke-walk (минуты, отдельно)
```

Шаг «строки» — `tools\check-strings.ps1`: ключи ресурсов в коде и XAML
против `Strings.resx` в обе стороны (опечатка в ключе компилируется молча и
всплывает в интерфейсе). Exit code 0 — зелено, иначе код первого упавшего
шага. Не запускать через `cmd /c` из bash — возвращает 0 и глотает вывод.
Точечно можно `dotnet build` / `dotnet test`, перед коммитом — полный
`check.bat`.

- `tools\metrics.ps1 [-Out file]` — измерение структуры: строки по проектам,
  крупные файлы, публичная поверхность Core, места
  `ServiceLocator.IsRegistered`, длинные методы, вложенность, `using` на
  файл. Снимки «до/после» техчистки обязаны быть одним измерением. Грубый
  сканер скобок, важна повторяемость.
- `tools\deps.ps1 [-UpdateDoc]` — граф `using`-ов по папкам: рёбра, уровни,
  циклы. Правило «между папками нет циклов» и снимок — в ARCHITECTURE.md,
  `-UpdateDoc` перезаписывает блок там после правок `using`-ов или
  раскладки.

### Экран и ввод — не трогать

Claude не эмулирует ввод и не поднимает окна поверх экрана: никаких
`SetCursorPos` / `mouse_event` / `SendKeys` / `SetForegroundWindow`, никаких
кликов «чтобы проверить» — рядом на том же экране работает человек.
Исключение — `check.bat run`: `--smoke` поднимает окно за экраном без фокуса
и панели задач, само закрывается; при финализации скоупа обязателен.

Чем проверять: сборка, тесты, `check-strings`; логи `%LOCALAPPDATA%\Wander\logs`;
**`tests/Wander.Harness`** — настоящее окно за экраном на сгенерированной
песочнице, данные в `artifacts\<run>\data` (чужой `state.json` не
трогается), скриншоты, метрики, диалоги по политике:

```pwsh
$h = "tests\Wander.Harness\bin\Debug\net10.0-windows10.0.19041.0\Wander.Harness.exe"
& $h selfcheck                                            # генераторы против читателей Core
& $h run tests\Wander.Harness\Scenarios\smoke-walk.json   # артефакты в artifacts\
```

Восемь сценариев: `smoke-walk`, `focus-keys`, `tree-bookmarks`, `file-ops`,
`search`, `preview-formats`, `watcher`, `soak`. Десять профилей песочницы.

Шаги, профили, правила — QA.md. Разовый консольный харнесс в scratchpad —
для одного класса. Что проверить нельзя — списком «что посмотреть глазами»
в отчёт, человек прокликает сам (чек-лист в приложении — PLAN N).

Текущее состояние: 905 тестов, формат чистый, 434 строки ресурсов.

## Git — только чтение

Claude выполняет только читающие команды: `status`, `log`, `diff`, `show`,
`ls-files`, `ls-tree`, `blame`, `check-ignore`, `tag` (список). Всё
мутирующее (`add`, `commit`, `reset`, `revert`, `checkout`, `restore`,
`branch`, `merge`, `rebase`, `stash`, `tag <имя>`, `push`, `pull`, `mv`,
`rm`) — человек, без явной просьбы не делать. Файлы перемещать обычным
перемещением на ФС, не `git mv`; `.gitignore` править, а не `git rm --cached`.
Результат остаётся незастейдженным, в отчёте перечисляется, что изменилось.
Скрипты в `tools\` печатают git-команды, но не выполняют.

## Кодстиль

Зафиксирован в `.editorconfig`, `dotnet format` применяет. Выжимка: 1TBS
(`{` на той же строке, `} else {`, `} catch {`); braces обязательны везде;
file-scoped namespaces `Wander.<модуль>.<раздел>`; `var` где тип виден,
явный тип для примитивов; `_camelCase` private-поля, PascalCase остальное;
4 пробела; пустая строка после `return` / `continue` / `break` и между
блоками, две — между полями и методами. **В комментариях кода только
ASCII**: `-`, `"`, `->`, `...` — типографика в маркдауне и `Strings.resx`,
не в коде (в диффе `-` от `—` не отличить, и файл уже превращался в кашу при
пересохранении не тем инструментом).

**Порядок членов** (O9, 2026-09-01): константы → поля → конструктор →
свойства и события → публичные методы → приватные помощники → вложенные
типы. Без `#region`: лекарство от «не найти» — файл поменьше. Файл с
баннерами `// --- Заголовок ---` (единственная форма баннера) держит порядок
внутри каждого раздела; голова класса — до первого баннера. Исключения:
приватное поле прямо над своим свойством (`_showHidden` + `ShowHidden`,
`GifUriProperty` + `GifUri`); блок P/Invoke целиком внизу файла (в
`ShellContextMenuInterop` порядок членов интерфейса = порядок vtable).

## Roadmap

- **Тёмная тема.** Все цвета уже в `Resources/Palette.xaml` (O8); галерея и
  панель просмотра берут цвета из `GalleryPalette`. Расширять оттуда.
- **Фильтры поиска по дате, размеру и regex** — нужна форма диапазонов, та
  же, что фильтру по ISO / выдержке (PLAN, J3); делать один раз на обе.
- **Плагины** — если идея зайдёт.
- **Symlinks / junctions / hard links** — сейчас только `.lnk`.

Вкладки переехали в BACKLOG (2026-08-27): разделение внимания между папками
уже решают дерево, закладки и история; цифры под `Ctrl` заняты областями
окна.
