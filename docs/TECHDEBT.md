# Wander — технический долг

Мелочь, замеченная по пути и сознательно отложенная: одна-две строки, место
и суть. Чистится заходом, не вперемешку с фичами. Перед релизом список
разбирается целиком (PRERELEASE.md, шаг 2): критичное — в PLAN, серьёзное —
на обсуждение, остальное остаётся. Закрытое удаляется (история — CHANGELOG
и гит). Последний разбор — 2026-09-30 для 0.5.0.

## Список файлов и навигация

- **`IsCutRow` — `MultiBinding` из двух привязок в каждом контейнере** (R3,
  намеренно). По-настоящему — attached-свойство плюс хук подготовки
  контейнера в обеих семьях панелей; ~80 строк, в замеры не попало.
- **Бросок из обработчика `CollectionChanged` глотается** (2026-09-22).
  `SyncEntries` идёт из `SearchController.ApplyAsync`, вызываемого как
  `_ = ApplyAsync()`: исключение панели посреди уведомления (краш
  2026-09-22) оставляет план полуприменённым, остальные панели-слушатели
  уведомления не получают, а в лог попадает лишь «Unobserved task
  exception» из финализатора — минуты спустя. Ловить в `ApplyAsync`,
  писать сразу, после сбоя — перечитать папку.
- **`ListingDiff` — квадратичный худший случай** («половина строк уехала
  далеко»; полный разворот уходит в пересборку, `Wholesale`). Честная
  O(n log n) — дерево Фенвика; по логам не встречалось. `Move` /
  `Replace` с блока 2 считаются в `MaxReconciledChanges` — предел на все
  правки.
- **`IconImageCache` растёт по путям у `Small` / `Normal`** (2026-09-21):
  ключ — `(размер, путь)`, каждая пройденная строка оставляет `BitmapImage`
  (~4 КБ), `ThumbnailBudget` считает только `Medium` / `Large`. Ключ по
  `byte[]` (общий на тип) снял бы рост и повторный декод; `Forget` не чистит
  `_thumbOrder` (`Trim` стерпит ключ без картинки, но положенный снова
  после `Forget` стоит в очереди дважды и уходит раньше срока). Оценка
  2026-09-30: растут только строки, побывавшие на экране в «Таблице»,
  «Плитке» и панелях папок; живая сессия на 93 папки (2551 строка) — единицы
  мегабайт, в `SYS` не видно. Дёшево — вторая очередь с потолком по числу,
  как у миниатюр (~15 строк).
- **Итог операции затирается счётчиком папки** (2026-09-30): сообщение,
  сказанное между началом чтения новой папки и очисткой строк
  (`RefreshFolderAsync`, первый `Dispatcher.Yield`), заменяет «Элементов: 0»
  очистки, и после посадки возвращается счётчик, а не оно. Окно — кадр;
  лечится счётчиком «сказанного» вместо сравнения текстов.
- **`ui.stall` 0,4–0,55 с на уходе из окна** (живые логи 2026-09-29 / 30):
  пачка `WindowDeactivated` → `WindowActivated` → `WindowDeactivated` за
  60 мс (снимок экрана, перетаскивание из другой программы), следом —
  остановка UI; рядом в логе только перечитывание раскрытых веток, оно с
  пула. Человек в этот момент не в окне; причина не разобрана.
- **`Ctrl` + стрелки на границах сетки** — двигают курсор без выделения, а
  отдельного курсора нет (`Shift` обошёлся якорем). Внутри сетки делает WPF,
  края отданы ему осознанно (комментарий в `TryGridStep`). Нужен свой
  курсор, синхронизированный с фокусом контейнера.
- **`Shift`+клик считает диапазон от нашей каретки**, а не от якоря WPF:
  после клика по пустому месту расходятся.
- **Адресная строка берёт фокус отложенно** — `BeginAddressEdit` через
  `Dispatcher.BeginInvoke`; проверка сразу после `Tab` / `Alt+D` видит
  старый фокус.
- **Две ошибки привязки при фильтрации** — `Error: 4` про
  `Horizontal/VerticalContentAlignment` на переиспользуемом `ListBoxItem`;
  задать оба на самом `ListBox`.
- **`AsyncIcon` стартует лишнюю загрузку на дефолтном размере** — `IconPath`
  применяется раньше `IconSize`. Coalescing через `Dispatcher`, если заметно.
- **`TileLayout` предполагает одинаковые ячейки** — подпись `Height`, высота
  строки `шрифт × 1,35`, не `FormattedText`; экзотический шрифт обрежет.
- **Пересортировка по оценке — ординальный компаратор имён**
  (`StrCmpLogicalW` приватен в `SystemIOFileSystem`): `IMG_10` перед `IMG_9`.
  Компаратор в `IFileSystem` или сортировка листинга наверх.
- **`Alt` над полосой фильтра гасит клик молча** — обычный клик или слово в
  статусе.
- **Рамка в Таблице — угол по средней высоте строки** (блок 2, 2026-09-23):
  `RubberBandController.PixelOffset` = `VerticalOffset × ActualHeight /
  ViewportHeight`; `DataGrid` прокручивает строками, а в `ActualHeight` ещё
  заголовок и неполная строка — на длинной протяжке угол может съехать на
  долю строки. Честно — прямоугольник строки по индексу. Глазами — QA,
  «Рамка выделения за край».
- **`FocusLine` панели ждёт контейнер приоритетом `Loaded`, не генератором**
  (ревью блока 2, 2026-09-24): `FolderTreesView.FocusLine` при
  нереализованной строке откладывает фокус `Dispatcher.BeginInvoke(Loaded)`
  с проверкой `IsKeyboardFocusWithin`; строка далеко за экраном в
  виртуализированном списке может не получить контейнер к этому проходу —
  фокус тихо остаётся на списке. У `FileListView` то же сделано по
  `ItemContainerGenerator.StatusChanged` (`_pendingFocus`); сделать так же.

## Поиск

- **Спутники всплывают отдельными строками в результатах фильтра** — проход
  поиска не сворачивает (`CompanionResolver`). Вместе с «путь у результата»
  (BACKLOG).
- **Галочка «в подпапках» описывает только окно** — фильтр всегда достаёт
  подпапки.
- **Окно поиска не помнит геометрию** — второй блок как `WindowGeometry`.
- **Папку поиска нельзя выбрать, только увидеть** — кнопка обзора.
- **Системный фильтр падает на `.doc`, который не Word** (живой лог
  2026-09-30, `read me.doc` из архива и с диска): `FilterTextExtractor`
  получает `NullReferenceException` из нативного кода фильтра, ловит его
  вызывающий (`ContentSearchService`) — `WARN` на каждый выбор файла,
  панель пишет «нет просмотра». Ловить в самом экстракторе рядом с
  `COMException`; текстовый `.doc` старых архивов читать как текст
  (`TextProbe`), когда фильтр отказался.
- **Побайтовый поиск читает файл дважды** — `PlainTextExtractor`, потом
  `MatchesRawBytes`: 748 мс против 60 на 523 файлах.
- **`PruneMissingAsync` — stat на каждую строку**; затронутые пути знает
  `BatchExecutor`.
- **`SearchController`: `FilteredChanged` может выстрелить после `Reset()`**
  — check-then-act между токеном и `Invoke`. Поколение запроса вместо токена.
- **Поиск из окна поиска начинает с пустого списка** (2026-09-28):
  `SearchResultsController.Begin` кладёт пустую выдачу, выделение уходит с
  ней, и файл, выделенный до поиска, в результатах не выделен, даже если
  найден. Поиск из поля фильтра строки держит (`IsFilterPass`). Лечить
  памятью о выделении на время прохода, а не выделением строк, которых нет
  в списке: по нему работают команды.

## Панель просмотра и миниатюры

- **Аудио без обложки занимает место в кэше как с обложкой** —
  `BuildCacheKey` по пути; после неудачи — ключ по расширению.
- **Миниатюра ярлыка не сбрасывается при замене оригинала** — подмешать
  mtime цели.
- **Оценку предлагают только картинкам** (`OfferRating`, `ImageFormats`) —
  осознанно; видео / PDF — одна строка.
- **Подпись большой программы не запоминается** (блок 8, 2026-09-24):
  «Проверить» на установщике в 3 ГБ, ушёл и вернулся — снова «не
  проверялась», и проверка читает файл заново. Итог по пути + размер +
  время — словарь в `PreviewController`.
- **Полный кадр для лупы вне бюджета картинок** (замер 2026-09-24):
  `ZoomSource` после 150 мс на снимке — 96 МБ у CR3 на панель,
  `PictureMemory` его не считает; пик WS на CR3 (923 МБ) — он и нативные
  битмапы, не кэш. Считать в долю кадров или отпускать раньше.
- **Полоса снимка под WebView2** (блок 8): полоса со звёздами теперь у всего,
  чему предлагается оценка, но поверх WebView2 WPF не рисует — у PDF или
  HTML со своим `.xmp` в половине сплита звёзд не видно. Редкость; всплывёт
  — для `Kind = Web` звёзды в футер.
- **Перепись папки обходит дерево целиком, кэша нет** — шара или корень
  диска считаются секунды. Кэш по пути + mtime или пересчёт по кнопке.
- **WebView2 init 1–2 с при первом обращении** — прогрев на старте, если
  панель включена.
- **Папка WebView2 с другими параметрами у второго экземпляра** (AD1,
  2026-09-25): профиль берёт один набор `CoreWebView2EnvironmentOptions`;
  установленная 0.4.1 (без аргументов) и отладочная сборка с `--yield` на
  тех же данных — у запущенной второй веб-просмотр, вероятно, пустой, пока
  первая открыта (не проверено; исключение глотает
  `EnsureWebViewReadyAsync`). Пройдёт с установкой 0.5; при нужде — строка
  в лог.
- **AvalonEdit без XAML-грамматики** — xaml как plain XML.
- **HTML: JS включён** — сеть и попапы отрезаны, скрипты локального `.html`
  исполняются (`IsScriptEnabled` глобальный, PDF-viewer без него не живёт).
- **Иконки грузятся с MTA** — apartment-threaded провайдеры могут вернуть
  пусто. Замер 2026-09-21: `GetOverlayIndex` (`SHGFI_OVERLAYINDEX`) с пула
  ждёт общий host-STA — долгий вызов там держит все четыре слота `AsyncIcon`
  (`slow shell load` с одинаковым временем). Корзину оттуда убрали; без неё
  то же на `D:\Dev\lekta\Wander` (~1,9 с), виновник — вероятно,
  overlay-обработчик. `GetImage` не блокируется. Релизный smoke
  2026-09-30 на `tests\Fixtures`: `slow shell load: 1062 ms`, и дочерним
  процессом Wander в ту же секунду поднялся `TGitCache.exe` — похоже,
  первый запрос overlay TortoiseGit запускает его кэш.
- **Слот значка не отпускается при уходе из папки** (2026-09-18) — начатый
  shell-вызов не отменить, зависшие значки держат следующую папку.
- **Окно совпадений: значки мигают при прокрутке** (ревью 2026-09-21).
  `AsyncIcon` на `ConflictRowViewModel` не знает, папка ли строка;
  `TryGetCachedIcon(isFolder: null)` отвечает только путевыми ключами. Брать
  `Kind` стороны по `IconPath`, но заглушки `Unknown()` из `BatchExecutor` /
  `ExtractionService` всегда `File` — для папки нужен null.
- **Несколько массивов на один общий ключ значка** (ревью 2026-09-21):
  одновременные промахи по `ext|.txt|Normal` кладут разные `byte[]`,
  «проигравшие» декодируются заново на UI-потоке. `Store`, который оставляет
  первый.
- **`AsyncIcon.RowIsFolder` зовёт `Archives.Of` на UI-потоке** для узла
  дерева — `File.Exists` на перерисовку. Флаг корня архива хранить на узле.
- **Папки «Таблицы» и миниатюры делят бюджет 512** — в папке на 600 подпапок
  значки вытесняются и мигают при прокрутке назад.
- **`TryGetCachedIcon` для `Medium` ходит на диск под замком провайдера**
  (`IsThumbnailable` → `Directory.Exists`, у записи архива — `File.Exists`)
  на UI-потоке.
- **Пиксели в футере — как лежат в файле**: при ориентации 5–8 панель рисует
  портрет, строка пишет `1620 × 1080` (и `ShotSummary`). Решить, чей счёт.
- **Кадр под зажатой лупой, если загрузка упала не отменой** (ревью

## Файловые операции и корзина

К блоку «Надёжное копирование» (PLAN K) относятся первые пять.

- **`MoveEntry` cross-volume — нет уборки при частичном сбое**: частичная
  копия или дубликат при неудавшемся delete. Отмена — не этот случай
  (`CopyFileEx` убирает недописанное, частичная папка кладётся в undo).
  Ожидание занятого для папки — только в пределах тома (2026-09-21).
- **Безвозвратное удаление не ждёт занятый** — `DeleteForGood` проверяет
  только заявки операций.
- **Папка, удалённая навсегда наполовину, оставляет шаги в истории**
  (2026-09-29): `DeleteManyCore` отдаёт `UndoService.Forget` только пути
  со статусом `Ok`; у папки, чьё удаление упало на середине, часть
  содержимого ушла, а шаги про него остались — их откат кончится «путь не
  найден» в отчёте отмены.
- **Откат не отпускает панель просмотра** — `ReleasePreview` стоит перед
  удалением, переносом, переименованием, не перед `Ctrl+Z`. Шире — PLAN
  K («`Ctrl+Z` ждёт занятых»).
- **Папка с занятым файлом внутри — «занято» ли это для Windows** (не
  проверено): `Directory.Move`, вероятно, отвечает `ERROR_ACCESS_DENIED`, и
  `BusyGate.Retry` не ждёт. Стенд.
- **Строки отката: английское `Description`** — `StatusUndone` показывает
  `IUndoableAction.Description` («delete of 3 items»). К PLAN AD5.
- **Провал извлечения: коды движка — по-английски** (блок 8, 2026-09-24).
  Причину названную (`ShellArchiveFolder.Failure`) статус говорит текстом
  системы: для `0x80070070` и подобных он русский, а свои коды движка
  копирования (`COPYENGINE_E_*`, «съёмный диск полон») .NET не знает —
  «Exception from HRESULT: 0x8027…». Частые — в строки ресурсов.
- **«Открыть» из архива с паролем — английская строка** (блок 8):
  `OpenArchiveEntryAsync` пишет `ex.Message`; на `ArchiveLockedException`
  место `StatusArchiveLocked`, как у извлечения.
- **Извлечение: отмена — между элементами**. Бар внутри элемента едет
  (`IFileOperationProgressSink.UpdateProgress`, процентом), отмена — только
  `PreCopyItem`.
- **Конфликты при извлечении — по верхнему уровню**: папка поверх папки
  спрашивает один раз, дальше решает шелл. Как у копирования папки на папку.
- **Извлечение уплощает пути** — цель = `targetFolder + имя листа`; две
  записи с одним именем из разных подпапок метят в один файл. Руками так не
  выделить.
- **Conflict: «Оставить оба» = auto `(1)`**, без диалога имени.
- **«Извлечь рядом» распаковывает пары для сравнения зря**
  (2026-09-23): `ExtractionService.UnpackForComparison` идёт до
  `ResolveAll` при любом резолвере, а `FixedConflictResolver` байты не
  смотрит — до 32 распаковок впустую. Спрашивать резолвер, нужно ли ему.
- **Окно совпадений строит вьюмодель на каждую пару сразу** — мерить на
  живой большой папке.
- **Проверка длинного пути обходит папку на каждом шаге ожидания** (ревью
  2026-09-21) — `ShellRecycleBin.TooLongForBin` из `SendMany`, `RetryMany`
  шлёт каждые 200 мс; сотни тысяч файлов — десятки секунд. Запоминать на
  операцию.
- **Исключение посреди корзины теряет откат уже отправленного** (редко):
  `DeleteManyCore` уходит до `PushComposite`. Ловить по прогону, шаги отката
  собирать из готового.
- **Откат переименования с обменом имён — цепочка зависимых шагов**:
  `UndoService.Unwind` считает их независимыми; сбой в середине оставляет
  `имя.<hex>.wander-tmp` на виду.
- **«Восстановить» в корзине — на UI-потоке** (`RestoreFromRecycleBin`): до
  ~270 мс на элемент, без прогресса и отмены.
- **Возврат из корзины — прогон на элемент** — ~15 мс на файл, откат 5000 —
  больше минуты. Пачкой — 3 мс (стенд). Нужен `IRecycleBin.RestoreMany` и
  размотка подряд идущих `DeleteAction` одним вызовом. COM — заход Фабле.
- **Порог длинного пути для корзины не измерен** — 259 по документации,
  стендом проверены 263 и 349. Мерить — только на машине без человека
  (PLAN T).
- **Одиночный `.gz` показывает запись размером 0** (стенд 2026-09-25):
  `PKEY_Size` отвечает 0 — «неизвестно»; `ShellArchiveFolder.SizeOf` это
  уже знает, строка листинга (`BuildEntry`) — нет.
- **Три копии помощников `IShellItem`** (`CreateItem`, `DisplayName`,
  `Release`, `CreateFileOperation`) в `ShellArchiveFolder`,
  `ShellRecycleBinFolder`, `ShellRecycleBin` — место им в `ShellItemInterop`.
- **`SystemPathGuard` фаза 2** — warn вместо block для Program Files и чужих
  профилей, переопределение в настройках; запись внутрь (`MayWriteInto`,
  блок 8) запрещена только в дерево Windows.
- **Корзина: статичная иконка** — empty / full раз за сессию; инвалидировать
  при Restore / Empty или `SHChangeNotifyRegister`.
- **Одиночные `Copy` / `Move` / `Delete` синхронные** — зовут только тесты.
- **Undo не переживает рестарт** — стек в памяти.
- **`state.json` без миграций** — старый файл → `new AppState()`. Pre-1.0 ОК.

  `%LOCALAPPDATA%\Programs\Pandoc`; куда ставит per-user MSI, не проверялось.

  пуле с отложенным ответом, как `LocateToolsAsync`.
