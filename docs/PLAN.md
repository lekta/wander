### Пины — [решение человека 2026-11-17]

Пин — долгоживущая пометка файла или папки, «выделение, которое не
сбрасывается» (образец — FastStone): отметить при отсмотре, потом показать
или выделить только отмеченное. Любые файлы, не только снимки; в папку
файла ничего не пишется — этим отличается от цветной метки. Имя в коде —
`Pin`. Примерка принята: `docs/prototypes/pins/` (артефакт
`claude.ai/artifact/FqeBCrL7A4p3pS6oRQh36g`). Решения человека 2026-11-17 —
в скобках.

- **Хранение** — [своя база, JSON]: папка → имена, целиком в памяти,
  атомарная запись с задержкой после последней правки, дата пина на
  записи; доступ — интерфейс в Core. Съёмный носитель — ключ по серийнику
  тома, не по букве.
- **Пропавшее** — [диск на месте, файла или папки нет — пин удаляется;
  выключается настройкой]; [диск отключён — пин спрятан и хранится].
  Чистка — при листинге и при показе плашки, проверка существования — вне
  UI-потока. При выключенном удалении — серые строки и «Убрать
  потерянные» (в примерке — рычаг `showGone`).
- **Следование** — свои операции (перенос, переименование, отмена, корзина
  и возврат) пин переносят; переименование снаружи при открытой папке —
  сторож; при закрытой — [пин теряется, принято]. [Копия пин не
  наследует.]
- **Пин не выделение** — операции идут только с выделением; мост —
  «выделить пины».
- **`Ctrl+Z`** — [пин не откатывается: не операция с файлами]. «Снять все
  пины» — подтверждение с Cancel по умолчанию.
- **Список не дёргается** — пин — правка внутри строки, подмена без
  пересборки, как у оценки; при фильтре «только пины» снятый пин — строка
  выпадает [верно]. Сортировки по пину нет.
- **Клавиша** — [выбор в настройках из списка]: `\`, `` ` `` (в русской
  раскладке — «ё», привязка по физической клавише), `Ins`; умолчание —
  **[решить]** (предложение — `\`: запрещена в именах, не пересекается с
  type-ahead). Во всех видах, в сплите, на полном экране. [Автоперехода
  нет.]
- **Плашка «Пины»** — [третья панель слева, рядом с «Компьютером» и
  «Закладками», с крестиком; не закладка]. Внутри — папки с пинами
  деревом: узел рисуется, если в папке есть пины или под ней расходятся
  две и больше ветки с пинами (предок только группирует, не нажимается);
  пустые промежуточные — нет. [Дерево — на пробу, годность человек решает
  по живому.] Щелчок по папке — её пины в списке (адрес «Пины › папка»),
  по заголовку — все, группами по папкам. [Областей над списком нет;
  набора из нескольких папок нет.] Список — тот же, что у папки: виды,
  панель просмотра, меню, операции.
- **Действия** — «⋯» заголовка: «Снять все пины…»; «⋯» папки: «Открыть
  папку», «Снять пины папки»; меню файла в списке пинов: «Перейти к
  расположению» (`MenuCommandId.GoToLocation`), «Снять пин» / «Снять пины
  (N)». [Места — подобрать, примерка — первое приближение.]
- **Открыто** — **[решить]**: вид значка (заметно отличается от оверлея
  git и цветных меток; возможно, подсветка фона — отдельная примерка);
  фильтр «только пины» — кнопка в полосе `RatingFilter`, появляется с
  первым пином в папке, или блок в меню; слово в интерфейсе («Закрепить»
  занято оболочкой, булавка читается как «наверху списка»); спутники и
  пара RAW+JPEG; одинокая папка в плашке — только лист имени, путь в
  подсказке.
- **Не делаем** — «брак» (`X` Lightroom); пин в XMP или NTFS-потоке.
  Соседи: BACKLOG «Метки (теги)» — ключевые слова, другое; «Обсуждения» —
  «Окно панелей» (чем вернуть закрытую плашку), «Хранилище подвижных
  данных».

**Спека** (2026-11-17). Цель — пин ставится клавишей, виден в строке,
переживает свои операции и собирается в плашке «Пины». Порядок: сначала
невидимый фундамент Core (книга, ключ тома, следование) — на нём стоят
все виды, и он не ждёт открытых решений; затем строка и клавиша; затем
плашка и список. Шаги 1–3 расписаны, 4–8 — контуром: дописываются перед
своей пачкой, после решений из «Открыто».

1. **Книга пинов и хранилище.** `Core/Pins`: `PinBook` — в памяти, папка →
   записи (имя, дата пина UTC, признак «в корзине»), сравнение путей без
   регистра; пин папки — запись в её родителе. Операции: спросить, поставить,
   снять, имена папки, список папок с пинами, снять все, событие об
   изменении. `IPinStore` (`Load`, `Save`, `IsReadOnly`) — в
   `Core/Persistence`, образец `IFolderSettingsStore`; `JsonPinStore` — в
   `Platform.Windows/Persistence`, образец `JsonFolderSettingsStore`
   (временный файл и `File.Move`, версия формата, `InstanceLock` — вторая
   копия только читает); файл — `AppPaths.PinsFile`, `pins.json`;
   регистрация — `PlatformBootstrapper.RegisterDefaults`. Запись — тем же
   таймером, что `state.json`, по своему флагу (образец — `_foldersDirty`
   в `MainViewModel`). [Своя база, JSON, целиком в памяти.] Не в этом
   шаге: значок, клавиша, любое UI. Стор ведёт себя как образец: битый
   файл — пустая книга, файл новее по версии — читается, но не пишется;
   тестов у стора нет (тесты только Core). `SaveState()` заодно
   переписывает `state.json` — принято, `pins.json` пишется только по
   своему флагу. Тесты — `PinBookTests` (книга и её снимок для стора, стор
   — подделкой), путь файла — в `AppPathsTests`. Глазами — нечего;
   `check.bat run` (старт). Харнесс: `state-upgrade`. Готово: книга
   проходит круг «поставить → снимок → новая книга из снимка» в тесте,
   старт зелёный, в логе — строка о загрузке с числом пинов.
2. **Ключ съёмного носителя.** `VolumeInfo` получает серийник тома:
   поле в записи (её создают `WindowsVolumeInfo`, `DeviceFolders`,
   `VolumeInfoTests`), значение — `GetVolumeInformation`, PInvoke только в
   Platform. Правило — чистые функции в `Core/Pins`: путь + снимок томов
   (корень → серийник, съёмный ли) → ключ хранения и обратно; у
   `VolumeKind.Removable` ключ — по серийнику, не по букве, у остальных —
   путь как есть (внешний USB-диск приходит как `Fixed` — пока по букве,
   **[решить]**; том, смонтированный в папку, — по корню хозяина). Снимок
   держит книга: наружу она говорит путями и сама переводит их в ключи.
   Строит снимок `MainViewModel` вне UI-потока на старте из того же списка
   дисков, что «Компьютер», и обновляет по `IVolumeChanges`; листинг
   `IVolumeInfoProvider.Describe` не зовёт — берёт снимок. Ключ без
   подключённого тома обратно не разворачивается — такие записи книга не
   отдаёт и не чистит [диск отключён — пин спрятан и хранится]. Тесты: та же флешка под другой
   буквой находит свои пины; другая флешка под той же буквой — нет;
   отключённая — спрятана, после возврата — на месте. Глазами — нечего.
   Харнесс: `devices`. Готово: тесты зелёные, в `pins.json` у съёмного —
   серийник.
3. **Следование и пропавшее.** Новый держатель `PathHolder.Pins` в
   `PathFollowing`, ветка в `MainViewModel.FollowRelocated` —
   `PinBook.Follow(откуда, куда)`: переезжает и сама запись, и все записи
   под папкой; ключ каждой считается заново из нового пути (между томами
   вид ключа меняется — правка префикса не годится). `Follow` без записей
   под «откуда» — пусто, повтор безвреден (сторож вернёт и свои
   переименования). Дыры: одиночное переименование **файла**
   (`MainViewModel`, рядом с вызовом для папок) и пакетное переименование
   (файлы и папки) `FollowRelocated` не зовут — там звать прямо
   `PinBook.Follow`, остальных держателей не трогать; что пакетное не
   ведёт за папкой прочих держателей — строкой в TECHDEBT, не чинить.
   Переименование снаружи при открытой папке — пары
   `WatchTickDecision.Renames` (там же, где `_landingRenames`). Смена
   только регистра имени запись не правит — книга сравнивает без регистра.
   Спутники за пином не идут — пин на основном элементе (спутники —
   «Открыто»). Удаление — `MainViewModel.RunDeleteAsync`, по
   `results` со статусом Ok: в корзину — запись (у папки — и все под ней)
   получает признак «в корзине», не показывается и не чистится; файл
   снова на месте (отмена, возврат из корзины) — признак снимается при
   листинге; безвозвратно (`permanent`, `DeleteResult.Permanent`,
   повторный безвозвратный проход) — записи удаляются. Запись «в
   корзине» после очистки корзины остаётся до «Снять все пины» — строкой
   в TECHDEBT. [Копия пин не наследует; `Ctrl+Z` сам пин не откатывает.]
   Чистка — чистая функция книги: папка + все имена листинга → снятые
   пины. Имена собираются в цикле перечисления `RefreshFolderAsync` до
   отсева скрытых и схлопывания спутников; чистит только перечисление,
   дошедшее до конца без исключения и отмены, и только обычной папки на
   диске (не архив, не устройство, не результаты поиска, не места
   оболочки). Выключатель —
   поле `AppSettings` (по умолчанию чистить), контрол в настройках — шаг 8.
   Не в этом шаге: проверка существования для плашки (шаг 6), серые строки.
   Тесты — в `PinBookTests`, `PathFollowingTests`: перенос, переименование
   файла и папки с пинами внутри, отмена каждого, корзина и возврат, чистка
   и её отказ на неполном листинге. Харнесс: `file-ops`, `watcher`.
   Готово: тесты зелёные; в логе — строка на перенос пина и на чистку.
