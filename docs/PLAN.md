## Блок 0. Долги 0.4.x

Найдено ревью патча 0.4.1 (2026-09-21); трогает ежедневное — не в патч.

- **Сторож с выделением прокручивает список к выделенному.** `Refresh`
  ставит приземление «оставить выделенное», `RestoreListSelection` делает
  `ScrollIntoView`: список прокручен колесом в сторону, снаружи появился
  файл — список едет обратно. Тихий путь (`SelectionRefreshRequested`) до
  перечитываний сторожа не доходит. Приземление без прокрутки для тика
  сторожа; риск — возврат клавиатуры после замены строки с фокусом держится
  на `RestoreListSelection`.
- **«Нет в листинге» ≠ «ушёл из папки»** [решить]. Выделение переходит на
  соседа и когда файл переименовали снаружи (сторож `OldFullPath` не
  отдаёт), выключили «скрытые» при выделенном скрытом, свернули спутники при
  выделенном сайдкаре — до 0.4.1 выделение снималось. Вариант: путь ещё на
  диске — снять выделение, а не брать соседа (один `stat` на UI-потоке).
  Цель панели (`SelectedEntry` пуст) из правила исключена 2026-09-22:
  `ReconcileEntries` её не ищет в строках и ушедшей не считает.
- **`Ctrl+Z` не ждёт занятых.** Шаг отката идёт мимо `BusyGate`: миниатюры
  только что вставленных снимков, поиск, панель держат файл — шаг падает и
  выбывает из стека навсегда. Каждый шаг — через `Check` / `Retry`; заодно
  `ReleasePreview` перед откатом (TECHDEBT).
- **Корзина на границах — стенд на машине без человека** (T). (а) Путь
  внутри `X:\$Recycle.Bin\<SID>\$R…` на 60–70 знаков длиннее исходного:
  если оболочка меряет там, папки с путями 200–259 внутри получат системный
  вопрос «удалить безвозвратно?» с «Да» по умолчанию. (б) Папка больше
  лимита корзины — тот же риск. (в) Страховка сразу: оболочка ответила
  успехом, а элемента корзины не назвала (`ShellRecycleBin`, сейчас `WARN` и
  нерабочий откат) — считать безвозвратным удалением и так и сказать.

Вопросы, отложенные 2026-09-18 [решить]:

- **Win32-имена в Rider** — 118 «Name does not match rule» на константах
  P/Invoke: пары `// ReSharper disable / restore InconsistentNaming` в десяти
  файлах либо не трогать.
- **Анализаторы**: `TreatWarningsAsErrors`; точечно warning в
  `.editorconfig` — `CA1310`, `CA1309`, `CA2101`, `CA1001` (остальное из
  `latest-recommended` — шум: `CA1707` 1196, `CA1305` 173, `CA1861` 161,
  `CA1863` 121); `VSTHRD100` / `110` при выключенных `001` / `200` / `003`.
- **Слова из XMP при конвертации**: `ImageConvertAction` берёт название,
  слова, комментарий, автора из свойств декодера WIC (`ExifTags.
  TextPolicies`), тот отдаёт их не для каждого контейнера. Откуда брать —
  вшитый XMP / IPTC (MetadataExtractor, `XmpDirectory`) или сайдкар `.xmp`
  (у RAW слова обычно в нём); для проверки нужен RAW / DNG со вшитыми
  словами в фикстурах.
- **«Документы», «Загрузки» и соседи в `SystemPathGuard`**: Проводник
  удалять не даёт, у нас тест `UserProfileRoot_IsProtected_
  ButDocumentsAreNot` закрепляет обратное; с панели закладок уже не
  удаляются, из списка и меню папки — да.
- **Рабочий набор под харнессом +10–15 %** (TECHDEBT) — искать причину, если
  живой прогон подтвердит.
- **`.rar` / `.tar.gz` при установленном WinRAR** папкой не открываются
  (правило «как Проводник»): привязка системного обработчика по CLSID мимо
  ассоциации — стенд, если захочется.

## Блок 1. Сборка и отладка

### AH. Номер сборки четвёртым числом — [P2, решить детали]

Цель (2026-09-21): каждая сборка в Rider увеличивает четвёртое число версии,
оно однозначно называет билд; релиз остаётся с тремя.

Сейчас: версия — `Directory.Build.props` (`Version`, `InformationalVersion
0.4.0-beta`, `FileVersion`; `AssemblyVersion 0.0.0.0` закреплён нарочно),
читает один `BuildInfo` (Core) — строка `v0.4.0 D, 96e5e, 31.08.26`: буква
Debug / Release по `DebuggableAttribute`, пять знаков коммита (неявный
SourceLink), дата сборки; видна в меню, шапке лога, крэш-бандле. Счётчика
нет; коммит не различает сборки между коммитами.

Получится: цель MSBuild перед компиляцией `Wander.App` увеличивает счётчик в
файле и кладёт его в `FileVersion` / `InformationalVersion` (`0.5.0.137`),
`BuildInfo.Line` показывает. Решить:

- где счётчик: файл вне гита (свой на машину, переживает ли очистку
  `artifacts\`) или в гите (шум в каждом коммите); сбрасывает ли его
  `version.ps1`;
- кто считает: только Rider (свойство MSBuild от него — проверить) или любая
  Debug-сборка, включая `check.bat` и харнесс;
- установленная копия (`publish.ps1 -Install` — Release, но не релиз): с
  номером или нет; без номера тогда только сборка по тегу в CI;
- цена: номер внутри exe — `Wander.App` компилируется каждый раз (секунды),
  в том числе когда менялся только Core (иначе номер не вырастет); номер
  файлом рядом с exe — инкрементальность цела, но exe сам себя не называет.

Ловушки: `LastRunVersion` сравнивается с `InformationalVersion` строкой
(`DropThumbnailCacheOnUpgrade`) — с номером кэш миниатюр сносился бы каждым
билдом, сравнивать по трём числам; `version.ps1` бросает, если тег версии
встречается дважды; поле `FileVersion` ≤ 65535.

### AI. Отладочные операции и занятость — [P2]

Меню отладки (`Settings.ShowDebugMenu`, сейчас в нём только «Журнал») — два
инструмента, чтобы смотреть интерфейс операций, не гоняя данные по диску.

  окна. Около сотни строк в App. Решить: сценарии (ровный / ошибка на N-м /

- **AI2. Отладочная занятость** — переключатели на выделенном: (а) «занят

## Блок 2. Надёжное копирование

### K. Быстрое и надёжное копирование — [P1, иссл.]

Сценарий человека (2026-09-21): копирование с фотоаппарата идёт минутами —
должно быть максимально надёжным, прозрачным, ошибкоустойчивым, с
возможностью повторить или продолжить прерванное. Решение 2026-09-18: сюда
же проверка крупного копирования (живой прогон 0.4.0 его не гонял) и итог
операции в логе (AD5, п. 3).

Сейчас: `SystemIOFileSystem.CopyFile` — `CopyFileExW` без флагов (прогресс и
отмена внутри файла; недописанное при отмене убирает Windows), папка —
рекурсия мимо reparse points, перенос между томами — копия + удаление. Нет:
проверки после копии, временного имени, повтора при сбое, продолжения,
докачки, защиты от сна. Устройств без буквы диска (MTP / PTP — так
подключается большинство камер и телефонов) Wander **не видит вообще**:
корни — `DriveInfo.GetDrives()`, `IShellNamespace` знает только корзину и
архивы; виртуальные файлы из буфера распознаются, чтобы отказать.

Исследование — что выяснить и решить:

- **Как подключён фотоаппарат** [вопрос человеку]: картридер или Mass
  Storage — обычный съёмный том, работает сегодня; MTP / PTP — нужна третья
  ветка shell-namespace («Этот компьютер» → устройство) с копированием через
  `IFileOperation`, как у архивов (`ShellArchiveFolder.CopyOut`), либо WPD
  API. У MTP: одна передача за раз, без произвольного доступа и докачки,
  медленное перечисление, сессия рвётся при засыпании камеры, даты — из
  свойств объекта.
- **Съёмный том против внутреннего**: источник может исчезнуть посреди
  файла (`ERROR_DEVICE_NOT_CONNECTED`, `NOT_READY`, `GEN_FAILURE`), ошибки
  чтения (`ERROR_CRC`, `IO_DEVICE`), FAT / exFAT (шаг времени 2 с, 4 ГБ на
  FAT32, нет ACL и потоков), запись **на** съёмный — кэш и «безопасное
  извлечение» (`FlushFileBuffers` перед «готово»), поддельные флешки.
- **Что даёт «быстрое»**: небуферизованный ввод-вывод
  (`COPY_FILE_NO_BUFFERING`) ускоряет крупные файлы между быстрыми дисками;
  параллельность помогает мелочи на SSD и вредит HDD, флешкам и MTP. С карты
  и с камеры скорость упирается в источник — там выигрыш в надёжности, не в
  скорости. Кандидаты: свой цикл с буферами, robocopy (`/Z`, `/R /W`, `/MT`,
  коды 0–7 успех, 8+ сбой; прогресс — разбор stdout), FastCopy как референс.
- **Карта сбоев и ответов**: источник пропал → операция встаёт на паузу,
  ждёт устройство (Y2), продолжает с упавшего файла; ошибка чтения → N
  повторов, затем пропуск и запись в итог; место кончилось → проверка до
  старта (взвешивание уже есть) и пауза посреди; сон компьютера →
  `SetThreadExecutionState` на время операции; вылет или питание → временное
  имя (`.wander-tmp` → переименование), журнал операции на диске и
  «продолжить» при следующем старте; тихая порча → проверка после копии: хэш
  источника на лету + перечитывание цели (второе чтение медленного источника
  не нужно), по флагу или порогу; перенос = удалять источник только после
  проверки и сброса буферов.
- **Развилка движка**: `CopyFileEx` (системный, переносит атрибуты и
  потоки, байтов не показывает — ни хэша, ни докачки) против своего цикла
  (хэш, докачка по смещению, повтор блока; атрибуты, даты, потоки — руками).
  Слои: движок в `Wander.Platform.Windows` за абстракцией, в Core ни слова
  про robocopy; undo-запись для любого пути; когда включать (всегда / порог /
  том съёмный).

Хвосты сюда же: TECHDEBT «Файловые операции» (cross-volume без уборки,
безвозвратное не ждёт занятый, папка с занятым внутри); BACKLOG (FAT32 4 ГБ,
UNC-таймауты, reparse points, длинный путь); AF ниже.

### K2. Операции остаются в строке состояния — [P1, решить форму]

Идея человека: завершённые операции остаются «свёрнутыми» в строке
состояния; «подчистить завершённые»; проблемная требует решения — развернуть
и «повторить» либо «прервать». Сейчас `Dispose` ручки убирает операцию из

(`ReportBatchResults`); повтор есть только у удаления (`AskRetryInUse`).

Нужно: операция как запись с итогом по элементам (готово / пропущено / сбой
с причиной / отменено) — она же кормит журнал (AD5), повтор упавших и
продолжение после вылета (K). Решить: сколько живут завершённые (сеанс?),
что значит «повторить» (только упавшие; план пересчитывается — источник мог
измениться), «прервать» (оставить сделанное, undo как есть), вид свёрнутой
строки (значок важности уже есть), что при выходе с проблемной операцией.
Проверять — AI1.

### AK. Изображение открывается мгновенно — [P1, иссл.]

Цель проекта (2026-09-21, столп 4 в CLAUDE.md): стремиться к FastStone —
никаких мельканий, смена снимка выглядит мгновенной.

Исследовать: что видит глаз между двумя снимками сейчас (заглушка, пустая
панель, смена «быстрая версия → полная», прыжок футера) и сколько
миллисекунд до первого пикселя по форматам (JPEG 24 Мп, CR3, PNG) — замер
`PerfLog` от смены выделения до кадра, на релизной сборке. Что делает
FastStone: держит соседей декодированными (упреждающее чтение вперёд и
назад), декодирует под размер экрана, не гасит прежний кадр до готовности
следующего, берёт вшитые превью у RAW.

Кандидаты мер:

- **Упреждающее чтение соседей** — следующий и предыдущий по списку
  декодируются в фоне, потолок памяти, отмена при смене направления.
- **JPEG: сначала под размер панели, полный — следом** [после проверки
  глазами]. У RAW два шага есть (быстрый `PRVW`, большой после 150 мс); у
  JPEG `DecodePixelWidth` — масштаб в DCT (1/2, 1/4, 1/8), в разы быстрее и
  без сотни мегабайт на кадр. Полный — тем же `LoadFullSizeAsync`, только
  для зума, в `ZoomSource` (смена вписанной картинки была видна глазом);
  `MaxWidth` у `ImgFit` считать от полной. Уходит `HighQuality` по 24 Мп в
  потоке рендера. Уже сейчас у CR3 вписанный кадр — `PRVW`, панель шире 1620
  DIP он не заполняет.
- **Прежний кадр держится до готовности нового** — без пустой панели и
  заглушки между снимками.
- **Debounce смены выделения** (TECHDEBT): Task на каждое изменение, 200–300
  мс при быстрой прокрутке — против цели напрямую.
- **Подвисания галереи** (BACKLOG «Производительность»): GC / LOH от потока
  миниатюр; порядок работ описан там.

Идея человека (2026-09-21): при отборе видеть недосветы и пересветы, что
вытянется из теней и светов, куда попал фокус, где резко. Принцип прежний
(BACKLOG): галерея показывает и размечает, но не проявляет — всё только
отображение. Сейчас RAW не декодируется: панель и миниатюры берут вшитый
JPEG (`RawPreviewExtractor`, `RawThumbnail`).

Крупно — три слоя по цене:

1. **По вшитому JPEG, без декодера RAW.** Focus peaking — Лаплас или Собель
   по яркости, порог, оверлей; по сути фрагментный шейдер (`ShaderEffect`).
   Карта резкости — идея человека: резкое светлее, нерезкое темнее. Скор
   резкости — variance of Laplacian; сравним только внутри серии одной
   сцены, считать в ROI вокруг точки AF. Зебра пересветов / недосветов и
   гистограмма по JPEG — приближение (после баланса белого и кривой
   камеры). Поднятие теней / приглушение светов кривой поверх JPEG — 8 бит,
   покажет «что там есть», не «что вытянется».
2. **Точка и область фокуса** — из makernotes (Canon `AFInfo`, Sony, Nikon):
   проверить, что отдаёт MetadataExtractor; рамка оверлеем, ROI для скора.
3. **По данным RAW.** Клиппинг — Bayer-данные до баланса белого против white
   level (LibRaw: `color.maximum`) и black level, маска по каналам;
   RAW-гистограмма — те же данные, бины в log2 (EV), по каналам; честные
   тени и света. Нужен декодер: LibRaw (нативная DLL, лицензия LGPL / CDDL,
   вес, чужой код читает файл) либо свой (CR2 — lossless JPEG, посильно; CR3
   — кодек CRX, тяжело). Системный RAW-кодек WIC отдаёт уже проявленное — не
   годится. Главная развилка блока.

Решить: где живут переключатели (панель, галерея, полноэкранный просмотр),
хоткеи, цена на кадр (24 Мп шейдером — мгновенно, на CPU — по уменьшенной
копии), кэш скора резкости (рядом с `thumbs`, как J3).
