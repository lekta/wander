  видит.
- **Заняла внешняя программа** — приоритет её, ничего не прерываем;
  называем программу (Restart Manager уже умеет и папки — до 500 файлов
  внутри, 2026-09-17).
- **Занял Wander, но по команде пользователя** (идущая операция из
  трекера, своё действие с ffmpeg / LibreOffice, файл во второй половине
  сплита с видео) — не прерываем молча, а **явно говорим**, какая наша
  операция держит файл, чтобы пользователь не конфликтовал сам с собой.

Есть сейчас (2026-09-17): `ShellRecycleBin` проверяет файл открытием
на удаление (2 мс; сам `SHFileOperation` отвечает на занятый файл за
секунду), ждёт 0,3 с и сдаётся — файл и папка за ~0,3 с (стенд);
провал удаления из-за занятости — диалог «Файл занят» с именем
программы и «Повторить»; панель просмотра на занятом файле пишет, кто
его держит. Занятое самим Wander называется просто «Wander (PID …)».

Решения 2026-09-21 (исполнение — блок 0): свои читатели открывают файл с
`FileShare.Delete`, для остального — заявки `PathClaims` с отменой по
пути; ожидание — взгляд каждые 0,2 с до 2 с, в журнале остаётся «был
занят (кем) — отпущен»; воспроизведение в панели прерывается молча,
операция пользователя называется; проверка выносится из `ShellRecycleBin`
в Core; над файлом в работе — значок в списке и строка в панели.
Разведка (2026-09-21, по коду): управляемых чтений без `FileShare.Delete`
— 15 мест; не берут флаги — WPF-декодеры (держат только на время
декода), WebView2 и `MediaElement` (держат, пока показано; отдельного
«отпустить перед удалением» нет вовсе — только смена выделения),
shell-миниатюры и `IFilter` (без токена отмены), дочерние процессы своих
действий; очередь значков (`IconLoadGate`) по пути не адресуется;
`OperationTracker` знает только текущий путь операции, не список.

**Позже, вне блока 0 — большая папка** (решение 2026-09-21: записать,
ситуация из тех, что стоит решить). Перенос или переименование крупной
папки упирается в «что-то внутри занято», Restart Manager смотрит первые
500 файлов, дальше — без имени. Требование: пользователь видит
**конкретный файл и программу**. Заход: на отказе пройти папку
`IFileBusyProbe` (2 мс на файл) до первого занятого и спросить Restart
Manager про него одного.

Проверка (нужна программа, которая держит файл намертво; Блокнот
отпускает): PowerShell, `[IO.File]::Open(путь, 'Open', 'Read', 'None')`
в отдельном окне до `Enter` — Restart Manager называет её
«Windows PowerShell (PID …)». Для «своих» — длинная миниатюра / видео в
панели / своё действие на большом файле и удаление в этот момент.
