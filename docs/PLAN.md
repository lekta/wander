### K. Надёжное копирование больших файлов — [P2/P3, исследование]

Внешний движок для тяжёлых случаев (десятки ГБ, нестабильная сеть,
съёмные). Кандидаты: **robocopy** (встроен; retry `/R /W`, restartable
`/Z`, `/MT`, длинные пути, внятные коды), **FastCopy** — референс по своим
буферам и обходу системного кэша, не зависимость (лицензию проверить),
**certutil -hashfile** — verify-after-copy по флагу (для больших файлов
дорого).

Решить — это и есть работа, а не выбор утилиты: слои (процесс в
`Wander.Platform.Windows` за абстракцией, в Core ни слова про robocopy);
прогресс (`OperationTracker` ждёт per-item, robocopy пишет в stdout —
парсить или неопределённый); отмена = убить процесс, судьба хвоста (`/Z`
продолжает); undo-запись и для внешнего пути (без undo не выпускается);
когда включать (всегда / порог размера / флаг); коды robocopy 0–7 успех,
8+ сбой — замапить в человеческие сообщения.

### P. Архивы как папки — [P2, спринт 8]

Минимум: вход по `Enter` / двойному клику, выход назад, адрес
`…\pack.zip\subdir`; имя, размер, дата, папки папками; извлечение
перетаскиванием / `Ctrl+C` → `Ctrl+V` / «Извлечь…»; «открыть» — во
временный файл и запуск ассоциацией; всё остальное внутри (удаление,
переименование, вставка, создание) погашено, как в корзине. Сюда же
«zip в панели просмотра» из активных направлений — одна механика.

**Прецедент — корзина**: shell-namespace, обвязка есть — `IShellNamespace`
(`IsShellPath` / `Enumerate` / `GetDisplayName`), `WindowsShellNamespace`
(`IShellItem`), shell-ветка листинга, `PathIsNavigable` /
`IsCurrentShellNamespace`, `IShellContextMenu` по пути. `.zip` в Windows —
namespace-extension (`zipfldr.dll`), тот же `IShellFolder`. Основной
кандидат — обобщить существующее: снять с `IShellNamespace` допущение
«путь начинается с `shell:`», научить «реальный путь до файла + хвост
внутри». После O11 архивное перечисление — третья ветка `FolderSession` с
той же эпохой и правилами прибытия.

**Первый шаг — разобрать Проводник** (Win11 26200), записать результат:
видит ли `IShellFolder` `.rar` / `.7z` / `.tar` / `.gz` (libarchive с 23H2)
как namespace или только «Извлечь всё» в меню — главная развилка (видит —
приезжают бесплатно с zip; нет — свой читатель, вторая очередь);
извлечение перетаскиванием Проводник отдаёт `CFSTR_FILEDESCRIPTOR` /
`CFSTR_FILECONTENTS` — формат уже распознаётся и честно отвергается;
научиться принимать = извлечение + вложения писем + снимки с телефона —
**самый выгодный шаг секции**; «Извлечь всё…» — shell-глагол через
`IShellLauncher`, строчка; записи внутрь и обратной записи изменённого
временного файла Проводник не делает (теряет молча).

| | Shell (namespace-extension) | Свой читатель |
|---|---|---|
| Зависимости | нет | `System.IO.Compression` для zip; rar / 7z — сторонняя |
| Форматы | zip всегда; rar / 7z по результату проверки | что подключим |
| Реюз | всё уже написано | всё своё |
| Тесты | никакие (COM, живая система) | полные, в Core, на готовых архивах |
| Столп «интеграция» | точно | уступка, обосновывать |
| Риски | RCW и STA (по корзине наступали), скорость на больших архивах, пути-сентинелы | zip-бомбы, `../` в именах; solid rar / 7z — квадратичный random access |

Порядок: сначала shell; абстракцию в Core сразу такой, чтобы второй путь
встал рядом, а не вместо (по критерию интерфейса из чистки #4: вторая
реализация запланирована).

**Решить до кода:** что такое «путь внутри архива» (`Directory.Exists`
false, `Path.GetDirectoryName` работает, `IFileSystem` ломается) — разбор в
Core: первый сегмент-файл с архивным расширением, дальше хвост; один
предикат в одном месте, иначе расползётся по тридцати местам, как чуть не
расползлась корзина; дерево — разворачивать ли архив (дерево грузит уровень
синхронно, TECHDEBT; большой архив дорог); сторож — отключать или вешать на
файл архива; панель просмотра и миниатюры — байты = распаковка во
временный, решить, показываем ли миниатюры внутри вообще («значок по
расширению» честен и стоит ноль); временные файлы — где
(`%LOCALAPPDATA%\Wander\tmp`), когда убирать, и **что делать с
отредактированным** ((а) повторить Проводник, но сказать заранее —
умолчание со строкой в статус-баре; (б) заметить и предложить записать —
это уже запись в архив, отдельная фича); извлечение = файловая операция
(guard, лог, undo = удалить извлечённое, прогресс с отменой); пароль —
минимум «нужен пароль», не пустая папка; поиск, спутники, оценки внутри —
выключены решением, не «случайно не работает»; битый архив — сообщение.

Дальше, не в этот заход: запись в архив; создание из выделения (сейчас
7-Zip в чужом меню — возможно, достаточно; BACKLOG «поднимать пункты
расширения»); архив в архиве; содержимое в панели просмотра без входа.

### Q. Умный режим разрешения конфликтов — [P1, спринт 8]

Сейчас в `Wander.App/Conflict/`: `BatchConflictDialog` — один вопрос
вслепую в начале батча («Заменить все / Пропустить все / По одному /
Отмена»); `ConflictDialog` — имя, размер, дата у обоих, четыре кнопки,
`StackPanel` 48 строк, ширина 520 `NoResize`, цвета в разметке, свой
форматтер размера, даты без пометки «новее». `BatchExecutor` спрашивает
через pull-интерфейс `IConflictResolver`: `StartBatch(int)` и
`Resolve(FileConflictInfo)` по мере обнаружения; `DispatcherConflictResolver`
тянет на UI-поток.

- **Q1. Сравнение.** К `FileConflictInfo` (две `FileSystemEntry`) — расчёт
  различий: размер (всегда; совпадение тоже вслух); дата как вердикт
  («источник новее на 3 дня»); контрольная сумма — сама, если оба меньше
  порога (кандидат 64 МБ), иначе по кнопке; в фоне, с отменой, окно живёт
  без неё; превью для картинок — обе миниатюры через `IIconProvider.GetIcon`
  большого размера (кэш и RAW уже есть); «идентичны» — отдельное состояние
  окна.
- **Q2. Окно.** Переписать: две равные колонки, превью сверху, различия
  таблицей, кнопки внизу; resizable, геометрия запоминается, Cancel по
  умолчанию, клавиатура; цвета из палитры; подписи в `Strings.resx`. Не
  трогает Core — можно первым.
- **Q3. «Применить ко всем»** — галка в самом окне, уже посмотрев на файл;
  дальше вердикт-зависимые («пропускать идентичные», «заменять, если
  новее»). `BatchConflictDialog` исчезает, а не остаётся вторым способом.
- **Q4. Пропуск идентичных** — настройка. Ловушка: для копирования no-op,
  для **перемещения** «пропустить» обязано означать «удалить источник»,
  иначе перемещение тихо становится копированием.

Решить до кода: чем считать сумму (BCL `SHA256` — умолчание, диск всё равно
узкое место; `System.IO.Hashing` `Crc32` / `XxHash3` — зависимость; в
окне «контрольная сумма», не имя алгоритма); где — в Core через
`File.OpenRead`, как `Preview/` (правило «когда `IFileSystem`, когда
`System.IO`» — ARCHITECTURE); контракт — оставить pull (умолчание; «весь
список сразу» лучше для батча, но ломает «конфликт возник в процессе» и
переписывает `BatchExecutor`); папка против папки — `Replace` делает
delete + copy и теряет непересекающееся (TECHDEBT), Проводник делает merge;
минимум назвать вслух, merge — отдельно; «Оставить оба» подставляет `(1)`
без диалога (TECHDEBT) — чинить здесь или оставить; медленный источник —
всё отменяемое, окно живое; спутники — конфликт по группе, показать
«вместе поедут .meta, .pp3».

Минимум на спринт: Q1 + Q2; Q3 и Q4 меняют батч и требуют решения по
контракту.

вызова должна стать короче, а не переехать. Исполнитель: Фабле — где риск
тихой смены поведения или проектное решение; Опус — механика по спеке,
промахи ловят компилятор и тесты; шаг Опуса не закрыт без ревью Фабле.
