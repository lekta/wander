# Wander — подготовка к релизу

Между финализацией и [RELEASING.md](RELEASING.md). Запускается отдельно и
явно, словами «готовимся к релизу X.Y.Z»: это решение человека
«выпускаем», после которого начинается дорогая часть. Из финализации не
следует. Ведёт Фабле; батчи автотестов и отчёты по ним — Опус; живой
прогон, решение по каждому блокеру и зелёный свет — человек (роли —
[WORKFLOW.md](WORKFLOW.md)). Итог — зелёный свет либо список блокеров.

Ниже — ветка **релиза версии** (`X.Y.0`). **Патч-релиз** (`X.Y.Z`, Z > 0)
идёт укороченной — «Ветка патча» в конце; слова — WORKFLOW.md, «Версия».

**Стабилизация.** С этих слов и до выпуска доработки, которые могут
что-то сломать, не берутся — откладываются на после релиза, чтобы до
следующего успели обкататься. До релиза чинятся баги взаимодействия и
держится стабильность базовых действий; проверок на живом приложении
больше, чем обычно (WORKFLOW.md, «Версия»).

Порядок такой потому, что дешёвое отсеивает раньше дорогого: незакрытый
блокер в PLAN обесценивает тридцатиминутный соак, запущенный до его чтения.

1. **Хвосты.** PLAN — что осталось незакрытым и уедет ли в следующую
   версию; CHANGELOG `Unreleased` — описывает ли он то, что реально
   сделано; README — не врёт ли про «в планах»; GUIDE.md — описывает ли
   релиз, а не дерево: снимок на теге станет руководством версии
   (RELEASING.md, «Руководство релиза»).
2. **Разбор техдолга.** TECHDEBT читается целиком и раскладывается на три
   кучки. **Критичное** выносится в PLAN без обсуждения — задачей до
   релиза. **Несколько самых серьёзных** (три-семь) идут человеку списком
   на обсуждение, с рекомендацией «чинить / переносить» по каждому.
   Остальное остаётся в TECHDEBT, о нём не докладывают. Рабочее
   определение: критично — теряет или портит данные, роняет или вешает
   приложение, ломает базовое действие (открыть, удалить, скопировать)
   хотя бы в одном виде, врёт пользователю (показано одно — сделано
   другое) или нарушает правило, которое сама подготовка проверяет
   (циклы `deps.ps1`, ключи ресурсов). Серьёзно — заметный дефект на
   поверхности, которую релиз показывает впервые или трогал сильнее всего,
   и всё, что растёт со временем: логи, кэши, утечки. Первый разбор —
   2026-09-03 для 0.3.1 (итоги — TECHDEBT «Закрыто», DONE).
3. **Критичные баги — списком.** Что чинится до релиза, что переносится.
   Решение по каждому — человека; задача Claude — не дать им уехать молча.
4. **Статический анализ и полный набор автотестов.** Сначала дешёвое —
   lint Rider по всему `src` («Lint Rider» ниже), затем набор:
   `check.bat`, `check.bat qa`, все сценарии
   харнесса, `soak` с `"minutes": 30`. Раскладка — [QA.md](QA.md).
   «Готовимся к релизу» и есть просьба прогнать набор — отдельного
   «прогони» не ждут (WORKFLOW.md, «Автотесты»). Каждый батч оставляет
   строку в `artifacts\test-runs.tsv` — когда, сколько из скольких,
   секунды; находки — списком в отчёт.
5. **Живой прогон релизной сборки.** `tools\publish.ps1 -Run`, минут
   десять по своим папкам с галереей и просмотром: харнесс не видит
   настоящий ввод, обмен с Проводником и глаз.
6. **Замеры версии.** `tools\release-metrics.ps1 -Version X.Y.Z` собирает
   вес, старт, логи живого прогона и цифры харнесса в
   `docs/measurements/X.Y.Z.md`; раздел «Verdict» дописывается руками —
   [docs/measurements/README.md](measurements/README.md).
7. **Ручной чек-лист.** Разделы QA.md по тому, чего харнесс не покрывает:
   обмен с системой, DnD, чужие пункты меню, внешний вид.
8. **Вердикт.** Зелёный свет либо список блокеров. Регрессия в замерах
   останавливает релиз — так же, как красный тест. Находки шагов 4–7 —
   по таблице «Разбор находок» (WORKFLOW.md).

**Lint Rider** (с 2026-09-17). Problems View через MCP пуст — инспекции
снимаются `lint_files` батчами по ~50 файлов (`find src -name "*.cs"` без
`obj` / `bin`); ответы больше 50 КБ уезжают в файл, сводить скриптом.
Уровень `WARNING` просматривается весь, поимённо; weak — по счётчикам
против прошлого раза (база 2026-09-17: 1848 сообщений на 303 файла,
`WARNING` ~330 до правок). Применяется то, что не меняет поведение и
проходит `check.bat`; спорное — вопросом человеку; шум (Win32-имена,
базовый тип у `partial`, COM-приведения) не трогается. Оставленное
сознательно помечается в коде `SuppressMessage` с причиной, а не
молчанием. `dotnet format` проверяет naming-правила `.editorconfig`
(IDE1006): новое правило сначала считается по коду. Анализаторы .NET —
пробной сборкой `dotnet build --no-incremental
-p:AnalysisLevel=latest-recommended`; смотреть предметные коды (`CA1310`,
`CA1001`, `CA1806`, `CA2101`, `CA2000`), а не общее число.

Только после зелёного света — «релизим», дальше RELEASING.md по шагам.
Пуш тега — публикация, тихо откатить нельзя: это всегда человек, и Claude
доводит до «осталось закоммитить» и останавливается.

## Ветка патча (`X.Y.Z`, Z > 0)

Только баги и хвосты (WORKFLOW.md, «Версия»); блок в составе — уже не
патч. Те же шаги, короче:

| Шаг | В патче |
|---|---|
| 1. Хвосты | CHANGELOG `Unreleased` и GUIDE — по задетому; PLAN и README не перечитываются |
| 2. Техдолг | не разбирается |
| 3. Критичные баги | как всегда — списком, решение человека |
| 4. Анализ и автотесты | lint — файлы, изменённые с прошлого тега (`git diff --name-only vX.Y.(Z-1) -- src`); `check.bat run`, `check.bat qa`, сценарии задетого по матрице QA.md; `soak` — только если тронуты память, кэши, миниатюры, сторож |
| 5. Живой прогон | релизной сборкой по задетому, минут пять |
| 6. Замеры | файл версии снимается как обычно; Verdict — вес и старт против прошлой, две строки |
| 7. Ручной чек-лист | «Всегда» и разделы задетого |
| 8. Вердикт | тот же |

Правка в файловых операциях, undo, `SystemPathGuard` или `state.json` —
полный набор автотестов, как у версии: цена ошибки от номера не зависит.
Стабилизация действует так же.
