# Wander — харнесс и песочница

Автоматика выше тестов Core: стенды без окна, где всё крутится, песочница
данных, оконный харнесс и его сценарии. Когда что запускать — QA.md, «Кто и
когда гоняет»; какой сценарий что задевает — QA.md, матрица «трогал →
проверь».

## Стенды без окна

**Что можно проверить без окна вообще** (уровень 4). WPF рисует в
`RenderTargetBitmap` из консольного приложения — `Measure` / `Arrange` /
`UpdateLayout` руками, PNG на диск: какой глиф `Segoe MDL2 Assets` за
кодом, перебивает ли триггер шаблона значение из `DynamicResource`.
`VirtualizingWrapPanel` вне окна не строит ничего (владелец
`IsVisible: false`, WINDOW, «Вид, которого не видно»), но достижима:
`HwndSource` за экраном (`PositionX/Y = -32000`,
`WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, как `--smoke`), `RootVisual` из
XAML, скопированного из `FileListView.xaml` с литералами вместо биндингов
к вьюмодели, и `RenderTargetBitmap`. Так найдено «имя выделенной ячейки не
разворачивается»: `DesiredSize` контейнера 159 px до `InvalidateMeasure` и
173,84 после — панель не перемерялась. **Упрощённый** стенд эту разницу
скрыл, настоящий XAML показал. Композицию окна `RenderTargetBitmap` не
снимает (рисует по порядку визуального дерева) — её отдаёт
`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` в DIB-секцию, и для окна за
экраном: так проверен `Panel.ZIndex` из `ArrangeOverride` (порядок детей —
`VisualTreeHelper.GetChild`, перекрытие — по цветам пикселей).

Медиа — тоже без окна: `MediaPlayer` (не `MediaElement`) играет файл в
консольном приложении, `Volume = 0` — рядом человек. Так измерено, что
`burn-in-hell-elmo.mp4` не сообщает длительность и оживает только от
`Close()` + `Open()`, а файл с длительностью после конца берёт и
`Position = 0; Play()`, и `Stop(); Play()` — отсюда две дороги
`RestartMedia`. Длинный файл перематывается к концу
(`Position = Duration - 1.5 s`) до `Play()`.

## Где это крутится

Всё локально, на этой машине: сервера с тестами нет, Claude запускает те
же команды, что человек (`dotnet build`, `check.bat`, `Wander.Harness.exe`),
и видит их вывод. Прогон длится столько же, сколько руками; окно харнесса —
настоящее окно этой Windows за краем экрана; всё, что прогон пишет,
ложится на этот диск.

| | Откуда | Куда |
|---|---|---|
| Данные, по которым ходят | генерируются в `%TEMP%\wander-sandbox\<имя>` (фото, RAW, документы, 5000 файлов) | там и живут между прогонами; `--rebuild` пересобирает |
| Чего генератор не умеет | `tests/Fixtures/` в репозитории | копируется в песочницу по расширению |
| Состояние чужой сборки | `tests/Fixtures/state/<версия>.json` | data-dir прогона, до старта приложения |
| Результат прогона | — | `artifacts\<сценарий>-<время>\`: `report.md`, `screenshots\`, `metrics.json`, `data\` с логом и `state.json` этого прогона |
| Журнал батчей | — | `artifacts\test-runs.tsv`: строка на каждый батч, дописывается |

`artifacts\` в `.gitignore` — мусор прогонов, не история; нужное из него
переезжает в доки словами и числами.

**Журнал батчей.** Каждый батч автотестов дописывает строку в
`artifacts\test-runs.tsv`: когда, имя батча, сколько прошло, сколько всего,
секунды, `ok` / `fail` / `crash`. Пишут трое одним форматом:
`tools\run-tests.ps1` (тесты Core из `check.bat`, по итоговой строке
VSTest), `selfcheck` (проверок напечатано / из них не `FAIL`) и каждый
сценарий (`RunJournal`: шагов `ok` из шагов сценария, время от старта
приложения до отчёта). `smoke` строку не пишет: один запуск — не батч.
Файл вне гита, на этой машине; что с ним дальше — WORKFLOW, «Открытые
вопросы».

## Песочница данных

Живые прогоны идут по сгенерированному дереву, не по файлам машины.

**Изоляция.** Всё, что приложение пишет для себя (`state.json`, `logs`,
`thumbs`, `crashes`, `WebView2`), идёт через один корень
`AppPaths.DataRoot`: `--data-dir <путь>`, `--portable` (папка `data` рядом с
exe), переменная `WANDER_DATA_DIR`, иначе `%LOCALAPPDATA%\Wander`. Харнесс
ставит переменную на `artifacts\<run>\data` — настоящий `state.json` и
кэши машины не трогаются (в логе строка `Data root: … (env)`). Единственное
касание системы — корзина: удалённые файлы песочницы попадают в настоящую,
сценарий возвращает их `undo`.

**Папка старта — тоже своя** (`StartFolder`): сеанс без `state.json`
начинается в рабочей папке, а это «Документы» человека, поэтому тестовый
запуск называет папку сам — `check.bat run` ключом `--folder`
(`tests\Fixtures`), харнесс — корнем песочницы прогона
(`StartFolder.Override`), и со `state` из фикстур тоже. Запуск exe руками —
с `--data-dir` под `artifacts\` и с `--folder`.

**Генератор** — `Wander.Harness sandbox <dir> [--profiles …] [--photos N]
[--big N] [--raw N] [--raw-mb N]`; `run` строит песочницу сам в
`%TEMP%\wander-sandbox\<имя>`, если её нет (`--rebuild` пересобирает).
Позже — VHDX (`Mount-DiskImage`: съёмный том, извлечение) и SMB-loopback
(`\\localhost\share`: UNC, таймауты).

| Профиль | Что внутри | Что проверяет |
|---|---|---|
| `photos` | JPEG 1620×1080 с EXIF-ориентацией 1 / 6 / 8 / 3 по кругу; стрелка и подпись нарисованы так, что после поворота смотрят вверх — сбой ориентации виден на скриншоте; `.xmp` у каждого третьего, `.pp3` у каждого пятого; `sub\` с 10 снимками; `notes.txt` | галерея, автовыбор, фильтр, оценки, миниатюры, `ListingDiff` |
| `raw` | синтетические **CR3** (ISO-BMFF: `moov` → Canon `uuid` с `CMT1` / `CMT2` TIFF, top-level preview `uuid` с `PRVW` JPEG, `mdat` шумом до `--raw-mb`) и **DNG** (IFD0 с превью и ориентацией, Exif IFD, sub-IFD с несжатой полосой шума); `selfcheck` сверяет `RawPreviewExtractor` и `MetadataExtractor` | RAW-путь миниатюр и превью, ориентация, размер файла |
| `big` | N файлов по 1 КБ + 50 подпапок | виртуализация, `list.apply`, `ListingDiff`, поиск 5000 |
| `deep` | 70 уровней + junction `l01\l02\loop` → `l01` (`mklink /J`) | предел 64, `FolderStatistics`, `CountAndSum`, обход поиска — **сценария на него нет**, и `Remove` на нём падает (TECHDEBT) |
| `names` | кириллица, эмодзи, RTL, диакритика, точки, ведущие пробелы, имя 200 символов, путь > 260 | type-ahead, rename, guard, крошки |
| `docs` | docx / xlsx / pptx / odt / epub (zip + XML), fb2 с обложкой-`<binary>`, md с таблицей, rtf (кириллица `\'xx` под `ansicpg1251`), pdf в один текстовый объект с ручным xref, html с картинкой по http и `fetch()`, txt в UTF-8 / UTF-16 / 1251 / 866 — в прозе каждого слово `needle42` и больше нигде в песочнице; плюс `.doc` / `.pdf` / `.rtf` / `.docx` / … из `tests/Fixtures/`, что там есть | поиск по содержимому, экстракторы, панель, `EncodingProbe`, изоляция WebView2 |
| `media` | генерируются `tone.wav` (RIFF `LIST`/`INFO`, теги в 1251), один куб тремя файлами `cube.stl` / `.obj` / `.gltf`, `texture.tga` (32 бита, RLE, строки снизу вверх), `shapes.svg`, `cover.jpg` рядом с треками; из `tests/Fixtures/` по расширению — mp3, flac, ogg, opus, m4a, m4b, aac, wma, mp4, webm, gif, webp, heic (чего нет — строка `missing` в сводке, не ошибка) | аудио-карточка, теги, обложка из папки, видео-миниатюра, 3D, TGA, SVG |
| `code` | `Program.cs`, `Window.xaml`, `pipeline.yaml`, `change.diff`, `build.bat` **в 866** с кириллицей, Unity `Settings.asset` (YAML) и `Binary.asset` (блоб) + `.meta` на оба; копии системных `cmd.exe` и `version.dll`, `.msi` из `tests/Fixtures/`, если есть | подсветка, `TextProbe` на одном расширении в две стороны, спутники, карточка программы |
| `attrs` | `+H`, `+S`, `+H+S`, read-only, `themed\` с `desktop.ini` и `+S` на самой папке, `denied.txt` под `icacls /deny *S-1-1-0:(R)` (по SID: на локализованной винде имя другое), `locked.txt` — обычный файл, хэндл берёт шаг `fs lock` | видимость, удаление, «файл занят», иконка папки из `desktop.ini` |
| `links` | `to-file.lnk`, `to-folder.lnk`, `broken.lnk` — через настоящий `ShellShortcutService` | прозрачность ярлыка, миниатюра, «Перейти к оригиналу» |
| `archives` | `nested.zip` (`ZipArchive`) и `nested.tar.gz` (системный `tar.exe`) с одинаковым содержимым — `readme.txt` и `docs\` из двух файлов; `nested.7z`, защищённый паролем `locked.zip`, `nested.rar` (то же содержимое) и `solid.rar` (solid, шесть текстов) копируются из `tests/Fixtures/` по имени (по расширению нельзя: `.zip` там уже занят `texts.zip`); плюс настоящая папка `plain.zip` — контрольный случай; `photos.zip` — шесть JPEG с EXIF-ориентацией без сжатия | архив как папка, пять форматов, извлечение, undo, «пусто или защищено», папка с архивным именем, распаковка для панели одна за раз, миниатюры внутри архива |
| `state` — **не профиль** | `state.json` чужой сборки кладётся в data-dir прогона полем сценария `"state": "0.3.0"` (файл `tests/Fixtures/state/0.3.0.json`) до старта `App`. Файла нет — прогон падает сразу, а не проходит молча. Пути внутри обезличены и ведут в никуда — нормальный случай для сохранённого состояния | чтение чужого состояния, пропавшие папки, настройки из файла |

`.gitignore` игнорирует `*.meta` и `*.lnk` — такие файлы только генерировать.
Очистка — `SandboxBuilder.Remove`: junction удаляется как junction, дальше
снимается read-only (профиль `attrs` пишет такой файл нарочно, а
`Directory.Delete` на нём падает), потом дерево целиком.

**Песочница переживает прогон и делится между сценариями.** Сценарий
убирает за собой сам (`permanent-delete` в конце); упавший на середине — не
убирает, и следующий прогон считает чужие файлы. Отсюда `fs delete` первым
шагом там, где важен точный счёт, и `--rebuild`, когда песочница разъехалась.

## Автоматизация — харнесс

Решение 2026-09-02: автоматизировать всё, что даёт адекватный результат;
оконный харнесс в репо — первым: те же кодовые пути, что у пользователя,
~70 % чек-листов, Claude не трогает экран. Отвергнуто: фейковая
`IFileSystem` на всё приложение — App и `Preview/` читают `System.IO`,
миниатюры — шелл, живая проверка работы с файлами теряется. Позже: UIA
(FlaUI) на релизном exe в Windows Sandbox — настоящий ввод и DnD с
Проводником; `--scenario` внутри продукта — только если понадобится
релизный бинарник без UIA. Проверки вне рабочей машины — PLAN T.

`tests/Wander.Harness` — консольный STA-проект со ссылкой на `Wander.App`:
настоящие `App`, `MainWindow`, `MainViewModel`, окно за экраном
(`App.Headless`), сценарий из JSON, артефакты в `artifacts\<имя>-<время>\`
(`report.md`, `screenshots\NN-имя.png`, `metrics.json`, `data\` с логом и
`state.json` прогона). Ввод синтезируется на UI-поток; экран и мышь не
трогаются. `HarnessApp : App` после базового `OnStartup` подменяет сервисы
(ниже), показывает `MainWindow` сам (`InitializeComponent` не зовётся —
BAML ищется в сборке наследника; `Resources/Shared.xaml` вливается руками) и стартует
`ScenarioRunner` на `ApplicationIdle`.

```pwsh
.\tools\check.bat qa                              # сборка + selfcheck + smoke-walk, минуты
$h = "tests\Wander.Harness\bin\Debug\net10.0-windows10.0.19041.0\Wander.Harness.exe"
& $h selfcheck                                    # генераторы против читателей Core
& $h sandbox D:\tmp\sb --profiles photos,raw      # песочница руками
& $h run tests\Wander.Harness\Scenarios\smoke-walk.json [--sandbox dir] [--out dir] [--rebuild] [--in-place]
```

Коды: 0 — прошло, 2 — шаг упал (скриншот `fail-N` и причина в отчёте),
70 — упал сам харнесс. `check.bat qa` — отдельный режим, в обычный
`check.bat` не входит: минуты против секунд.

`selfcheck` проверяет генераторы теми классами, которыми их читает
приложение: превью и ориентация из CR3 / DNG / JPEG
(`RawPreviewExtractor`, `MetadataExtractor`), `needle42` из пяти
zip-документов (`ZipDocumentExtractor`), четыре кодировки
(`EncodingProbe`), fb2 с обложкой, теги `tone.wav` (`AudioTags`), «в кубе
12 треугольников» для всех трёх мешей (`MeshFile`), `texture.tga` пиксель в
пиксель против картинки, из которой сделан (`TgaDecoder`), ресурс версии у
`cmd.exe` и `version.dll` (`WindowsExecutableInfo`). Плюс архивы профиля
`archives`: открывает ли шелл **этой** машины каждый из них как папку и
отдаёт ли размер записи — это состояние ассоциаций, не код, и красный шаг
в сценарии `archives` иначе выглядел бы виной приложения. Формат, чью
ассоциацию забрал сторонний архиватор, — строка в отчёте, не падение.
Смысл — отличать сломанный сценарий от кривого тестового файла.

Фикстуры проверяются там же и по тому же правилу: `SandboxBuilder` помнит,
что откуда скопировал (по имени их не найти — имя у фикстуры произвольное, а
расширение может совпасть с генерируемым), и `selfcheck` читает их теми же
классами — теги и обложку у аудио, текст у настоящих docx / epub. Формат, для
которого читателя у нас нет (pdf, doc, webp, zip), только перечисляется:
подменённая фикстура ломается тихо — трек без тегов выглядит как трек без
тегов, и скриншот в `preview-formats` правдоподобен в обоих случаях.

**Что подменяется.** `ILogger` → `CapturingLogger`; `IDialogs` →
`ScriptedDialogs` (ответ по виду диалога, выбор по виду — `AnswerChoice`:
`DeleteInUse` по умолчанию «отмена», `ExitWithOperations` — «принять»;
конфликты по политике, каждый вопрос попадает в отчёт); `IAppStateStore`
не подменяется — пишет в изолированный корень.

`CapturingLogger` слушает событие `FileLogger.Written`, а не свои
собственные вызовы: сервисы из `PlatformBootstrapper` получают логгер в
конструкторе и больше не ищут его в локаторе, поэтому логгер,
зарегистрированный поверх, их строк не видит — и `assert-log noErrors`
пропустил бы их ошибки. Событие поднимается под замком записи: подписчик
не логирует и не блокирует.

Пути в логе прогона настоящие: харнесс сразу после окна включает
`Settings.LogPaths` (у человека по умолчанию метки), и `assert-log` находит
пути песочницы. Первые строки сеанса, до этого, — метками.

**Окно не должно оказаться на экране.** `App.Headless` — окно за экраном
(`Left = -32000`; координаты — в конструкторе `MainWindow`:
`ShowActivated = false` учитывается до показа), не в панели задач,
геометрия не читается и не пишется, крах — лог и `Shutdown(1)`. Ставят
смок и харнесс (`internal set`, `InternalsVisibleTo("Wander.Harness")`); в
`App.OnStartup` флаг только включается (`Headless |= IsSmokeRun`):
присваивание затёрло бы флаг харнесса, и окно вышло бы на рабочий стол с
фокусом. `HarnessApp` перепроверяет флаг и отказывается работать при
выключенном, а позицию окна пишет в лог:
`HARNESS window at (-26214, -26214), taskbar=False, active=False`.

**Диалоги тоже.** WPF ставит окно с `CenterOwner` при владельце в
(−32000, −32000) ровно в (0, 0) — на рабочий стол человека
(`ShowActivated = false` с `ShowDialog` работает). Поэтому каждое окно
приложения зовёт `App.ParkIfHeadless(this)` в конструкторе; новое окно
обязано тоже. `App.WatchWindowsWhenHeadless` пишет в лог каждое окно и
попап (`HEADLESS …`, на экране — `WARN`), эти строки — в отчёт прогона.
2026-09-16 одно окно всё же мелькнуло на кадр, какое — не найдено; отсюда
правило «сценарии только по просьбе» (QA.md, «Кто и когда гоняет»). Решение человека 2026-09-30:
[со своим рабочим столом вопрос решён, сторож оставить].

**Свой рабочий стол** (2026-09-29). Окно за экраном и без активации всё
равно забирало системный фокус: при первом переносе клавиатуры внутри
окна (редактор имени на шаге `new-folder`) WPF отдаёт окну Win32-фокус,
окно активируется и выходит в foreground — у человека видео в браузере
выходило из полного экрана.
`WS_EX_NOACTIVATE` не годится: с ним WPF клавиатуру не даёт вовсе
(`AcquireFocus` ждёт Win32-фокуса в потоке), а шаги смотрят именно её.
Поэтому `run` запускает себя заново на отдельном рабочем столе Windows —
`HarnessDesktop`: `CreateDesktop` «WanderHarness», `STARTUPINFO.lpDesktop`,
та же консоль, тот же вывод и код выхода. Foreground у каждого рабочего
стола свой, и окно прогона — WPF, шелла, WebView2 — на экран человека не
попадает. Второй процесс — в job с `KILL_ON_JOB_CLOSE`: прогон, убитый
снаружи, не оставляет приложение, которого никто не видит. `--in-place` —
сценарий в этом же процессе, на рабочем столе запуска: для отладчика.
Проверка — наблюдатель за `GetForegroundWindow` раз в 10 мс (только
чтение): до правки окно харнесса вышло в foreground на шаге 3 `file-ops`,
после — ни разу за десять сценариев; шаги, время и скриншоты те же. Smoke
(`--smoke`) под тем же наблюдателем foreground не взял (один прогон) — как
и старт сценария до первого шага с клавиатурой.

**Поля сценария**: `name`, `sandbox` (папка под `%TEMP%\wander-sandbox`),
`profiles[]`, `state` (таблица профилей; кладёт `Program.SeedState`),
`stopOnFailure`,
`stepTimeoutMs`, `steps[]`. Комментарии `//` разрешены.

**Шаги сценария** (`{"do": …}`; пути с `{sandbox}` и `{out}`):

- `navigate path` — ждёт первый экран и тишину.
- `wait-idle [quietMs, idleTimeoutMs]`, `screenshot name`, `measure name`,
  `sleep ms`, `note text`.
- `view Details|Tiles|LargeIcons|Gallery`.
- `select names[]` — через контрол активного вида (путь клика).
- `command name` — delete, permanent-delete, copy, copy-to («Скопировать
  в…», папка — из `dialogs folder`), cut, paste, new-folder, refresh, undo,
  up, back, forward, clear-search; деструктивные — только когда текущая
  папка внутри песочницы.
- `rename name to`.
- `key Key [repeat]` — без модификаторов (`Keyboard.Modifiers` читает
  настоящую клавиатуру; для `Ctrl`-сочетаний есть `command`).
- `settings name value` — свойство `SettingsViewModel`.
- `dialogs {default | kind + accept | conflict | prompt | folder}`.
- `fs {op: create | mkdir | append | delete | move | lock | unlock, path}` —
  только в песочнице; `delete` не ругается на отсутствующий путь (шаг
  сброса); `create` и `delete` с `count` — серия файлов, `{n}` в имени —
  номер с 001; `move {to}` — переименование или перенос «другой
  программой»; `copy {to}` — копия «другой программой»; `lock` держит
  хэндл до `unlock` или конца прогона.
- `preview on`.
- `preview-format {ext, name}` — файл с таким расширением, если он тут
  есть, — выделить и снять; нет — строка в отчёте, не падение.
- `helpers {on[]}` — хелперы отсмотра `ReviewHelpers` по именам свойств:
  названные включены, остальные выключены; `[]` — все выключить.
- `tree-expand path [panel: drives|bookmark] [expand: false]` — шевроны
  событиями модели, курсор панели в конце на строке.
- `tree-rename {path, to}` — папка панели через `RenameFolderAsync`;
  редактор и `F2` остаются человеку.
- `tree-target path [panel]` — курсор панели на строку и клавиатура в
  панели — два факта, из которых модель выводит цель.
- `assert-tree {path, panel, exists: false | chevron | expanded | selected |
  name}` — строка панели как она нарисована, `selected` — под курсором
  панели; закрытые ветки по пути не раскрывает — сначала `tree-expand`.
- `post {event, …}` — событие модели окна полями JSON: `WindowActivated`,
  `WindowDeactivated`, `ZoneEntered {zone, reason}`, `CaretMoved`,
  `ChevronToggled {open, all}`, `RowClicked`, `RowActivated`,
  `CaretMoveRequested {key, pageSize}`, `PanelsRefreshRequested`,
  `PaneHidden {zones[]}`, `DialogOpened`, `DialogClosed`,
  `ViewModeChanged`; `panel: bookmark` — закладки; ждёт тишины.
- `assert-state {field, value}` — факт модели: `folder`, `keyboard.zone`,
  `keyboard.lastZone`, `drives.caret` / `.location`, `bookmarks.caret` /
  `.location`, `list.caret`, `list.primary`, `target` — вид цели,
  `target.folder`; `list.selection` с `names[]` в любом порядке; нет
  значения — «ничего».
- `assert-focus {zone, row}` — куда исполнитель поставил клавиатуру:
  зона, `none` — никуда; `row` — имя в списке, путь в панели.
- `assert-folders {pinned: {путь: вид}}` — `folders.json` после записи.
- `sort {key}` — порядок открытой папки, как клик по заголовку: тот же
  ключ — другое направление.
- `stars {rank | clear}` — фильтр по звёздам: щелчок по звезде, «только эта
  оценка».
- `place {name, rows}` — прокрутить список так, чтобы строка встала на
  `rows` строк ниже верха, и запомнить место.
- `assert-place {name, kept, tolerance, onScreen: false}` — строка на
  экране; `kept` — там, где её оставил последний `place`, под каким бы
  именем и среди каких бы строк она ни была; место читается с контейнера
  строки, не из арифметики вида.
- `bookmark {op: add|remove|rename, path}`; `rename` берёт название из `dialogs prompt`, пустое — имя папки.
- `search {name, text, subfolders, binaries, searchTimeoutMs | box}` —
  `box` — набрано в поле над списком: живой фильтр и обход подпапок,
  который его продолжает; `subfolders` при `box` — кнопка у поля, по
  умолчанию включена.
- `soak {minutes, maxWorkingSetGrowthMb, maxHandleGrowth, seed}`.
- `assert-log {contains | regex | absent | noErrors [+ allow[]], scope:
  step|all}`.
- `assert-entries {count | min | max | contains | absent | selected, scope:
  model|visible}`.
- `assert-path {is, crumbs[]}`.
- `assert-status {key}` — строка состояния говорит то, что строка ресурса
  (с плейсхолдерами — её начало до первого): отказ, который пишется только
  туда.
- `assert-operations {finished, failed, outcome, verified}` — завершённые
  операции; у новейшей — упавшие, итог, проверенные; ждёт конца идущих.
- `assert-files {exist[], absent[], ranks, sizes, datedAs}` — файлы на
  диске; размер в байтах, дата изменения — как у другого файла (± 2 с).
- `assert-pane {minList}` — ширина окна, панели просмотра и остатка под
  список — в отчёт; `minList` роняет шаг, если списку осталось меньше.
- `drop {paths[], target, effect: Copy|Move|Link}` — drop прямо во
  вьюмодель, минуя WPF: маршрут записи архива в извлечение,
  подтверждения, прогресс, undo; цель только в песочнице.
- `device {op}` — телефон сценариев (`HarnessDevice`): `plug {root,
  locked}` — хранилище — папка песочницы, `locked` — без хранилищ;
  `unplug`; `break {path, after}` — следующее чтение файла обрывается после
  `after` байт с кодом выдернутого кабеля (0x8007001F), устройство уходит;
  `wait-paused [reason]` — идущая операция ждёт устройство. Приход и уход —
  `WM_DEVICECHANGE` в настоящий `VolumeChangeHub` окна. Настоящие
  устройства харнесс не видит и не читает: `IDeviceContent` и пути
  `device:` в `IShellNamespace` подменены (`HarnessShellNamespace`).

У любого шага — `ifOpensAsFolder` с путём архива: шаг идёт, только если
приложение открывает этот архив папкой на этой машине; при WinRAR или
7-Zip на ассоциации — строка `skipped` с причиной, и в журнале батчей
такой шаг не считается. Спрашивается приложение, а не реестр: научится
Wander открывать формат сам — шаг пойдёт без правки сценария.

`command` и `key` ходят через `CanExecute` и через
`Window.InputBindings`, как настоящая строка меню и настоящий хоткей:
недоступная команда не выполняется, а пишет строку в «Notes» отчёта — так
проверяется, что внутри архива или корзины она именно не срабатывает.
Синтетическое событие клавиши мимо `InputBindings` пролетает (WPF сверяет
их внутри input manager), поэтому раннер сверяет их сам — но только когда
событие никто не обработал. `Enter` в таблице обрабатывает сам список
(`FileListView.List_PreviewKeyDown`: `DataGrid` гасил бы клавишу до
хоткея); `focus-keys` жмёт его в таблице, `archives` — в плитках.

`tree-expand` идёт по уровням — `ChevronToggled` на каждый и ожидание, пока
уровень прочитан (`LevelState.Loaded`): ветка читает детей с диска в
момент раскрытия, и путь на шесть уровней вниз до этого просто не
находится.

`post` и `assert-state` проверяют взаимодействие без WPF-ввода: событие
уходит в `WorkspaceController` тем же путём, что от вью, состояние
читается из модели; `assert-focus` — что сделал исполнитель. Окно
харнесса никогда не активно, поэтому активация — `post WindowActivated`,
а не ожидание: так проверяется перечитывание раскрытого при возврате в
окно. Отложенный до активации перенос клавиатуры живёт в исполнителе
окна, а харнессу исполнитель отвечает сразу — он проверяется глазами
(«Фокус», «Окно в фоне»). Логику цели харнесс не повторяет —
`tree-target` сообщает факты, цель выводит модель.

`assert-entries scope: visible` считает то, что показывает список, а не
`Entries`: **маска имени фильтрует вид, а не `Entries`** — после
`search name` вьюмодель держит всю папку, и проверка по ней проходит,
сработал поиск или нет. Поиск по содержимому кладёт результаты прямо в
`Entries`, там `scope` не нужен.

`preview-format` — для форматов, которые никто не генерирует: они приезжают
из `tests/Fixtures/` по расширению, и на машине без фикстуры сценарий обязан
пройти. Берёт первое совпадение по имени, поэтому годится только там, где
генератор такого расширения не пишет: `.pdf` в `docs` — это сгенерированный
`manual.pdf`, у которого свой шаг. Чего не нашлось, перечислено в отчёте
списком «эту ветку панели не открывали».

`assert-log noErrors` + `allow[]` — сценарий, который **нарочно** вызывает
ошибку (занятый файл, безвозвратное удаление), называет её. Именно
называет: ожидаемая ошибка остаётся проверяемой, а не становится уровнем,
на который перестали смотреть.

`soak` меряет плато **от конца первой минуты**, а не от старта: первая
минута — это заполнение кэша миниатюр, и на ней провалился бы любой
прогон. Отсюда минимум три минуты (одна на прогрев, две на наблюдение);
предрелизные тридцать — это `"minutes": 30` при тех же порогах.

**Сценарии** (`Scenarios\`):

Что клавиатурой и мышью не воспроизводится (`Shift`-выделение, DnD,
чужие пункты меню), помечено в сценариях шагом `note` и попадает в отчёт
списком «посмотреть глазами».

**«Тишина»** = `IsListLoading == false`, строка `First screen painted` для
папки, в которую навигировали (ждём до 5 с), и ничего в логе 400 мс.
Скриншот — `RenderTargetBitmap` визуального дерева: WebView2 (HWND) в нём
пустой.

**Прогоны.** Числа харнесса — Debug плюс сам харнесс в том же процессе:
базлайн харнесса, не приложения. Ожидаемое в чистом прогоне: `ERROR` —
только нарочные (`locked.txt` в `file-ops`, извлечение из архива с
паролем), `WARN` — только «Permanent delete», которым сценарий убирает за
собой; окна — только главное, за экраном. Числа по версиям — сценарии, пик
WS, gen2, хэндлы, soak-30 — в [measurements/](measurements/README.md).
Последний полный прогон — `measurements/0.7-dev.md` (2026-11-02). GC
харнесса между днями несравним (тот же 0.6.0 за soak-5: 70 gen2 2026-10-22,
367 — 2026-11-02): сдвиг против версии — прогоном обоих деревьев в один
день.
