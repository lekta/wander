# Замеры по версиям

Один файл на версию — `0.3.1.md`, — снятый на этапе «подготовка к релизу»
([PRERELEASE.md](../PRERELEASE.md)) и после этого не переписываемый. Внутри:
окружение и коммит, вес и SHA256 поставки, старт и строки `PERF` из логов
живого прогона, память, GC и хэндлы по каждому сценарию харнесса, и
написанный руками «Verdict» — что сдвинулось против прошлой версии и что с
этим решили.

Собирает [`tools/release-metrics.ps1`](../../tools/release-metrics.ps1):

```pwsh
.\tools\publish.ps1 -Run              # ... и погонять минут десять руками
.\tools\release-metrics.ps1 -Version 0.3.1
```

Скрипт ничего не мерит сам — он собирает уже намеренное: опубликованный exe,
свежие логи из `%LOCALAPPDATA%\Wander\logs`, артефакты прогонов харнесса из
`artifacts\`. Чего нет, помечает `n/a` (например, «нет логов свежее 24 ч» —
значит, живой прогон не делали). Окно берётся ключом `-Hours`.

**Чем это отличается от PERFORMANCE.md.** Там — как устроено и почему числа
такие: из чего состоит exe, что даёт ReadyToRun, где узкое место старта.
Тот документ живёт и переписывается. Здесь — снимок конкретной версии,
который через год отвечает на вопрос «когда именно стало на двести
миллисекунд медленнее» без археологии по гиту.

**Что дописывать руками.** Раздел «Verdict» — ради него файл и заводится.
Голая таблица через год не значит ничего: нужно, что сдвинулось против
прошлой версии, что по этому поводу решили и что осталось известной ценой.
Регрессия, с которой согласились, — это строка здесь и строка в TECHDEBT, а
не молчание.
