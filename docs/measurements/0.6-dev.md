# Wander 0.6 — замеры между релизами

Замеры дерева до файла версии (как `0.5-dev.md`).

## Свой цикл копирования против `CopyFileEx` (V1, 2026-10-15)

Стенд в scratchpad (`CopyStand`, консоль со ссылкой на Platform):
`SystemIOFileSystem.CopyFile` с прогрессом и токеном — свой цикл
(`StreamCopy`, буфер 1 МБ, `SetLength` заранее, `FlushFileBuffers` в
конце) и `CopyOptions.SystemOnly` — `CopyFileEx`; проверка — перечитывание
копии без кэша (`FILE_FLAG_NO_BUFFERING`), у `CopyFileEx` — обеих сторон.
Машина человека: один NVMe Samsung PM991a 1 ТБ (C:, D:, E: — разделы
одного диска), копия D: → D:, источник после первого прогона — в кэше.

**SSD → тот же SSD, три прогона:**

| Режим | 2 ГБ, МБ/с | 200 × 5 МБ, МБ/с |
|---|---|---|
| `CopyFileEx` | 117 / 155 / 155 | 139 / 184 / 104 |
| свой цикл | 100 / 102 / 117 | 110 / 121 / 92 |
| свой цикл + проверка | 90 / 92 / 87 | 93 / 93 / 95 |
| `CopyFileEx` + проверка | 82 / 88 / 87 | 121 / 118 / 106 |

**Варианты цикла, 2 ГБ, три круга вперемешку:** `CopyFileEx` 223 / 140 /
134; 1 МБ с `SetLength` 204 / 106 / 134; 1 МБ без него 137 / 133 / 119;
4 МБ 101 / 116 / 117; перекрытие чтения и записи 1 МБ 141 / 99 / 94, 4 МБ
109 / 126 / 147, 4 МБ с `SetLength` 132 / 137 / 106.

**Verdict.** Узкое место — запись самого диска: бюджетный NVMe без DRAM
скачет от 100 до 220 МБ/с между прогонами одного режима (кэш SLC,
нагрев), и разница режимов тонет в этом разбросе. Свой цикл 1 МБ с
`SetLength` — вровень с `CopyFileEx`; перекрытие и буфер 4 МБ выигрыша не
дали — оставлен простой последовательный цикл. Проверка стоит 10–20 % на
SSD (копия читается с диска заново). Флешка USB 3, кардридер, HDD и SMB —
не сняты: нужны устройства человека (PLAN «Спринт 2 — хвосты», V1).
