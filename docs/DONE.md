# Wander — реализовано

Снапшот того, что работает и как устроено сейчас. Пункты приезжают из
PLAN.md при закрытии; история — CHANGELOG.md и гит.

## Архитектура и Core

- 4 проекта на .NET 10: `Wander.Core` (логика, абстракции),
  `Wander.Platform.Windows` (Win32 / Shell / COM), `Wander.App` (WPF),
  `Wander.Core.Tests` (xUnit). Service Locator, без DI.
- Абстракции / реализации: `IFileSystem` / `SystemIOFileSystem`;
  `IShortcutService` / `ShellShortcutService` (`.lnk` через `IShellLinkW`);
  `IRecycleBin` / `ShellRecycleBin` (`RecycleHandle` для restore);
  `UndoService` — LIFO-стек `IUndoableAction` (Move / Rename / Delete /
  Create / Composite), `BeginOperation()`-guard; `ILogger` / `FileLogger`
  (`%LocalAppData%\Wander\logs\session-*.log`, регистрируется первым, он же
  `ILogFile`); `IConflictResolver`; `IFileLockInspector` /
  `RestartManagerLockInspector`; `IIconProvider` / `SystemIconProvider`;
  `IImageMetadataReader` / `MetadataExtractorImageReader` (EXIF включая
  RAW); `IAppStateStore` / `JsonAppStateStore` (`state.json`);
  `IVolumeInfoProvider` / `WindowsVolumeInfo`; `ISystemClipboard` /
  `WindowsClipboard`; `IDirectoryWatcher` / `WindowsDirectoryWatcher`;
  `IShellNamespace` / `WindowsShellNamespace`; `IShellContextMenu`;
  `ITextSource` (реализация в App).

## Файловые операции

- `FileOperationService` — единая точка: `SystemPathGuard`, лог,
  `IUndoableAction` в `UndoService`. `Delete` — в корзину;
  `PermanentDelete` (`Shift+Delete`) обходит её и затирает undo-стек.
- `BatchExecutor`: `CopyManyAsync` / `MoveManyAsync` / `DeleteManyAsync` с
  `OperationTracker` (прогресс и отмена между элементами, модальный
  `ProgressDialog`), conflict resolver, `BatchItemResult[]`; работает
  группами `BatchGroup` (файл + спутники: один вопрос, один шаг прогресса,
  авто-переименование `Sprite (1).png` + `.meta`). Replace отправляет цель
  в корзину и кладёт `DeleteAction` в composite — `Ctrl+Z` возвращает обе
  стороны (осознанное отличие от Explorer).
- Конфликты имён — push-контракт `IConflictResolver.ResolveAll(ConflictRequest)`:
  все коллизии находятся до первого касания диска и спрашиваются одним
  вызовом; ответ — `ConflictAnswer` на каждую показанную пару, включая
  найденные внутри сливаемых папок, привязка по пути источника; null или
  `Cancel` в ответе — отмена всего батча, ничего не применено; коллизия,
  возникшая по ходу (появившийся файл, имя внутри сливаемой папки, о
  котором не спросили), — второй вызов из одного элемента. Каждый файл
  группы — своя коллизия: спутник сравнивается, спрашивается и отвечает
  отдельно от основного файла (содержимое и мета меняются порознь);
  связывает их только имя — переименованный основной файл уводит
  спутников под новое имя, кроме пропущенных. `FileConflictInfo` несёт
  `IsMove` и `SourceReachable` (false для записи архива: ни сравнения, ни
  слияния); `ConflictVerdict.Of` — тот же вид / размер / кто новее (допуск
  2 с, FAT) / «идентичны» (false без чтения при разных размерах, null пока
  не сравнили); `FileContentComparer.AreIdentical` — побайтово блоками по
  64 КБ через `IFileSystem.OpenRead`, обрыв на первом отличии;
  `AutoCompareLimit` 64 МБ делит очередь сравнения на два прохода.
- Слияние папок — `ConflictResolution.Merge`: содержимое исходной папки
  ложится в существующую, вложенные папки сливаются в свою очередь,
  совпадения внутри решаются каждое своим ответом; при перемещении
  опустевшая исходная папка уезжает в корзину, непустая остаётся. Дерево
  совпадений внутри читает `MergeScanner` (Core, через `IFileSystem`,
  предел глубины 64 от junction-петель), считая и файлы без пары.
- Окно конфликтов `ConflictWindow` — один список на весь батч, строка на
  пару: две плашки с миниатюрами (`IconSize.Medium`), размером и датой, у
  каждой галка «оставить эту». Четыре сочетания — четыре ответа: только
  исходник = заменить, только целевой = оставить как есть, обе = оставить
  оба (файл под новым именем, папки — слияние), ни одной = не решено.
  Ответ дублируется словом после имени («заменить» / «оставить» / «оба»;
  для слияния — «слияние: совпадений N, прочих файлов M» или «читаем…»).
  Отмеченная сторона гасит противоположную (только когда выбрана ровно
  одна). Кнопок на строке нет намеренно: кнопка в списке читается как уже
  сделанное действие.
- Слияние в окне: как только у пары папок отмечены обе галки, папка
  читается в фоне и под строкой появляются вложенные строки с отступом —
  только совпадения имён, с путём относительно папки; вложенная пара папок
  приходит уже в слиянии и раскрыта, любую строку можно переключить.
  Переключение папки со слияния прячет вложенные строки, их ответы
  сохраняются. ОК считает и вложенные пары; ответы уходят в исполнитель по
  путям (`ConflictPair`, `ConflictBatch.Effective`).
- Раскладка по образцу системного диалога замены: глагол, размер батча и
  число совпадений — в заголовке окна («Копирование: 10 элем., совпадений
  имён: 3»), «Из:» и «В:» — над левой и правой колонкой, поэтому плашки не
  подписаны. Строки разделены отступом, без линеек.
- Отличия показываются весом, а не фразой: больший размер и более свежая
  дата — жирным. Остальное едет строкой имени, не занимая своей: «файлы
  идентичны», «содержимое отличается» (при равном размере), «разные типы:
  файл и папка», «Папка заменится целиком, без слияния» — только у пары
  папок с выбранной заменой; «Сравниваем…» — пока пара в очереди на
  побайтовое сравнение. Сравнение идёт в фоне по одной паре, сначала все
  до 64 МБ, потом крупные; кнопки «сравнить» нет; нечитаемая пара (занята,
  запись архива) из очереди выпадает молча.
- Два групповых ответа под списком, разной формы. Галка «не спрашивать про
  одинаковые файлы» — политика: отвечает «оставить» за совпавшие побайтово
  пары и продолжает отвечать по мере доезжающих сравнений, снятая —
  забирает ровно свои ответы и не трогает пользовательские. «Оставить» —
  всё остаётся где было: копия не создаётся, при перемещении исходник
  остаётся на месте (как Skip у Проводника). «Применить к нерешённым» —
  булеты (заменить / оставить оригиналы / оставить оба / заменить, если
  новее), применяются один раз к тому, что открыто, вложенные строки
  включительно; уже данный ответ не перетирается. Изначально не выбран ни
  один: нетронутый список и так решается по каждому.
- ОК активен, когда решены все пары, `Enter` ни к чему не привязан, `Esc` —
  отмена; ОК и Отмена стоят в отдельной полосе внизу, чтобы не читаться
  наравне с выбором по строке. Окно resizable, геометрия в
  `AppState.ConflictWindow`. Состояние и правила — `ConflictBatch` в Core
  (тесты), окно только рисует.
- Настройка «Не спрашивать про одинаковые файлы»
  (`AppSettings.SkipIdenticalOnConflict`, «Основное», включена по
  умолчанию: замена файла его же байтами ничего не меняет) — начальное
  состояние той галки.
- Копирование туда, где элемент уже лежит, конфликтом не считается:
  `BatchExecutor` сам отвечает «оставить оба» и делает `имя (1).ext` со
  спутниками, ничего не спрашивая; перемещение в свою же папку — no-op, а
  вырезание с вставкой в ту же папку просто снимает вырезание со строкой
  «Уже в этой папке, вырезание снято» в статусе (`PathSafety.AllAlreadyIn`).
  `Ctrl`-перетаскивание в свою папку больше не запрещено сторожем
  (`PathSafety.IsAllowedDuplicate`): папка на себя и папка в свою же
  подпапку по-прежнему запрещены.
- Cross-device move папок — `CopyDirectory + DeleteDirectory`. Read-only:
  явный список + второй вопрос, снятие атрибута. Self-drop — понятный
  текст. Locked — RestartManager: «файл открыт в: Word (PID 1234)».
- Подтверждения с Cancel по умолчанию на Delete и Move (включая DnD).
  Оба отключаются в «Основном»; отключённое подтверждение не отменяет ни
  разбор конфликтов при перезаписи, ни `Ctrl` + `Z`.
- Корзина: «Восстановить» первым в меню, на нескольких элементах; отката
  нет, как в Explorer.

## Навигация, дерево, закладки

- Дерево дисков: lazy-load, шеврон оптимистичный (`ProbeForChevrons` фоном
  убирает у листьев), сохранение раскрытых путей, авто-раскрытие на текущую
  папку, **никогда не сворачивается само**.
- Левая панель — `Views/FolderTreesView`: закладки сверху, дерево снизу,
  перемычка (`SessionState.BookmarksHeight`), свёрнутые закладки отдают
  высоту дереву. Наружу три события (`ContextMenuRequested`,
  `FolderTargeted`, `FocusListRequested`), DnD подключается
  `Connect(drops, drag)`.
- Строки под Проводник: подсветка во всю ширину, клик по любому месту,
  отступ — `TreeIndentConverter`.
- Закладки: зона «+» под списком (не кнопка; подсвечивается только под
  перетаскиванием папки, которой ещё нет; плашка говорит «Добавить … в
  закладки»); кнопка «…» = меню правой кнопки: «Переместить вверх / вниз»
  (`Ctrl+↑/↓`, порядок в `AppState.Favorites`), «Убрать», у пропавшей —
  «Указать расположение…». Стандартные папки выше своих, отделены чертой
  (флаг `TreeNodeViewModel.StartsUserSection`, не отдельный узел),
  выключаются в настройках. Закладка на пропавшую папку остаётся серым
  курсивом без шеврона; клик — панель «папка удалена или недоступна» с
  «Указать расположение…» (путь заменяется на месте) и «Убрать»; состояние
  взводит само перечисление по `DirectoryNotFoundException`. Выбор
  расположения открывается на самой глубокой уцелевшей части старого пути
  (`PathCrumbs.NearestExisting`): у закладки на `A:\B\C\D` без `D` поиск
  начинается в `C`, без `C` — в `B`. На мёртвом пути диалог открылся бы
  там, где Windows был в прошлый раз, — обычно на другом диске.
- Папка из дерева перетаскивается тем же конвейером, что файлы. Правый
  клик по узлу — цель операций (`SelectExternalPath`) + меню папки без
  перехода. Клик по папке переходит и выбирает её
  (`NavigateAndSelectFolder`, после прихода листинга). `Alt` + шеврон:
  раскрыть с детьми / свернуть рекурсивно. `Shift` + колесо —
  горизонтальная прокрутка везде.
- «Открыть в терминале» — единственный встроенный пункт со значком (глиф
  `Segoe MDL2 Assets`): стоит среди сторонних, у которых значки есть у всех.
- `NavigateTo` не проверяет путь на диске (спящий диск стоил секунды на
  шаг); «папки нет» скажет листинг. Набранный руками путь проверяется в фоне.
- Панель не меняется на спуске: шаг в подпапку наследует источник
  (`DescendSource`), как `GoUp`; `NavigationSource` в истории.
- В дереве стрелки только двигают курсор, входит `Enter` (настройка
  «стрелки открывают папку» — коалесировано: одиночное нажатие сразу,
  серия — по остановке; эхо перевыделения гасится до `ArrivalIntent`);
  мышь — клик = переход. Пока клавиатура в панели папок, узел под курсором
  — цель `Delete` / `Ctrl+C` / `Alt+Enter` (`TargetTreeNode`), список
  отпускает выделение.

## Архивы как папки

Секция P, P1 … P3 + P7 / P8, 2026-09-02. Устройство — ARCHITECTURE.md,
«Shell-namespace: корзина и архивы».

- `Enter` / двойной щелчок на архиве, который открывает сам Windows
  (`.zip` через `CompressedFolder`, `.7z` / `.rar` / `.tar.gz` и ещё
  десяток через `ArchiveFolder`, `.cab` через `CABFolder`), заходит внутрь
  как в папку: адрес и крошки обычные (`GetDisplayName` → null), `up` /
  `Backspace` наверх, имя, размер, дата, папки папками, сортировка и
  фильтр по имени как везде. Своего читателя архивов нет: набор расширений
  берётся из реестра по ProgID (с учётом `UserChoice`), и ассоциация,
  отданная 7-Zip, закрывает просмотр папкой — как в Проводнике.
- Один предикат на весь код — `Archives.Of(path)` →
  `IShellNamespace.ParseArchive`; `ArchivePath.Parse` (Core, чистая
  функция) режет путь надвое, Platform проверяет `File.Exists`
  контейнера — настоящая папка `backup.zip` открывается папкой.
  `MainViewModel` кэширует ответ на смену пути.
- Листинг — та же ветка, что у корзины (`RefreshShellAsync`: эпоха,
  спиннер, отмена, `PublishRows`), плюс сортировка `EntryComparers`;
  запись читается через `IShellItem2` (`PKEY_Size`, `PKEY_DateModified`),
  не через `Shell.Application` — тот для `ArchiveFolder` врёт. Первый
  экран замеряется как у обычной папки.
- Извлечение — `FileSystem/ExtractionService` (Core) поверх
  `IShellNamespace.CopyOut` (`IFileOperation` с `FOF_NO_UI`): один вызов
  движка на батч, `SystemPathGuard` на цель, диалог замены (Replace →
  старое в корзину), лог, прогресс в `OperationTracker`, отмена через
  sink, `Ctrl+Z` (`ExtractAction` — извлечённое в корзину). Входы:
  `Ctrl+C` внутри + `Ctrl+V` в обычной папке, «Извлечь…» в меню (для
  архива, выделенного в папке, — всё содержимое в выбранную папку).
- «Открыть» файл внутри — временная копия в `AppPaths.Tmp` (подпапка по
  хешу пути, `TempFiles.Sweep` на старте чистит старше суток) и запуск
  ассоциацией; статусная строка предупреждает, что правки в архив не
  вернутся. Осознанное отступление от «всё откатываемо» — записано в
  ARCHITECTURE.
- Внутри архива выключено решением: удаление, переименование, вырезать,
  вставка, создание, drop внутрь, сторож, оценки, спутники, поиск по
  содержимому и подпапкам, статистика папки в футере, миниатюры (значок по
  расширению). Меню внутри — четыре строки (Открыть, Копировать,
  Извлечь…, Копировать путь), у архива в обычной папке — обычное меню плюс
  «Извлечь…». Панель просмотра — карточка: имя, размер, дата и «В архиве».
- Пустой листинг при ненулевом файле — «пусто или защищено паролем»
  (7z с `-mhe` неотличим от пустого); нечитаемый контейнер — «архив
  повреждён или недоступен»; неудавшееся извлечение из zip с паролем —
  «не извлечь, архив защищён».
- Архив — узел в обеих панелях дерева, среди папок по имени, как в
  панели навигации Проводника: раскрывается в свои папки
  (`TreeNodeViewModel.ReadChildFolders` — файлы, которые шелл открывает
  папкой, плюс ветка через `IShellNamespace.Enumerate` внутри), клик —
  листинг, стоя внутри архива дерево подсвечивает путь внутри. Шеврон у
  архива не пробуется в фоне (это открытие каждого архива папки через
  шелл) — пустой теряет его при первом раскрытии. Drop на такой узел и
  меню по нему — нет (`Archives.Contains` там же, где `shell:`). Закладка
  на архив раскрывается как узел; закладка внутрь архива — лист, не
  «пропавшая».
- Проверяется: `ArchivePathTests`, `ExtractionServiceTests`,
  `ContextMenuBuilderTests`; профиль песочницы `archives` + сценарий
  `archives`; `selfcheck` спрашивает шелл машины, видит ли он фикстуры
  папками.

## Клавиатура и области окна

- `Tab` / `Shift+Tab` по областям: кнопки навигации → адрес → фильтр →
  закладки → дерево → список; недоступные (свёрнутые закладки, пустая
  история) пропускаются; `GridSplitter` из цепочки убран. Активная область
  — серая рамка (`OnZoneFocusChanged`). Логика — `Wander.Core/Layout/WindowZones`
  (`Order`, `Ring`, `FolderPane`).
- Прямые адреса: `Ctrl+1` панель папок (на узел текущей папки в той панели,
  из которой открыли; повтор переключает панель; свёрнутые закладки
  разворачиваются), `Ctrl+2` список, `Ctrl+Shift+E` текущая папка в дереве,
  `Ctrl+Q` панель просмотра, `Alt+D` / `Ctrl+L` адрес,
  `Ctrl+Shift+1/2/6/7` виды (цифры Проводника).
- `Esc` нигде не запирает фокус — из фильтра, адреса, дерева возвращает в
  список.
- Стрелки на границах сетки (`Wander.Core/Layout/GridNavigation`): сетка =
  один список, свёрнутый в строки; `→` в конце строки — следующая, `↑` в
  верхней — первый файл, `↓` в короткую последнюю — её последний; `Shift`
  тянет через границу, якорь вычитывается из выделения (конец, где нет
  каретки). Перехватываются только нажатия, на которые WPF отвечает
  «некуда».
- Фокус и выделение переживают операции: после удаления — следующий
  уцелевший, после вставки — вставленное, после подъёма — папка, из которой
  вышли; возврат в папку восстанавливает выделение (память 64 папок,
  `FolderSession`); `IUndoableAction.PathsAfterUndo` — после `Ctrl+Z`.
- Хоткеи списка: `Ctrl+A`, `Ctrl+C/X/V`, `Del`, `F2`, `Enter`, `Backspace`
  (вверх), `Ctrl+Shift+N`, `Esc`, `Alt+Enter` (без выделения — свойства
  папки), `Alt+←/→/↑`, `F5`, `Ctrl+Shift+C` (путь). Пока идёт правка
  имени, хоткеи окна не работают (туннелирующий `OnPreviewKeyDown`
  проверяет редактор — иначе `Esc` снимал выделение раньше отмены правки).
- Type-ahead: буквы прыгают на файл; пауза 1 с сбрасывает; заворачивается
  через конец; одна буква ищет после текущего (повтор обходит все на неё),
  длинный префикс — с текущего. `TypeAheadController` в Core с
  подставляемыми часами.

## Список файлов

- Все виды и жесты — `Views/FileListView`; наружу `DragStartRequested` и
  `ContextMenuRequested`. Четыре вида: Таблица (`DataGrid`), Плитка,
  Крупные значки, Галерея — три последних на `Controls/VirtualizingWrapPanel`
  (только видимые ячейки, контейнеры переиспользуются, `IconImageCache`
  держит декодированное). Арифметика — `Wander.Core/Layout/` (`TileLayout`,
  `TileMetrics` — размер ячейки из настроек, не из измерения). Плиточные
  без горизонтальной прокрутки, Таблица — с ней.
- Листинг заезжает одним уведомлением (`BulkObservableCollection.ReplaceAll`:
  4 уведомления вместо 7681 на 5000 файлов). Перечисление —
  `DirectoryInfo.EnumerateFileSystemInfos()`. Обновление той же папки —
  `ListingDiff` (удалить / вставить / сдвинуть; неизменённые строки
  сохраняют контейнеры; полная перестройка только на смену сортировки).
  Уход в другую папку убирает старые строки ниже ввода (`Background`),
  очистка пропускается, если листинг уже пришёл; спиннер только на
  медленной папке (150 мс).
- Рамка выделения (`Controls/RubberBandController`) — с пустого места;
  мебель списка — `Util/ListVisuals.IsChrome`. Нажатие только **взводит**
  жест, прямоугольник появляется после системного порога перетаскивания:
  щель между плитками в несколько пикселей плюс дрожь руки выделяли обоих
  соседей, теперь это клик по фону. Ховер есть во всех четырёх видах
  (в Таблице добавлен), так что «есть ли элемент под курсором» видно до
  клика.
- **Каретка** — «последний выделенный», рамка как в проводнике
  (`MainViewModel.CaretPath` + `CaretRowConverter`, кисть `RowCaretBorder`,
  триггер последним в стиле контейнера, поэтому видна и на выделенной
  строке). Клик по пустому месту снимает выделение, но рамку оставляет:
  выделенной считается текущая папка (панель просмотра показывает перепись
  папки), а стрелка возвращает список к строке в рамке
  (`TryEnterList`, `CaretIndex`). Путь, а не строка: строки заменяются на
  каждом перечитывании.
- Отложенный клик (`Util/SelectionController`) — и для `Ctrl`: WPF
  переключал выделение на нажатии, поэтому `Ctrl`-перетаскивание за один
  из выделенных файлов роняло именно его. Теперь переключение
  применяется на отпускании, а начавшееся перетаскивание его отменяет;
  единственное исключение — `Ctrl` по невыделенной строке: она
  добавляется, иначе поехало бы не то, за что взялись.
- Имя выделенной ячейки показывается целиком: в Крупных значках и Галерее
  подпись снимает ограничение по высоте, ячейка растёт вниз
  (`VirtualizingWrapPanel.MeasureChild`), сетка не переливается —
  раскладка считается от размера ячейки, а не от содержимого. Рост
  ограничен случаем «выделена ровно одна» (`IsExpanding`): при нескольких
  росли все и нижняя из соседних накрывала верхнюю. Ограничение вешает
  триггер «не выделен», а не атрибут метки: `DynamicResource` в шаблоне
  ложится значением на сам элемент и перебивает триггер шаблона, поэтому
  снять его триггером нельзя (первый подход так и провалился — многоточие
  уходило, высота оставалась). Второе условие — панель слушает
  `SelectionChanged` владельца и инвалидирует себя: контейнер с
  неизменившимся ограничением возвращает прежний `DesiredSize`, и без
  этого панель просто не узнаёт, что мерить надо иначе (детали —
  ARCHITECTURE). **Не закончено:** в живом окне выросшую ячейку всё равно
  перекрывает сосед снизу — имя опять обрывается; на offscreen-стенде
  `Panel.ZIndex` из `ArrangeOverride` кладёт её поверх (проверено и
  растеризатором, и `PrintWindow`), а живое приложение расходится со
  стендом, причина не пойма́на (BACKLOG, «Интерфейс»).
- Inline rename `F2` во всех четырёх видах: один `TextBox` на контрол в
  adorner-слое `ScrollContentPresenter` (`RenameAdorner`), находит подпись по
  `x:Name="NameLabel"` (контракт шаблонов); расширение не выделяется,
  запрещённые символы не вводятся; `Enter` применить, `Esc` отменить, клик
  мимо применить — в том числе клик по пустому месту той же папки, который
  редактор раньше переживал (список помечает такое нажатие обработанным,
  чтобы владеть лассо, поэтому клавиатура не уходила из редактора и он
  висел над снятым выделением; теперь нажатие само применяет правку —
  `CommitRenameOnClickAway`); фокус остаётся на строке (в `DataGrid`
  синхронизируется текущая ячейка). Текст переносится по строкам, редактор растёт вниз
  (`RenameAdorner` меряет по нужной высоте) — длинное имя видно целиком, а
  не окном в шесть символов. Запасной `PromptDialog` — для строки, не реализованной

- Подсветка в плитках — на файл, не на ячейку: `ControlTemplate`
  контейнера (`TileChrome` → `TileItem`, в галерее `GalleryItem`), отступ —

- Размеры у каждого вида свои (Таблица: строка и значок; Плитка: ширина,

- Сводка «Выбрано: N · размер» отдельным полем статус-бара; папки
  считаются объектами, не байтами.
- Вырезанные строки гаснут (`MainViewModel.CutPaths` + `CutRowConverter`),

## Контекстное меню

- Строится на каждый правый клик: `ContextMenuBuilder` (Core, чистая
  функция) → `ContextMenuFactory` (App); разметки меню в XAML нет. `Menu` /
  `Shift+F10` — то же с клавиатуры.
- Клик вне выделения переносит его, внутри — сохраняет, по пустому —
  снимает и даёт меню папки. Порядок по частоте: `Открыть`, «Открыть с
  помощью», сторонние; свои операции — в подменю «Файл»; фон — `Вставить`,
  `Создать папку` первыми.
- Сторонние (7-Zip, TortoiseGit, Notepad++, антивирусы, системное
  «Создать») — классический `IContextMenu` с иконками и подменю; дубли
  режутся по каноническому глаголу, включая «Открыть с помощью».
  `ShellMenuCache` — повтор по тому же выделению не ходит в шелл.
- Настройки → «Контекстное меню»: мастер-выключатель, чёрный список,
  галочка на каждый свой пункт; разделители схлопываются. Таблицу собирает
  `ShellExtensionCatalog` из реестра (приложение, типы) и виденного в меню
  (подпись), слияние по нормализованному ключу; не попадают пункты с
  ключом-CLSID и без имени / приложения / описания (галочка не сработала бы;
  уже выключенных и уже встреченных это не касается); одинаковые строки
  складываются (`Fold` → `Aliases`; BitLocker даёт два глагола с одной
  подписью), но только при равных подписи, приложении и областях; строка с
  именем приложения («7-Zip») — весь его раздел, содержимое решает
  обработчик при открытии.
- Свои команды: «Выбрать приложение…», «Открыть в терминале» (папка и фон),
  «Копировать путь» (`Ctrl+Shift+C`), «Копировать имя», «Создать ярлык».

## Drag & drop

Внутри окна и внешний (`FileDrop`). Эффект: тот же диск Move / другой Copy /
`Shift` Move / `Ctrl` Copy / `Alt` ярлык. Плашка (`DragPreview/OutgoingDrag`,
один конвейер для списка и дерева): иконка + `+N`, индикатор действия,
текст с целью, DPI; внутри окна при `Effects=None` без причины — скрыта,
причина показывается только когда целились в папку
(`DropTargetController.TargetIsFallback`). Плашка садится справа-снизу от
курсора и переворачивается на другую сторону, когда там нет места
(`WindowPlacement.BesideCursor`) — иначе у нижнего края экрана, куда и
ведёт перетаскивание на панель задач, надпись уезжала за экран. За
пределами своих окон (`WindowFromPoint` → наш ли процесс) плашка говорит
только «что в руках»: разрешён ли drop, отвечает приложение-цель, и
отвечает системным курсором — свои вердикты и свой курсор там были бы
выдумкой. Подсветка цели — adorner, у `TreeViewItem` только строка (`Bd`).
Drop на `.lnk` папки — в реальную. Приём — `DropTargetController`, общий
для списка и панелей.

## Буфер обмена — общий с системой

`Ctrl+C` виден в Проводнике и наоборот: `CF_HDROP` + `Preferred DropEffect`
(DWORD, вся разница копировать / вырезать). Запись наружу сразу, чтение —
при активации окна (буфер эксклюзивный и межпроцессный, а `CanExecute`
дёргается десятки раз в секунду). Следствия: прочитанное побеждает (чужой
текст гасит «Вставить»); нечитаемый буфер ничего не портит (запись при
занятом буфере остаётся внутри, статус-бар сообщает); виртуальные файлы
(вложения писем, архивы — поток содержимого) — честная строка в
статус-баре; после «вырезать → вставить» чистятся оба буфера; спутники
расширяют выделение до группы до записи. `ISystemClipboard` (Core) /
`WindowsClipboard` (чистый Win32, без WPF) / `ClipboardController`.

## Список обновляется сам

`IDirectoryWatcher` / `WindowsDirectoryWatcher` за открытой папкой; галочка
«Обновлять список автоматически». Троттл 0,5 с, таймер повторяющийся
(перезапускаемый не сработал бы при непрерывном потоке), останавливает себя
без изменений. Откладывается: пока правится имя и пока идёт своя операция.
Shell-namespace не отслеживаются. Сторож называет файл и «изменился ли
состав» — выборочное перечитывание строк (правило в CLAUDE.md).

**Миниатюра не переживает свой файл.** Кэши миниатюр ключуются путём, а
путь не меняется, когда меняется файл под ним, — картинка удалённого файла
показывалась вместо копии, положенной под тем же именем. Две страховки:

- сторож папки называет каждый затронутый путь, в том числе при изменении
  состава (`FolderChanges.ChangedPaths` → `WatchTickDecision.Stale`), и тик
  чистит по нему `IIconProvider.Forget` + `IconImageCache` +
  дисковую запись, после чего `AsyncIcon` перерисовывает иконки этого пути
  (статическое событие, подписка живёт от `Loaded` до `Unloaded`);
- листинг при публикации сверяет `FileStamp` (mtime + размер) каждой строки
  с тем, что был у закэшированной картинки (`ForgetIfChanged`) — это ответ
  на правку, которую никто не сторожил: папку посмотрели, ушли, файл
  изменили снаружи, вернулись. Один словарный поиск на строку, диска не
  касается.

Дисковый ключ и так несёт mtime и размер; точечное удаление файла кэша
закрывает единственную дырку — перезапись с сохранением обоих. Оно уходит
на пул: тик сторожа живёт на UI-потоке.

## Панель просмотра

- Отдельный контрол `Views/PreviewPane` (зум правой кнопкой, транспорт,
  WebView2); окно — ширина и видимость, состояние сохраняется.
  Маршрутизация — `PreviewRouter` в Core (`PreviewRoute` ≠ `PreviewKind`:
  чем прочитан ≠ чем нарисован). Загрузки async с отменой и спиннером.
- Контент: Image, Gif, Video, Audio, Text, Code (AvalonEdit), Document
  (RTF в `RichTextBox`), Web (WebView2: PDF / HTML / MHTML / Markdown /
  FB2), Model (STL / OBJ / glTF / GLB), Folder.
- Фон — `MainViewModel.ContentPalette` (палитра области файлов, не
  настройка галереи: в таблице список светлый — панель тоже); текст, код,
  документы — на своём светлом (страница на тёмном — прямоугольник с
  рамкой).
- Текст: > 1 МБ — первый мегабайт + «показано начало, всего N МБ»,
  оборванный `U+FFFD` срезается. Кодировка — `Wander.Core/Preview/EncodingProbe`:
  BOM → строгий UTF-8 → Windows-1251 / DOS-866 по счёту строчных против
  прописных (порог 8 кириллических букв, иначе немецкий с умляутами —
  «русский»); таблицы кодировок выписаны в Core. Markdown — свой
  `MarkdownPipeline` (`UsePipeTables` + `UseGridTables` +
  `UseEmphasisExtras` + `UseTaskLists` + `UseAutoLinks` + `UseFootnotes`; не
  `UseAdvancedExtensions` — тянет iframe и `{#id .class}`).
- Книги: `.fb2` — `Fb2Document` → HTML (обложка, название, авторы,
  аннотация, текст), предел 400 000 символов по ходу обхода (книга бывает
  одной `<section>`), картинки `data:` с бюджетом 6 МБ.
- Видео и звук — один транспорт: воспроизведение / пауза, повтор, ползунок,
  часы. **Начать сначала** (`RestartMedia`) — две дороги по признаку «файл
  объявил длительность». Объявил — перемотка `Position = 0; Play()`,
  картинка на экране стоит до первого кадра нового прохода. Не объявил —
  только `Close()` + свежий `Open()`: замерено на стенде `MediaPlayer`
  (2026-09-03) на `burn-in-hell-elmo.mp4` (0,8 с, контейнер без
  длительности) — после конца `Position = 0; Play()` и `Stop(); Play()`
  оставляют позицию на нуле, а файл с длительностью берёт все три способа.
  Переоткрытие стоит кадра пустоты между закрытием и первым кадром
  (элемент без медиа схлопывается в ноль, потом рисует чёрное) — его
  закрывает снимок последнего кадра поверх элемента (`HoldLastFrame`,
  `VideoHold` в XAML; сам элемент держится в размере через `MinWidth` /
  `MinHeight`), снимается первым тиком, где позиция сдвинулась. Через
  `RestartMedia` идут и повтор, и второе нажатие кнопки. Признак
  «доиграл» — флаг, а не позиция: движок сам отматывает на ноль в конце,
  поэтому «я в конце?» отвечает «нет» ровно тогда, когда клип кончился
  (из-за этого кнопка и была мертва после первого показа).
- Повтор включается сам для роликов короче трёх секунд и для файлов без
  объявленной длительности (`PlaybackClock.LoopsByDefault`; звука не
  касается — двухсекундный шум по кругу это не просмотр), выбор — на файл,
  не на сеанс, и перезапуск его не сбрасывает. Часы — `Timecode`: позиция
  вниз, длительность **вверх**; когда файл длительности не сообщает, её
  место занимает самая дальняя достигнутая позиция, поэтому после одного
  показа видно «0:01», а не «0:00». `PlaybackClock` ещё и страхует от
  файлов, которые не сообщают о конце вовсе: «играем, а позиция стоит
  секунду» = доиграли.
- Ярлыки прозрачны: показывается цель, футер с именем оригинала и «Перейти
  к оригиналу» (`RevealPath` — папка, выделение, прокрутка); битый — словами.
- `Ctrl+C` с клавиатурой в панели просмотра копирует выделенный текст
  (простой текст, код, RTF, поле GUID; WebView2 копирует сам), а не файл, и
  статус-бар говорит, что именно скопировано: панель и список — одно
  нажатие друг от друга, и «скопировано элементов: 3» над выделенным
  абзацем было бы тихим неверным ответом. Решает окно
  (`PreviewPane.TryCopySelectedText`), а не каждое поле по отдельности.
- Корень тома: метка, ФС, тип, полоса (жёлтая с 85 %, красная с 95 %),
  «занято X из Y · свободно Z»; не готовое устройство описывается, не роняет.
- Футер: пусто → текущая папка; файл → имя / размер / дата (+ EXIF);
  папка → count + size; multi → агрегат. RAW-превью по ориентации из
  контейнера (встроенный JPEG неповёрнут); галочка «Полный кадр RAW»
  (полный декод, липкая).
- Перепись папки (`FolderStatistics`, Core, поверх `IFileSystem`,
  итеративно, до конца; предел глубины 64 — не бюджет, а защита от
  junction'ов, при срабатывании «числа неполные»): файлы, папки, размер,
  топ типов с полосками. Крутилка там, где появятся числа
  (`IsCensusLoading`, отдельно от `IsLoading`), имя и заполненность диска
  сразу; числа по дороге раз в 150 мс через `IProgress<FolderProgress>`
  (процента нет — узнать нельзя, не обойдя); список типов не трогается до
  конца (отсортирован по размеру).
- Аудио. Играют MP3, FLAC, M4A / M4B, AAC, WAV, WMA, OGG, Opus (Ogg / Opus
  зависят от Web Media Extensions). Карточка: обложка, название,
  исполнитель, альбом с годом, битрейт / частота / каналы — над транспортом
  видео. Теги свои (`Wander.Core/Preview/AudioTags`, BCL, MetadataExtractor
  их не читает): ID3v2.2 / 2.3 / 2.4 (синх-безопасные размеры), ID3v1,
  Vorbis (FLAC), MP4-атомы, RIFF-INFO; WMA / Ogg теги не читаем. AAC:
  только ID3, длительность у проигрывателя (кадр ADTS проходит проверки
  MP3 и врёт). Длительность: FLAC из `STREAMINFO`, MP3 по первому кадру,
  VBR — `Xing` / `Info` / `VBRI`; сверено посекундно на 30 файлах.
  Кодировка 0 в ID3 — догадка `EncodingProbe` **по всем однобайтовым
  полям тега сразу** (одного поля мало). Обложка: `APIC` / `PICTURE`,
  иначе `Cover.jpg`, `folder.jpg`, `front.*`, одноимённая, единственная
  картинка в папке (две — не угадываем); крупный скан декодируется в размер
  карточки. Играет `MediaPlayer`, не `MediaElement` (элемент без площади
  открывает файл и не играет); транспорт один, `Kind` ставится до
  `MediaUri`. Тесты на байтах, собранных билдерами (фикстура прячет
  одинаковую ошибку в парсере и в себе).
- 3D: разбор в Core (`MeshFile`, `StlReader`, `ObjReader`, `GltfReader`),
  рисует `Viewport3D`; тянуть — вращать, колесо — зум, внизу треугольники /
  вершины. `MeshData` — общие позиции + `MeshPart` с индексами и цветом
  (`Kd` из `.mtl`, `baseColorFactor`; текстуры нет — BACKLOG; у PBR-моделей
  `Kd` почти всегда `0.8`). Нормали не читаются (WPF считает пофасеточные),
  обратная сторона — притемнённый цвет. STL: двоичный по `84 + 50 × n`
  (оба начинаются с `solid`); OBJ: индексы единичные, отрицательные от
  конца, четырёхугольники веером; glTF: обход узлов от корней с матрицами и
  памятью посещённых (битый файл — переполнение стека), буфер из `BIN` /
  `data:` / `.bin` рядом только по простому имени. Камера из радиуса
  описанной сферы и вертикального угла, плоскости отсечения от размера;
  проверено харнессом (36 случаев, занято 1–90 % кадра).

## Галерея и оценки

- Четвёртый вид, `Ctrl+Shift+1` («Огромные значки» Проводника): те же
  `TileMetrics` и панель; подпись в одну строку; оценка значком в углу
  (бейдж строится только у оценённых); фон светлый / серый / тёмный тремя
  квадратиками над списком (по умолчанию светлый), яркость серого и тёмного
  — настройки; палитра (`GalleryPalette`) считается из фона одним типом —
  на тёмном подсветка это подъём фона, на светлом проводниковые цвета.
  Фон панели просмотра следует под картинкой. Шаг `Ctrl` + колесо 16 px.
- Автовключение: больше половины **содержательных** файлов — изображения
  (спутники, `.bak` / `.tmp` / `.crdownload` / `~`, подпапки не в
  знаменателе; минимума нет), порог — настройка; ручной выбор запоминается
  на папку (`state.json`, 128 записей, вытесняются старые); выход
  возвращает последний ручной вид; всё выключается галочкой.
  `Wander.Core/Listing/ImageFolderProbe`, расширения —
  `Wander.Core/Icons/ImageFormats` (общие с панелью просмотра).
- Фильтр по оценкам и меткам — полоса над списком только в папках с
  оценёнными файлами, во всех видах (спрятанный фильтр — «почему папка
  пустая»); набор, не порог: щелчок — эта и выше, `Ctrl` + щелчок —
  добавить / убрать одну; перечёркнутая звезда — без оценки; «Сбросить
  фильтр»; `Alt` ничего не делает; снимается при уходе
  (`SearchController.Reset`). Папки не фильтруются. Стоит ноль I/O.
- Столбец «Оценка» в таблице — по тому же правилу, метка точкой, звёзды
  текстом; сортируется; порядок приезжает следующим листингом.
- Оценка не пересобирает папку: `SearchController.Replace` подменяет
  строку, `Entries[i]` заменяется, выделение без прокрутки и переноса
  фокуса; панель просмотра сравнивает путь + размер + mtime, перечитывает
  только спутники, а не 30-МБ RAW. `Ctrl+Z` — `MetadataTargets`.
- `0`–`5` в галерее ставят оценку всему выделенному (только в галерее —
  в остальных видах цифры принадлежат type-ahead); пачка — один шаг отмены
  и один диалог на создание сайдкаров.
- Чтение оценок по папке — вторым проходом (`RatingsController.StartPass` →
  `RatedListing.WithRatings`, пул, отмена по уходу), только строки со
  спутником; без оценок возвращается тот же список по ссылке, UI-проход
  не выполняется.
- Создание сайдкара, когда его не было (единственное место, где Wander
  создаёт файл, которого не называли): звёзды приглушены, первый щелчок
  предлагает создать — спрашивает (Cancel по умолчанию; вопрос снимается в
  «Галерее», для прогона по папке RAW), логирует, undo удаляет файл
  целиком, `SystemPathGuard`, один раз на пачку, отказывается,
  если файл есть (правка идёт своим путём и сохраняет чужой рецепт), снятие
  оценки ничего не создаёт. По умолчанию `.xmp`: `.pp3` с одной строкой
  меняет проявку в RawTherapee (профиль по умолчанию перестаёт
  применяться), `.xmp` — нет (RawTherapee читает с 5.7, синхронизирует с
  5.11); переключатель на `.pp3` с предупреждением. `.xmp` несёт
  `xmp:Rating` и `xmp:Label` (пустой), чтобы правки шли заменой на месте.
- Спутники (`Wander.Core/Companions/`, `CompanionResolver`): `.meta`,
  `.pp3`, `.xmp` одной строкой с основным, едут и удаляются вместе; футер
  панели — блок «Integrated:».

## Поиск

- Быстрый фильтр (`Ctrl+F`, поле над списком): сужает на каждую букву;
  маски (`*.cs;IMG_?.jpg`; без `*?` — подстрока), `NameFilter` общий с
  окном. Через 400 мс и от 2 символов (`MinAutoRunLength`) под ним
  запускается проход по подпапкам (`SearchScope.Subfolders`,
  `ContentSearchController.IsFilterPass`): вложенное ложится под найденным
  здесь (`HereFirst`), засевается тем, что фильтр уже показал, повторы
  отсеиваются; следующая буква отменяет обход. `Esc` — остановить,
  сбросить, в список. Двоеточие — `маска:текст` (`SearchExpression`; всё
  после первого двоеточия — текст); флаги отмечает подсвеченный `⋮`. Окно
  этим путём не ходит (`_fromFilterBox`).
- Окно (`Ctrl+Shift+F` / `⋮`): имя, текст, папка (следует за навигацией),
  флаги «в подпапках», «двоичные». Имя **и** текст; маска — ворота (файл,
  отвергнутый маской, не открывается: 17 файлов / 43 мс против 5074 / 217).
  Автозапуск через 400 мс без порога длины, флаг — сразу, `Enter` — сразу.
  Owner главного, не Topmost; `Esc` закрывает и возвращает клавиатуру в
  список; поле в тулбаре на это время скрыто. Индикатор без затемнения,
  счёт в строке состояния.
- Навигация сбрасывает поиск целиком (забытая галка превращала фильтр в
  обход диска); область и галка бинарей не переживают сессию, тексты
  запросов — тоже.
- Кодировки — `EncodingProbe`, регистр не важен. Экстракторы по очереди:
  `ZipDocumentExtractor` (Core: `.docx` `.xlsx` `.pptx` `.epub` `.odt`
  `.ods` `.odp` — zip + `XmlReader`), `FilterTextExtractor` (Platform,
  системный `IFilter`: `.doc` `.rtf` `.pdf` `.chm` `.msg` `.mht`; `.doc` —
  `OffFilt.dll` из Windows, `.pdf` — только с установленным обработчиком),
  `PlainTextExtractor` (`TextProbe` 8 КБ + `EncodingProbe`). Специфичный
  взялся и не смог — файл в счётчик «не удалось прочитать» (не проваливается
  в текст: иначе `%PDF-1.4` находился как слово). Двоичные — по галке,
  только ASCII, кириллица честно не находит. `ExtractedTextCache` — LRU
  32 МБ в памяти, ключ путь + размер + mtime, дорогие форматы (25 мс против
  129). Индекса нет (REJECTED).
- Результаты заменяют список: столбцы «Папка» и «Совпадение», в плитках
  путь вместо типа; сортировка на месте; `F5` повторяет поиск; операция
  убирает строку (`PruneMissingAsync` на пуле), остановка оставляет
  найденное. Пределы: 32 МБ на файл, глубина 64 + посещённые, 5000
  результатов. Хвосты — BACKLOG «Поиск: что доделать».

## Настройки и справка

- Язык — русский; все строки в `Strings.resx` через `Resources/Strings.cs`
  (аксессор разложен по областям partial-классами); второй язык —
  `Strings.<culture>.resx`.
- «Клавиатура» в настройках — те же пять таблиц, что в GUIDE
  (`HotkeyCatalog`, `SharedSizeGroup` на всю страницу — колонка жестов одна
  на пять групп); читает, не редактирует; жесты литералами, описания из
  ресурсов; мышиных жестов нет. Поиск (`HotkeyCatalog.Filter`) ищет и по
  жесту, и по описанию; пробелы в жесте при сравнении снимаются, поэтому
  «ctrl+q» находит «Ctrl + Q».
- Кэш миниатюр: три уровня — `IconImageCache` (256 декодированных
  `BitmapImage`; декод был последней частью показа на UI-потоке), память
  `SystemIconProvider` (512), диск `%LocalAppData%\Wander\thumbs` (256 МБ,
  PNG, ключ хэш поколения + пути + mtime + размера, запись через временный
  файл, подрезка по времени обращения в фоне; поколение бампается, когда
  Wander начинает рисовать миниатюру иначе, — иначе кэш продолжал бы
  отдавать старую картинку). Пределы и очистка — «Миниатюры».
- «Быстрое чтение первых файлов при открытии папки» (`VisibleFirstLoading`,
  выключена): `IconLoadGate` с двумя очередями — значок в окне
  `ScrollViewer` обгоняет значок за краем; запрос откладывается до
  `Loaded`. В плитках эффекта почти нет, в таблице и большом дереве — есть.

## Диагностика

- `Wander.Core/Diagnostics/PerfLog` — секундные окна, в лог только > 100 мс
  суммарно или > 33 мс за вызов. `UiStallWatch` — фоновый поток меряет
  неответ UI (> 150 мс → `ui.stall`). `PerfCounters`: `COUNT layout.new /
  reused / kept / discard`, `LAYOUT <вид> container: N visuals` — всегда
  включены, регресс шаблона виден по журналу. `FirstScreenWatch`: `First
  screen painted in N ms: K icons, M awaited` / `abandoned`. `Folder listed
  in N ms` при > 300 мс. Точки — PERFORMANCE.md.
- Журнал действий (`Wander.Core/Logging/ActionJournal`) — что за сеанс
  происходило, словами статус-бара, с датой и временем; кнопка со списком
  (глиф MDL2 `F0E3`) слева в самом статус-баре открывает его текстом
  (`journal-<pid>.txt` рядом с логом сеанса, системный просмотрщик).
  Пишутся открытые папки (`Открыта папка: …`, только на приход — `F5` и
  перечитывание после операции ту же папку не повторяют) и операции;
  **не** пишется то, чем статус-бар описывает сам список («элементов: 27»
  переписывается на каждую букву фильтра) — такие сообщения идут через
  `SetStatusQuietly`. Повторы подряд и пустые строки не пишутся, предел
  500 строк. Это не лог сеанса: тот про диагностику и написан словами
  кода, а этот — то, что видел пользователь, его словами.
- `Wander.exe --smoke` — окно за экраном (`Left = -32000`), без фокуса и
  панели задач, закрывается само, код возврата; `CrashReporter` выключен.
  `check.bat run` проверяет код (сломанный ключ ресурса в XAML роняет шаг).
- `tools\check-strings.ps1` — ключи в обе стороны, шаг `check.bat`.
- Данные приложения — один корень `AppPaths` (`--data-dir`, `--portable`,
  `WANDER_DATA_DIR`, иначе `%LOCALAPPDATA%\Wander`); все модальные вопросы
  — через `IDialogs` (2026-09-02).
- QA-харнесс `tests/Wander.Harness` (2026-09-02): настоящее окно за
  экраном на сгенерированной песочнице, JSON-сценарии, скриншоты, метрики
  процесса и GC, диалоги по политике, отчёт; `selfcheck` сверяет
  генераторы и фикстуры с читателями (теги mp3 / flac / m4a, настоящие
  docx / epub). Механика — ARCHITECTURE, использование — QA.md.
  - Десять профилей песочницы: `photos`, `raw`, `big`, `deep`, `names`,
    `docs` (пять zip-документов, fb2, md, rtf, pdf, html, четыре
    кодировки), `code` (подсветка, Unity `.asset` в двух видах, `.bat` в
    866), `media` (wav с тегами, куб в stl / obj / gltf, остальное — из
    `tests/Fixtures/` по расширению), `attrs` (флаги, read-only,
    `desktop.ini`, `icacls /deny`), `links` (три `.lnk`). `state.json`
    прошлой версии — поле сценария, не профиль.
  - Девять сценариев: `smoke-walk`, `focus-keys`, `tree-bookmarks`,
    `file-ops`, `search`, `preview-formats` (26 скриншотов при нынешнем
    наборе фикстур), `watcher`, `soak` (плато памяти и хэндлов),
    `state-upgrade` (старт на `state.json` чужой сборки). Шаги сверх
    базовых: `tree-expand`, `bookmark`, `search`, `soak`, `fs lock|unlock`,
    `assert-log allow[]`, `preview-format` (формат из фикстур: нет файла —
    строка в отчёте, а не падение), `assert-entries scope: visible` (маска
    имени фильтрует вид, а не `Entries`).
  - `check.bat qa` — сборка, `selfcheck`, `smoke-walk`; в обычный
    `check.bat` не входит (минуты).
- `SYS`-строка в логе (`App/Diagnostics/SystemVitals`, 2026-09-02): раз в
  5 с и на каждый `ui.stall` — рабочий набор, private, счётчики GC,
  прирост аллокаций, LOH, хэндлы, потоки, CPU. Одна строка не значит
  ничего, форма за сессию — всё; `soak` смотрит на неё. В отчёте харнесса
  секция `SYS` (последние пять).
- Иконки не пропадают: `SHGetFileInfo` сериализован, негативный кэш только
  у миниатюр, `AsyncIcon` переспрашивает через секунду; провал —
  `[icon-diag]`.

## Отзывчивость

- Листинг приземляется ниже ввода (`Background`), миниатюры — `ContextIdle`;
  ушедший контейнер отзывает загрузку у шлюза (поколение по `Unloaded`).
  Сторож и `state.json` не трогают UI-поток (ретаргет на пуле, запись по
  дебаунсу 500 мс с флашем при закрытии). `F5` по веткам, старт
  (`OpenStartFolderAsync`), чистка результатов, открытие файла для текста,
  размер кэша в настройках — на пуле, на UI только ответ (O10).
- Плитка стоит копейки (R, 2026-09-02): шаблон 6–9 визуалов вместо 18–23
  (один `TextBox` на список, `ControlTemplate` по property-триггерам,
  размеры ресурсами и наследованием, ни одной `RelativeSource`, бейдж
  лениво); вид, которого не видно, не строит ничего
  (`VirtualizingWrapPanel.MeasureOverride` при `IsVisible == false` только
  перемеряет; таблице отвязывают `ItemsSource`, выделение переносится). Было
  500–750 мс `ui.stall` на навигацию и три реализации на папку; стало 78
  навигаций без `ui.stall`, до 6 навигаций/с. Отладочные переключатели
  (вуаль, синхронная очистка, лёгкие плитки, отцепка, без миниатюр, без
  оценок, таблица без кэша) показали: цена — шаблон и скрытые виды, вуаль
  не нужна; сняты вместе с меню, счётчики остались. Что шаблону нельзя —
  ARCHITECTURE.
- Закрытие: окно `Hide()` до освобождения COM (~1,4 с доумирает невидимо).
