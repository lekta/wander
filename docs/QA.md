# Wander — QA

Как проверяется продукт: уровни проверки, песочница данных, матрица
«трогал → проверь», чек-листы, предрелизный прогон, метрики, план
автоматизации и роль Claude в нём. Тесты живут только на Core; всё выше
(вьюмодели, XAML, фокус, DnD, COM) покрыто компилятором, smoke и этим
документом.

## Уровни проверки

| # | Уровень | Ловит | Не ловит | Есть |
|---|---|---|---|---|
| 1 | Тесты Core (xUnit, фейки) | логику, машины решений, гонки в контроллерах | UI, COM, диск | да, `check.bat` |
| 2 | Сборка, `format`, `check-strings`, `deps.ps1` | компилируемость, ключи ресурсов, циклы папок | всё поведение | да |
| 3 | Smoke (`--smoke`) | XAML, ресурсы, регистрация, первый кадр и листинг | жесты, содержимое | да, `check.bat run` |
| 4 | Консольный харнесс на класс | конвертеры, `TreeNodeViewModel`, контроллеры, замер одной операции | окно | **нет в репо** (жили в scratchpad) |
| 5 | Оконный харнесс за экраном | фокус, выделение, rename, раскладка, приземления, скриншоты, трассировка биндингов, PerfLog / GC / память — на песочнице | обмен с системой, настоящий ввод ОС | **нет в репо**, главный кандидат |
| 6 | UIA (FlaUI) на релизном exe | настоящий ввод, поставленный бинарник, DnD с Проводником | ничего сверх 5 по коду; хрупкие селекторы | нет; только Sandbox / VM |
| 7 | Человек по чек-листу | «прыгает или нет», обмен с системой, внешний вид | масштаб | чек-листы ниже |
| 8 | Claude через 5 / 6 | сценарии, оценка скриншотов и логов, разведочные прогоны | то же, что 5 / 6 | план ниже |

Правило: проверка, которую можно сделать тестом Core или харнессом, уходит
из чек-листов в код.

## Песочница данных

Живые прогоны идут по сгенерированному дереву, не по файлам машины.

**Изоляция.** Пути `%LOCALAPPDATA%\Wander\{state.json, logs, thumbs,
crashes, WebView2}` зашиты в пяти местах (`FileLogger`, `JsonAppStateStore`,
`PlatformBootstrapper`, `CrashReporter`, `PreviewPane`); `LOCALAPPDATA` из
среды `Environment.GetFolderPath` не читает. Нужен один корень —
`--data-dir <путь>` / `WANDER_DATA_DIR` — и через него все пять. В харнессе
дополнительно подменяется `IAppStateStore` (уже практиковалось). Единственное
касание системы — корзина: удалённые файлы песочницы попадают в настоящую;
сценарий восстанавливает или удаляет их сам.

**Генератор** (`tools\make-sandbox.ps1` или команда харнесса `sandbox
<dir>`), дерево в `%TEMP%\wander-sandbox\<профиль>`; при необходимости —
на VHDX (`Mount-DiskImage` даёт съёмный том, извлечение — сценарий
«отвалившийся диск») или на SMB-loopback (`\\localhost\share` — сетевой
путь, UNC-корень, таймауты).

| Профиль | Что внутри | Что проверяет |
|---|---|---|

| `docs` | docx / xlsx / pptx / epub / odt (zip + XML генерируются), fb2, md с таблицей, rtf, минимальный pdf, html с внешней картинкой и `fetch()`, txt в UTF-8 / 1251 / 866 / UTF-16 | поиск по содержимому, экстракторы, панель, изоляция WebView2 |

VHDX — размонтировать.

## Чек-листы ручного прогона

Брать разделы, которых коснулся диф; «Всегда» — обязательный. Что не удалось
проверить — в отчёт (FINALIZING, п. 3).

### Всегда

- [ ] `.\tools\check.bat run` — зелёная целиком.
- [ ] Приложение открывается на той же папке, тем же размером, на том же
      мониторе.
- [ ] В логах сессии нет `ERROR` и лишних `WARN`.
- [ ] Ни одна подпись не выглядит как ключ ресурса.

### Скорость и отзывчивость

Три починки фризов 2026-09-01 ломали друг друга — прогонять после **любой**
правки навигации, иконок, приоритетов.

- [ ] **Навигация мгновенная**: вход, выход, первый вход, съёмный / спящий
      диск — адресная строка и дерево отвечают сразу, содержимое следом.
- [ ] **Пока сыплются миниатюры — окно живое**: холодная папка с сотнями
      RAW, сразу клики по строкам, дереву, колесо.
- [ ] **Первый экран в журнале**: `First screen painted in N ms: K icons,
      M awaited` на каждый вход, `abandoned` при уходе раньше. С «Быстрым
      чтением первых файлов» в Таблице на холодном кэше `N` не хуже, чем
      без. Зажатая стрелка в дереве не оставляет `abandoned` с остатком на
      **каждой** папке.
- [ ] **Зажатая стрелка в дереве** («стрелки открывают папку»): курсор без
      лага, листится папка остановки, промежуточные не листаются и не
      засоряют историю; одиночное нажатие открывает сразу.
- [ ] **Клавиатура по списку** не тормозит, пока генерируются миниатюры.
- [ ] **Клик по папке из папки с миниатюрами**: адрес и подсветка дерева в
      тот же кадр, список следом; `nav.refresh` в логе не появляется (порог
      33 мс). `Backspace` выделяет папку, из которой вышли, — и в быстрой
      локальной (один своп), и в медленной (очистка, спиннер).
- [ ] **Проход подряд по папкам с фотографиями** (стрелки, `Backspace` /
      `Enter`, закладки): показана выбранная сейчас папка, не предыдущая;
      миниатюры новой начинаются сразу.
- [ ] **`F5` с развёрнутыми ветками на медленном диске**: окно отвечает,
      ветки обновляются по мере ответа, развёрнутое и выделенное на месте.
- [ ] **Запуск после сессии на отключённом диске**: окно сразу, первый диск;
      с диском на месте — запомненная папка.
- [ ] **Удаление из результатов поиска** убирает строку (после операции и по
      тику сторожа), остальные не прыгают.
- [ ] **Смена вида** Плитки → Значки → Галерея → Таблица и обратно: одна
      заминка в момент переключения — норма; на навигации заминки нет.
      Строки на месте, выделение целиком, фокус в списке.
- [ ] Нет многосекундных `ui.stall` (сотни мс на холодной папке — норма).

### Фокус, выделение и клавиатура

- [ ] После **удаления** выделение на соседней строке, стрелка идёт от неё.
- [ ] После **переименования** строка выделена, список не прокручен,
      клавиатура на строке.
- [ ] **`F2` во всех четырёх видах**: редактор на месте подписи, имя без
      расширения выделено, `Enter` / `Esc` / клик мимо; прокрутка во время
      правки — редактор едет со строкой и режется краем; строка ушла из
      виртуализации — коммит по потере фокуса. В галерее цифры при открытом
      редакторе набираются в имя.
- [ ] После **`Ctrl+Z`** выделение на том, что вернулось.
- [ ] **`Alt+←` и `Backspace`** выделяют папку, из которой вышли; стрелка
      идёт от неё. И с «стрелки в дереве открывают папку».
- [ ] **Повторный вход в папку** — на строке прошлого раза.
- [ ] **Создание папки** (`Ctrl+Shift+N`, меню пустого места): создана,
      выделена, редактор открыт, имя выделено, `Enter` / `Esc`.
- [ ] **Клик по звезде** не пересобирает список: выделение, прокрутка,
      фокус, строка под курсором на месте.
- [ ] `Tab` / `Ctrl+1..4` по областям в обе стороны; свёрнутые закладки и
      выключенные кнопки пропускаются.
- [ ] **`Ctrl+1` переключает панели**, `Ctrl+Shift+E` ведёт в ту, из
      которой открыли; из адресной строки — где клавиатура была последней;
      без закладок — дерево.
- [ ] **Стрелки на краю сетки**: `→` в конце ряда — начало следующего, `↑`
      на верхнем — первый, `↓` в короткий последний — его последний; на
      первом и последнем каретка стоит. С `Shift` выделение растёт от якоря.
- [ ] Type-ahead прыгает на строку, не проваливается в другие обработчики.
- [ ] **Клавиша меню** (Apps) и `Shift+F10` открывают меню, и оно остаётся
      открытым.

## Предрелизный прогон

Дополняет RELEASING.md; порядок — от дешёвого к дорогому, регрессия на
любом шаге останавливает релиз.

1. **База**: `check.bat run`, `deps.ps1` без циклов, `metrics.ps1` снимок,
   доки сверены (FINALIZING, п. 5).
2. **Релизная сборка**: `publish.ps1`, размер и SHA, `size-report.ps1`
   против PERFORMANCE (категории не выросли без причины).
3. **Первый запуск и обновление**: чистая машина (Sandbox) — SmartScreen,
   без `state.json`, умолчания, первая папка; поверх прошлой версии —
   `state.json` и кэш.
4. **Функциональный прогон** на песочнице релизным exe: «Всегда» + все
   разделы чек-листов; автоматизированная часть — харнессом (когда будет),
   остальное руками.
5. **Окружения** — раздел выше, хотя бы DPI и один «странный» том.
6. **Замеры** — таблица ниже, все строки; плюс 30-минутный soak: случайная
   навигация по песочнице — память выходит на плато, handles стабильны, лог
   без `ERROR`, CPU в простое ~0 %.
7. **Итог**: числа в PERFORMANCE (дата, версия), находки разложены по
   спискам, exit-критерии: 0 открытых P0 / P1, `WARN` / `ERROR` в сессиях
   релизного прогона — ноль, метрики в порогах.

| Метрика | Как снять | Порог / базлайн |
|---|---|---|
| Первый кадр | `Startup: first frame N ms`, три запуска релизного exe | ~1650–2050 мс (PERFORMANCE) |
| Неответ UI | `PERF ui.stall` | одиночные < 400 мс, частые < 100; на холодной папке — сотни, не секунды |
| Первый экран | `First screen painted in N ms` по профилю `photos` холодно / тепло | базлайн снять |
| Шаблон плитки | `LAYOUT <вид> container: N visuals` | Tiles 8, Icons 6, Gallery 9 (без оценки) |
| Реализации на навигацию | `COUNT layout.new: N in K passes` | K = 1 |
| Раскладка в простое | харнесс: проходы за 5 с без ввода | 0 |
| Миниатюры RAW | `bg.thumb-shell` / `RawThumbnail`, мс на файл | ~3 мс WinRT, 75 через оболочку — регресс |
| Память | `SYS` (предложение ниже) или харнесс: `WorkingSet64`, `PrivateMemorySize64` — пик и плато после 200 навигаций | smoke 344 / 225 МБ; плато — снять |
| GC | `GC.CollectionCount(0/1/2)`, `GetTotalAllocatedBytes` за окно, `GetGCMemoryInfo` (LOH, % в GC) | gen2 не растёт линейно с навигациями; аллокации на навигацию — снять |
| Handles, потоки | `Process.HandleCount`, `Threads.Count` в soak | стабильны после разогрева |
| CPU | `TotalProcessorTime` дельта: в простое 10 с | ~0 %; таймеры останавливают себя |
| Диск | размер `thumbs` до / после, `bg.thumb-disk-write` | в пределах лимита, подрезка срабатывает |
| Закрытие | `OnClosing` → смерть процесса | окно исчезает сразу; процесс < 2 с |
| Лог | размер файла сессии, повторяющиеся строки | нет заливки одинаковыми исключениями |
| Поиск | время по `big` (5000 файлов) и `docs` с кэшем / без | 0,2 с обход репозитория; кэш ×5 |

**Предложение — строка `SYS` в логе**: тот же heartbeat `UiStallWatch`
раз в 5 с (и на каждый `ui.stall`) пишет `SYS ws=… private=… gen=0/1/2
alloc=+N MB loh=… handles=… threads=… cpu=…%`. Цена — несколько вызовов
`Process` / `GC`, ничего не аллоцирует заметно. Даёт замеры и в живых
сессиях, не только в харнессе; Core не трогается. Глубже — `dotnet-counters`,
`dotnet-trace` / PerfView, dotTrace из Rider: по требованию, не в прогон.

## Автоматизация — план (предложение, не сделано)

Что можно гонять без человека: навигация по песочнице во всех видах,
просмотр каждой ветки панели, клавиатурные сценарии, файловые операции с
undo, поиск, смена настроек — со скриншотами и логами на каждом шаге.
Нельзя: реальный Explorer, реальная мышь на рабочем столе, «прыгает или нет»
на глаз (частично — счётчики раскладки и сравнение скриншотов).

Варианты, оценка:

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **A. Оконный харнесс в репо** (`tests/Wander.Harness`, консоль, STA, ссылка на `Wander.App`; настоящие `MainViewModel` и окно за экраном, жесты на UI-поток, `RenderTargetBitmap` для скриншотов, подменённый `IAppStateStore`) | те же кодовые пути, что у пользователя; скриншоты и трассировка биндингов; ~70 % ручных чек-листов; Claude работает через API харнесса, не трогая экран | не релизный бинарник (Debug / Release-сборка тех же проектов); ввод синтезированный; диалогам нужен шов | **делать первым** |
| B. UIA (FlaUI) на релизном exe | настоящий ввод и поставленный бинарник; DnD с Проводником внутри Sandbox | захват ввода — только Windows Sandbox / VM / вторая RDP-сессия; хрупкие селекторы; медленно | вторым, для предрелизного прогона релизного exe |
| C. `--scenario` внутри продукта | релизный бинарник без UIA | тестовый код в поставке; шов диалогов всё равно нужен | не сейчас; формат сценария из A переиспользовать, если понадобится |
| D. VHDX / SMB-loopback как дополнение к A / B | съёмный и сетевой том честно | скрипты монтирования | да, дёшево |
| E. Фейковая `IFileSystem` на всё приложение | без диска вовсе | восемь файлов App и `Preview/` читают `System.IO`, миниатюры — шелл; нереалистично | нет |

**Шаги A**, каждый — отдельный коммит:

1. `--data-dir` / `WANDER_DATA_DIR` — один корень для пяти путей.
2. Шов диалогов: подтверждения, конфликты, `PromptDialog` — через один
   интерфейс App-уровня, который харнесс подменяет автоответом (сейчас —
   голые `MessageBox.Show` в `MainViewModel` и `SettingsWindow`).
3. Генератор песочницы (профили выше) + `tests/Fixtures/` для того, что не
   синтезируется.
4. Проект харнесса: команды `sandbox`, `run <сценарий>`, `soak <минуты>`;
   сценарий — список шагов (`navigate`, `select`, `key`, `view`, `preview`,
   `wait-idle`, `screenshot`, `assert-log`, `measure`), артефакты в
   `artifacts/<run>/` (лог, PNG, `metrics.json`, отчёт).
5. `SYS`-метрики в логе.
6. `check.bat qa` — медленный режим, не в каждом прогоне.
7. UIA-набор для Sandbox — когда A стабилен.

**Кто что делает** (по правилу чистки #4: Фабле — решения и риск, Опус —
механика):

| Роль | Кто |
|---|---|
| Спроектировать сценарии под правку, разобрать падение, оценить скриншоты на UX-регрессию, разведочный «ручной» прогон через харнесс шаг за шагом | Fable 5.1 (Opus 5 при экономии) |
| Прогнать набор, сверить лог и метрики с порогами, собрать отчёт, разложить находки по спискам | Sonnet 5 или Opus 5 |
| Всё с настоящим Проводником, мышью и глазом; экзотические тома; решение «релиз / не релиз» | человек |

Claude никогда не ведёт настоящий рабочий стол: харнесс — только окно за
экраном; UIA — только внутри Sandbox / VM, где чужого экрана нет.

## Что ещё берут из практики QA

- **Находка = шаги, ожидание, факт, строка версии (`v… R, коммит, дата`),
  лог сессии, скриншот.** Severity: P0 потеря данных / падение, P1 не
  работает фича, P2 неудобно, P3 косметика.
- **Теги набора**: smoke (минуты) / regression (час) / release (день);
  флаки считаются и чинятся, не «перезапустил».
- **Базлайны по релизам** — таблица в PERFORMANCE «версия → числа»; тренд
  важнее одного числа.
- **Сценарии потери данных**: kill на середине копии, диск заполнен (VHDX
  50 МБ), `state.json` при внезапном закрытии, два экземпляра Wander на
  одном кэше.
- **Первый запуск / обновление / удаление** (портативный: удалить папку
  данных) — отдельный проход, не «и так работает».
- **Доступность-минимум**: клавиатурой всё, DPI, контраст; Narrator и
  `AutomationProperties` — когда дойдут руки.
- **Безопасность превью**: html с JS и внешними ресурсами, имена с `..`,
  циклы junction, будущие архивы — zip-бомба и `../` в записях.
