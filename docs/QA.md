# Wander — QA

Как проверяется продукт: уровни проверки, песочница данных, матрица
«трогал → проверь», чек-листы, предрелизный прогон, метрики, харнесс и
роль Claude в нём. Тесты живут только на Core; всё выше (вьюмодели, XAML,
фокус, DnD, COM) покрыто компилятором, smoke и этим документом.

## Уровни проверки

| # | Уровень | Ловит | Не ловит | Есть |
|---|---|---|---|---|
| 1 | Тесты Core (xUnit, фейки) | логику, машины решений, гонки в контроллерах | UI, COM, диск | да, `check.bat` |
| 2 | Сборка, `format`, `check-strings`, `deps.ps1` | компилируемость, ключи ресурсов, циклы папок | всё поведение | да |
| 3 | Smoke (`--smoke`) | XAML, ресурсы, регистрация, первый кадр и листинг | жесты, содержимое | да, `check.bat run` |
| 4 | Консольный харнесс на класс | конвертеры, `TreeNodeViewModel`, контроллеры, замер одной операции | окно | частично: `Wander.Harness selfcheck` (генераторы и фикстуры против читателей: RAW, EXIF, zip-документы, кодировки, теги WAV / mp3 / flac / m4a, меши); разовые — в scratchpad |
| 5 | Оконный харнесс за экраном | фокус, выделение, rename, раскладка, приземления, скриншоты, PerfLog / GC / память — на песочнице | обмен с системой, настоящий ввод ОС | **есть**: `tests/Wander.Harness`, ниже |
| 6 | UIA (FlaUI) на релизном exe | настоящий ввод, поставленный бинарник, DnD с Проводником | ничего сверх 5 по коду; хрупкие селекторы | нет; только Sandbox / VM |
| 7 | Человек по чек-листу | «прыгает или нет», обмен с системой, внешний вид | масштаб | чек-листы ниже |
| 8 | Claude через 5 / 6 | сценарии, оценка скриншотов и логов, разведочные прогоны | то же, что 5 / 6 | «Автоматизация» ниже |

Правило: проверка, которую можно сделать тестом Core или харнессом, уходит
из чек-листов в код.

**Smoke** (уровень 3). `Wander.exe --smoke` = `App.Headless` («Окно не
должно оказаться на экране» ниже) + `StartSmokeCountdown`: две секунды на
листинг, значки, наблюдателей, затем `Shutdown(0)`. `check.bat run` зовёт
exe напрямую (не `start`) с `--folder` на `tests\Fixtures` и читает код;
ловушки cmd: `if errorlevel 1` не видит .NET-падения (0xE0434352 —
отрицательное), нужно `neq 0`; `exit /b` внутри скобок код не доносит.

**Что можно проверить без окна вообще** (уровень 4). WPF рисует в
`RenderTargetBitmap` из консольного приложения — `Measure` / `Arrange` /
`UpdateLayout` руками, PNG на диск: какой глиф `Segoe MDL2 Assets` за
кодом, перебивает ли триггер шаблона значение из `DynamicResource`.
`VirtualizingWrapPanel` вне окна не строит ничего (владелец
`IsVisible: false`, ARCHITECTURE, «Вид, которого не видно»), но достижима:
`HwndSource` за экраном (`PositionX/Y = -32000`,
`WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, как `--smoke`), `RootVisual` из
XAML, скопированного из `FileListView.xaml` с литералами вместо биндингов
к вьюмодели, и `RenderTargetBitmap`. Так найдено «имя выделенной ячейки не
разворачивается»: `DesiredSize` контейнера 159 px до `InvalidateMeasure` и
173,84 после — панель не перемерялась. **Упрощённый** стенд эту разницу
скрыл, настоящий XAML показал. Композицию окна `RenderTargetBitmap` не
снимает (рисует по порядку визуального дерева) — её отдаёт
`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` в DIB-секцию, и для окна за
экраном: так проверен `Panel.ZIndex` из `ArrangeOverride` (порядок детей —
`VisualTreeHelper.GetChild`, перекрытие — по цветам пикселей).

Медиа — тоже без окна: `MediaPlayer` (не `MediaElement`) играет файл в
консольном приложении, `Volume = 0` — рядом человек. Так измерено, что
`burn-in-hell-elmo.mp4` не сообщает длительность и оживает только от
`Close()` + `Open()`, а файл с длительностью после конца берёт и
`Position = 0; Play()`, и `Stop(); Play()` — отсюда две дороги
`RestartMedia`. Длинный файл перематывается к концу
(`Position = Duration - 1.5 s`) до `Play()`.

## Где это крутится

Всё локально, на этой машине: сервера с тестами нет, Claude запускает те
же команды, что человек (`dotnet build`, `check.bat`, `Wander.Harness.exe`),
и видит их вывод. Прогон длится столько же, сколько руками; окно харнесса —
настоящее окно этой Windows за краем экрана; всё, что прогон пишет,
ложится на этот диск.

| | Откуда | Куда |
|---|---|---|
| Данные, по которым ходят | генерируются в `%TEMP%\wander-sandbox\<имя>` (фото, RAW, документы, 5000 файлов) | там и живут между прогонами; `--rebuild` пересобирает |
| Чего генератор не умеет | `tests/Fixtures/` в репозитории | копируется в песочницу по расширению |
| Состояние чужой сборки | `tests/Fixtures/state/<версия>.json` | data-dir прогона, до старта приложения |
| Результат прогона | — | `artifacts\<сценарий>-<время>\`: `report.md`, `screenshots\`, `metrics.json`, `data\` с логом и `state.json` этого прогона |
| Журнал батчей | — | `artifacts\test-runs.tsv`: строка на каждый батч, дописывается |

`artifacts\` в `.gitignore` — мусор прогонов, не история; нужное из него
переезжает в доки словами и числами.

**Журнал батчей.** Каждый батч автотестов дописывает строку в
`artifacts\test-runs.tsv`: когда, имя батча, сколько прошло, сколько всего,
секунды, `ok` / `fail` / `crash`. Пишут трое одним форматом:
`tools\run-tests.ps1` (тесты Core из `check.bat`, по итоговой строке
VSTest), `selfcheck` (проверок напечатано / из них не `FAIL`) и каждый
сценарий (`RunJournal`: шагов `ok` из шагов сценария, время от старта
приложения до отчёта). `smoke` строку не пишет: один запуск — не батч.
Файл вне гита, на этой машине; что с ним дальше — WORKFLOW, «Открытые
вопросы».

## Песочница данных

Живые прогоны идут по сгенерированному дереву, не по файлам машины.

**Изоляция.** Всё, что приложение пишет для себя (`state.json`, `logs`,
`thumbs`, `crashes`, `WebView2`), идёт через один корень
`AppPaths.DataRoot`: `--data-dir <путь>`, `--portable` (папка `data` рядом с
exe), переменная `WANDER_DATA_DIR`, иначе `%LOCALAPPDATA%\Wander`. Харнесс
ставит переменную на `artifacts\<run>\data` — настоящий `state.json` и
кэши машины не трогаются (в логе строка `Data root: … (env)`). Единственное
касание системы — корзина: удалённые файлы песочницы попадают в настоящую,
сценарий возвращает их `undo`.

**Папка старта — тоже своя** (`StartFolder`): сеанс без `state.json`
начинается в рабочей папке, а это «Документы» человека, поэтому тестовый
запуск называет папку сам — `check.bat run` ключом `--folder`
(`tests\Fixtures`), харнесс — корнем песочницы прогона
(`StartFolder.Override`), и со `state` из фикстур тоже. Запуск exe руками —
с `--data-dir` под `artifacts\` и с `--folder`.

**Генератор** — `Wander.Harness sandbox <dir> [--profiles …] [--photos N]
[--big N] [--raw N] [--raw-mb N]`; `run` строит песочницу сам в
`%TEMP%\wander-sandbox\<имя>`, если её нет (`--rebuild` пересобирает).
Позже — VHDX (`Mount-DiskImage`: съёмный том, извлечение) и SMB-loopback
(`\\localhost\share`: UNC, таймауты).

| Профиль | Что внутри | Что проверяет |
|---|---|---|
| `photos` | JPEG 1620×1080 с EXIF-ориентацией 1 / 6 / 8 / 3 по кругу; стрелка и подпись нарисованы так, что после поворота смотрят вверх — сбой ориентации виден на скриншоте; `.xmp` у каждого третьего, `.pp3` у каждого пятого; `sub\` с 10 снимками; `notes.txt` | галерея, автовыбор, фильтр, оценки, миниатюры, `ListingDiff` |

| `links` | `to-file.lnk`, `to-folder.lnk`, `broken.lnk` — через настоящий `ShellShortcutService` | прозрачность ярлыка, миниатюра, «Перейти к оригиналу» |
| `archives` | `nested.zip` (`ZipArchive`) и `nested.tar.gz` (системный `tar.exe`) с одинаковым содержимым — `readme.txt` и `docs\` из двух файлов; `nested.7z`, защищённый паролем `locked.zip`, `nested.rar` (то же содержимое) и `solid.rar` (solid, шесть текстов) копируются из `tests/Fixtures/` по имени (по расширению нельзя: `.zip` там уже занят `texts.zip`); плюс настоящая папка `plain.zip` — контрольный случай; `photos.zip` — шесть JPEG с EXIF-ориентацией без сжатия | архив как папка, пять форматов, извлечение, undo, «пусто или защищено», папка с архивным именем, распаковка для панели одна за раз, миниатюры внутри архива |
| `state` — **не профиль** | `state.json` чужой сборки кладётся в data-dir прогона полем сценария `"state": "0.3.0"` (файл `tests/Fixtures/state/0.3.0.json`) до старта `App`. Файла нет — прогон падает сразу, а не проходит молча. Пути внутри обезличены и ведут в никуда — нормальный случай для сохранённого состояния | чтение чужого состояния, пропавшие папки, настройки из файла |

`.gitignore` игнорирует `*.meta` и `*.lnk` — такие файлы только генерировать.
Очистка — `SandboxBuilder.Remove`: junction удаляется как junction, дальше
снимается read-only (профиль `attrs` пишет такой файл нарочно, а
`Directory.Delete` на нём падает), потом дерево целиком.

**Песочница переживает прогон и делится между сценариями.** Сценарий
убирает за собой сам (`permanent-delete` в конце); упавший на середине — не
убирает, и следующий прогон считает чужие файлы. Отсюда `fs delete` первым
шагом там, где важен точный счёт, и `--rebuild`, когда песочница разъехалась.

- [ ] После **удаления** выделен следующий файл (последний в папке —

- [ ] **Файл удалён в другой программе**: открыть снимок по `Enter`,
      стереть его там, вернуться — выделен следующий, клавиатура на нём

      фильтр «3 звезды и выше», поставить снимку две — выделен следующий,
      клавиатура на нём, прокрутка на месте; то же при наборе в поле
      фильтра (клавиатура остаётся в поле).
- [ ] **Прокрутка переживает чужие правки**: папка прокручена вниз, в
      первой её половине файл удалён или добавлен (здесь или снаружи) —
      список не отматывается в начало.
- [ ] **Выделенный файл не уходит с экрана сам** (харнесс — `follow-row`,

      остальные, начало папки не мелькает; то же — поставить фильтр,

### Файловые операции

- [ ] Деструктивная операция спрашивает, **Cancel по умолчанию** (`Enter`
      ничего не сносит).
- [ ] `Ctrl+Z` откатывает всё, кроме безвозвратного удаления.
- [ ] **История после `Shift+Delete`**: переименовать файл A, перенести B
      в другую папку, удалить B навсегда — `Ctrl+Z` возвращает имя A, а
      переноса B в истории нет (следующий `Ctrl+Z` недоступен); вопрос «не
      помещается в корзину» про очистку истории больше не говорит.
- [ ] **Папки профиля**: `Delete`, `F2`, перенос на «Документах»,
      «Загрузках», «Рабочем столе», `AppData\Local` — отказ по-русски,
      папка на месте; файл внутри «Документов» удаляется и возвращается
      `Ctrl` + `Z`; «Извлечь рядом» в `E:\` работает.
- [ ] «Файл занят» (файл держит PowerShell: `[IO.File]::Open(путь, 'Open',
      'Read', 'None')` в отдельном окне до `Enter`): `Del` и `Shift+Del` —
      окно с именем программы и «Повторить», `Esc` оставляет файл, после
      отпускания «Повторить» удаляет; папка с таким файлом внутри — так
      же; фокус остаётся в Wander, окно отвечает (владелец вопроса — не
      окно операции). Строка состояния называет процесс и без окна.
- [ ] Свои не мешают: удалить / перенести / переименовать файл, открытый в
      панели, — видео на воспроизведении, PDF, текст, FB2, RAW — в обеих
      половинах двойного просмотра: проходит без «занят»; отказ операции
      (файл держит PowerShell) возвращает картинку в панель.
- [ ] Чужой держатель отпускает на ходу (закрыть окно PowerShell в течение
      двух секунд после `Del`): удаление доделывается, строка состояния и
      журнал — «„имя“ был занят (Windows PowerShell …) — отпущен через …».
      Сто занятых файлов разом — ждём две секунды, не двести; окно живое.
- [ ] Переименование занятого файла: окно не замирает, через ~2 с — отказ
      с именем программы.
- [ ] Операция против операции: долгая копия папки и `Del` на файле из неё
      — «занят операцией Wander: Копирование», файл цел; на источнике и в
      цели — часы на значке во всех четырёх видах, выделение и фокус на
      месте, список не перестраивается; в панели — «Идёт: …» / «В очереди: …».
- [ ] Короткая операция без часов: удалить один файл, переименовать,
      скопировать мелкий файл — часы не мигают; долгая копия — часы
      появляются вместе с окном операции (через 0,4 с), не раньше; на
      стенде «Отладка: занять на 5 с» — часы через 0,4 с и до конца.
- [ ] Не помещается в корзину: файл на пути > 260; короткая папка с таким
      файлом внутри — **системного диалога нет**; вопрос называет файлы,
      «Прервать» по умолчанию, `Enter` и `Esc` ничего не удаляют, «Удалить
      безвозвратно» серая первые полсекунды; остальное выделение в корзине.
- [ ] Корзина: `Del` на 1000 файлов — секунды; `Ctrl+Z` возвращает все, с

- [ ] Системный путь упирается в `SystemPathGuard`.
- [ ] Прерванная операция (убить процесс на середине копии): частичная
      копия видна и объяснима, состояние не побито.
- [ ] Перетаскивание **правой кнопкой** из списка, дерева и закладок на

- [ ] ПКМ-перенос RAW со спутниками: «Копировать / Переместить сюда»

`TransferRateTests`, `BatchExecutorTests`), само окно — нет. Окно,
строку состояния и отмену без диска показывает «Отладка» → «Операция».

      одного файла, «X из Y» растёт мегабайтами, скорость и «осталось ~»
      появляются через пару секунд и правдоподобны.
- [ ] Список под окном живой: можно ходить по папкам и смотреть файлы, пока

- [ ] «Отмена» посреди большого файла срабатывает сразу; в целевой папке не

      сначала вопрос, потом окно, не поверх вопроса; пока идёт подсчёт —

- [ ] Строка состояния: значок у предупреждения и ошибки (занятый файл,

- [ ] Свёрнутое: в строке состояния «Копирование: N %», клик — панель,

- [ ] Две операции разом: два окна, обе строки в панели, «Операций: 2 — N %»
      в строке состояния; свернуть обе, вернуть одну.

### Окно совпадений имён

Автотестами закрыта только логика (`ConflictBatch`, `PathSafety`,
`BatchExecutor` в Core); само окно харнесс не поднимает — `ScriptedDialogs`
подменяет `IDialogs` и отвечает по политике. Всё ниже — глазами, на
копировании между папками и на перемещении между дисками.

- [ ] Окно открывается **до** того, как что-то тронуто: `Esc` — и в целевой
      папке ничего не изменилось.
- [ ] Заголовок окна называет операцию и число совпадений; «Из:» и «В:»
      стоят над своими колонками и не разъезжаются при появлении полосы
      прокрутки.
- [ ] На плашках рисуются обе миниатюры (картинка — содержимым, не значком).
- [ ] Галки: левая = замена, правая = оставить как есть, обе = оба файла,
      снятые обе = пара снова не решена; после имени появляется слово
      «заменить» / «оставить» / «оба». Отвергнутая сторона гаснет; когда
      отмечены обе или ни одной — не гаснет ничего.
- [ ] Файл со спутником (`.png` + `.meta`, оба совпали): две строки, у
      каждой свой ответ; «оставить» на png и «заменить» на meta приезжают
      порознь.
- [ ] Больший размер и более свежая дата жирные; когда размер и дата
      совпадают — жирного нет.
- [ ] Одинаковые файлы: у имени стоит «Сравниваем…», потом доезжает «Файлы
      идентичны» — припиской в строке имени; при нескольких крупных (больше
      64 МБ) сначала отмечаются мелкие, окно не виснет.
- [ ] Галка «не спрашивать про одинаковые файлы» стоит с открытия
      (настройка по умолчанию включена): идентичные пары отметились сами
      «оставить»; сняли — вернулись в нерешённые, а то, что выбрано руками,
      осталось.
- [ ] Булеты «применить к нерешённым» не перетирают уже выбранное;
      «заменить, если новее» трогает только те пары, где новее исходник.
- [ ] **«Заменить все»** в шапке: отвечает и за уже решённые строки (в том
      числе за отмеченные «оставить» и за папку, раскрытую на слияние) и
      сразу закрывает окно; после операции `Ctrl+Z` возвращает всё, что
      заменилось. Рядом «Пропустить все» — ничего не перенеслось.
- [ ] Обе кнопки стоят далеко от «ОК» и «Отмена», `Enter` ни к чему не
      привязан, `Esc` — отмена.
- [ ] **ОК** серый, пока решены не все; `Enter` ничего не запускает; `Esc`
      отменяет всю операцию. Нижняя полоса отделена и читается как «конец
      разговора».
- [ ] Размер окна переживает перезапуск; окно на отключённом мониторе
      возвращается на существующий.
- [ ] **Перемещение**: заголовок окна говорит «Перемещение»; после правой
      галки исходник остался на месте — и у идентичной пары тоже.
- [ ] **Папка на папку, обе галки**: под строкой сразу появились
      совпадения внутри с отступом и относительным путём, строка папки
      говорит «слияние: совпадений N, прочих файлов M»; вложенная папка
      пришла в слиянии и раскрыта; переключили папку на «заменить» —
      вложенные строки исчезли, вернули — появились с прежними ответами.
      После ОК: несовпавшие файлы скопировались, совпавшие — по ответам,
      при перемещении опустевшая папка исчезла, `Ctrl` + `Z` вернул всё.
- [ ] Папка на папку, левая галка: «Папка заменится целиком, без слияния»
      видно на самой паре и только при этом выборе.
- [ ] **Извлечение из архива** с совпадением: строки без «Сравниваем…»,
      обе галки на папке дают новое имя, не слияние.
- [ ] **Копия в свою же папку**: `Ctrl` + `V` и `Ctrl` + перетаскивание
      дают «имя (1).ext» без окна; спутник получил такое же имя.
      Перетаскивание без `Ctrl` туда же ничего не делает, папку в саму себя
      и в свою подпапку не бросить.
- [ ] **Вырезать и вставить в ту же папку**: ничего не спрашивается и не
      меняется, вырезание снято, в статусе «Уже в этой папке, вырезание
      снято».

### Действия

Меню «Действия», переименование группой, свои команды и конвертация.
Правила закрыты в Core; окна и внешние программы — только глазами.

- [ ] **Меню в шапке**: без выделения — «Папка: …», терминал живой; на
      одном файле, на двух, в корзине и в архиве (своих действий нет,
      «Извлечь…» живо в архиве); «Частные» — «Нет действий…» и
      «Настроить действия…» (открывает Настройки на «Действиях»); скрытое
      в Настройках пропадает в обоих меню; `Esc` — фокус в списке.
- [ ] **Переименование группой**: 40 фото и `[C]` на три цифры; regex с
      `$1`; `[X]` на RAW (подпись «читается», потом пересчёт); своп
      счётчиком в обратном порядке; совпадение с существующим и с соседом;
      папки; смешанное выделение — строка состояния; `.JPG` → `.jpg`;
      `Ctrl+Z` возвращает всё.
- [ ] **Таблица действий**: открывается с пресетами; программа, которой
      нет, красная с подсказкой; копия пресета правится, пресет не
      удаляется; неверный режим — красная подпись; Отмена диалога
      возвращает таблицу.
- [ ] **Программы**: три блока; найденная — «Найдена в системе» и путь;
      «Указать…» — «Указана вручную», переживает перезапуск, снимает
      красное в таблице действий; «Сбросить» — снова найденная; удалить
      указанный exe — «По указанному пути файла нет»; строка winget
      выделяется и копируется.
- [ ] **Запуск**: ffmpeg на трёх видео — процессы по очереди, окно
      операции «N из 3»; отмена посреди второго — его выход в корзине,
      третий не запускался; битый файл — отчёт с кодом и строкой stderr;
      `Ctrl+Z` после успеха убирает `{name}.mp4` в корзину; «все одной
      командой» с `{list}`; своя «Открыть в Notepad++» с `{path}`,
      консоль скрыта / показана; PDF через LibreOffice — рядом с готовым
      `x.pdf` выходит `x (1).pdf`, готовый цел, `Ctrl+Z` убирает результат
      в корзину; своя строка с `{outdir}` без имени выхода или «все одной
      командой» — красная подпись; результат при
      занятых «x (3)» и «x (4)» называется «x (5)»; «Конвертировать ▸ В
      другую папку… ▸ В MP4» спрашивает папку, результаты в ней, `Ctrl+Z`
      убирает их оттуда; «все одной командой» с ошибкой — одна строка с
      числом файлов в отчёте.
- [ ] **Спутники у RAW + JPEG**: «В JPEG» рядом с `IMG.CR2` и
      `IMG.xmp` — сайдкар остаётся у RAW (одна строка, оценка в панели),
      JPEG отдельной строкой без оценки; перенос JPEG в другую папку не
      уносит `.xmp`.
- [ ] **Панель просмотра и тег ориентации**: портретный JPEG с камеры
      (тег 6 или 8, кадр хранится как снят) и «Превью из RAW» стоят в панели
      ровно, как в Проводнике; после «В JPEG» (пиксели развёрнуты, тег 1)
      тоже ровно, не дважды.
- [ ] **Картинки**: JPEG → PNG; RAW → JPEG 1920; портретный JPEG с
      ориентацией 6 стоит ровно, в свойствах Проводника ориентация
      «нормальная»; дата съёмки, камера, выдержка на месте у JPEG → JPEG и
      JPEG → TIFF; «Превью из RAW» на CR3 и CR2 портретных — стоит ровно в
      Wander и Проводнике, камера и дата в свойствах, быстро; у CR3
      маленькое (`_spv.jpg`) — 1620×1080, большое (`_lpv.jpg`) — полный
      кадр; у CR2 только большое; оба пункта — первые в «Конвертировать».
- [ ] **«Отладка: занять на 30 с»** (меню отладки включено): на файле —
      часы на значке, удаление и перенос отказывают с объяснением,
      Проводник называет занявшим Wander; на двух — по очереди, заявлены
      оба; на папке пункта нет; меню отладки выключено — пунктов нет ни в
      меню, ни в таблице действий.

### Архивы как папки

Сценарий `archives` закрывает вход, листинг, извлечение и гейты; глазами —
то, что он не поднимает.

- [ ] **«Открыть» файл из архива**: временная копия открывается нужной
      программой, строка состояния предупреждает, что правки не вернутся;
      `%LocalAppData%\Wander\tmp` не растёт бесконечно (папка старше суток
      уходит на следующем старте).
- [ ] **«Извлечь…»** из меню: диалог выбора папки, прогресс, отмена на
      середине, `Ctrl` + `Z`; на архиве, выделенном в обычной папке, —
      извлекает всё содержимое. На полный диск или носитель только для
      чтения — причина словами системы; «защищён паролем» — только у
      `locked.zip`.
- [ ] **«Извлечь рядом»**: внутри архива — выделенное появляется в папке
      архива без единого вопроса; повторно — копии с «(1)», старое на
      месте; на архиве в обычной папке — содержимое высыпается туда же и
      выделяется; `Ctrl` + `Z` убирает. Архив в корне флешки (`E:\`) —
      извлекается в корень; в `C:\Windows\Temp` — отказ по-русски.
- [ ] **Из дерева архива**: перетащить папку внутри архива из «Дисков» в
      обычную папку списка, на узел дерева и в Проводник — извлечена;
      правой кнопкой — меню броска с «Копировать сюда»; правый клик без
      движения на строке архива — строчного меню нет. Сам `.zip` из дерева
      — переносится и копируется как файл.
- [ ] **Из архива внутрь Wander**: перетащить запись на строку папки в
      списке, на узел дерева и на закладку-папку — курсор «+», плашка
      «Копировать … в …», после drop файл распакован туда, окно операции,
      `Ctrl` + `Z` убирает; над списком самого архива и над папкой внутри
      архива — стрелка без «нельзя», drop ничего не делает; `Shift` и
      `Alt` не превращают копирование в перенос или ярлык.
- [ ] **Наружу** (шелловский объект данных, автотестом не проверяется):
      перетащить запись из архива в окно Проводника — файл появился,
      распакован шеллом; `Ctrl` + `C` внутри архива → `Ctrl` + `V` в
      Проводнике — то же; перетащить запись в чужую программу (редактор,
      почта). Курсор над целью показывает только копирование — Move из
      архива не предлагается.
- [ ] **Меню внутри архива** — пять строк, ни одной серой; сторонних
      пунктов нет. На архиве в обычной папке рядом с нашими «Извлечь…» и
      «Извлечь рядом» живёт шелловское «Извлечь все…» и работает по-своему.
- [ ] **Ассоциации**: отдать `.7z` 7-Zip'у — архив перестаёт открываться
      папкой (как в Проводнике); вернуть — снова открывается. Перезапуск
      приложения обязателен, набор расширений читается один раз.
- [ ] **`.rar`** на машине с WinRAR: фикстуры нет, проверить живым файлом.
- [ ] **Панель просмотра, архив**: выделить `.zip` в обычной папке —
      список первого уровня, папки сверху, значки по расширению, строка
      «Архив: N файлов · M папок · размер»; на архиве с сотнями записей —
      «и ещё N»; на битом файле с архивным расширением — «архив повреждён
      или защищён», не пустота.
- [ ] **Панель просмотра, запись**: выделить текст, картинку и `.pdf`
      внутри архива — содержимое показывается, футер называет архив;
      стрелками вверх-вниз по записям панель успевает и не мигает
      (повторный выбор той же записи копию не переделывает: в логе одна
      строка `Extract (temporary copy)` на запись); зажатая стрелка по RAR
      из десятков файлов — распаковка одна за раз, программа отзывчива,
      архивы дальше открываются как папки; запись больше 32 МБ — карточка
      про «Открыть», а следующая за ней запись неизвестного формата —
      «просмотр недоступен», не старый текст; в архиве с паролем —
      «просмотр недоступен», без зависания. `%LocalAppData%\Wander\tmp`
      после этого не растёт бесконечно.
- [ ] **Панель просмотра, фон архива**: внутри архива клик по пустому месту
      — список текущей папки архива с заголовком «В архиве: N файлов · M
      папок»; в корне — «Архив: … · размер»; выделенная папка внутри — её
      список.
- [ ] **Извлечение с конфликтом одинаковых файлов**: положить в целевую
      папку копию файла из архива, извлечь — окно само отмечает пару
      одинаковой и (при включённой настройке) отвечает «пропустить»;
      с изменённым файлом того же размера — пара остаётся вопросом.
- [ ] **Архив в дереве**: стоит среди папок, раскрывается в свои папки,
      клик по папке внутри — листинг; пустой архив теряет шеврон при
      раскрытии; drop на узел архива не принимается; закладка на архив
      раскрывается. В панели закладок и в дереве дисков одинаково.
- [ ] **Миниатюры внутри архива**: zip со снимками — галерея с
      миниатюрами, `%LocalAppData%\Wander\tmp` не растёт (zip читается в
      память); 7z / rar — миниатюры по одной, папка `tmp` после пустая
      (копии удаляются сразу); solid `.rar` на 20 снимков — окно не виснет;
      запись больше 32 МБ и без размера — значок; пересобранный архив —
      свежие миниатюры (ключ по mtime архива); RAW и TGA внутри — миниатюры
      есть; смена вида «таблица → плитки» — вторая распаковка у 7z
      известна (TECHDEBT).
- [ ] **Ассоциация у архиватора**: `.rar` / `.7z` отданы WinRAR или 7-Zip —
      `Enter` в списке, путь в адресной строке и узел дерева открывают
      папкой, «Открыть» в меню и двойной щелчок в Проводнике — архиватор;
      строка «Archives open as folders» в начале лога перечисляет
      расширения.

- [ ] Копирование Wander → Explorer и обратно.
- [ ] DnD наружу (Explorer, браузер, редактор) и внутрь; `Ctrl` копирует,

- [ ] Двойной клик открывает ассоциацией.
- [ ] Пункты сторонних приложений в меню запускают их.
- [ ] **Вставка текста и картинки**: текст из Блокнота → `Ctrl+V` в папке —

### Просмотр и галерея

- [ ] **Вид — у папки**: в папке A выбрать «Плитка» — подпись меню «Эта
      папка · закреплён», в папке B вид не сменился; вернуться в A —
      «Плитка»; «Автоматически» в A — вид по правилу, галочка на
      «Автоматически»; «Сделать видом по умолчанию» в B — этот вид у всех
      незакреплённых папок и в «Настройки» → «Галерея»; перезапуск —
      закрепления на месте, `folders.json` в папке данных, в `state.json`
      `ManualViewModes` пуст; автогалерея выключена → папка со снимками
      показана видом по умолчанию, не видом прошлой папки; корзина — вид по
      умолчанию, архив со снимками — галерея; `F2` закреплённой папки в
      Wander и переименование снаружи (Проводник) — закрепление на месте (в
      логе `Folder record follows a rename made outside`); `Ctrl+Z`
      переименования — тоже; недавний путь адресной строки после переноса
      папки — новый.
- [ ] **Сортировка — у папки, меню пустого места**: в папке A по дате (меню
      «Вид», меню пустого места или заголовок таблицы) — в B порядок
      прежний, галочки меню и стрелка заголовка — у каждой свои; «По
      умолчанию» в A — порядок B, «Сделать сортировкой по умолчанию» (без
      закрепления серый) — порядок у всех незакреплённых; перезапуск — на
      месте. Меню пустого места: «Создать», потом «Вид» (подпись «Эта папка
      · …», хоткеи, галочка на виде на экране) и «Сортировка»; выбор в них
      закрепляет за этой папкой, как меню «Вид»; в корзине только «Вид», в
      архиве оба; «Настройки» → «Контекстное меню» → снять «Вид» и
      «Сортировка» — их нет, разделители не двоятся.
- [ ] Панель просмотра: картинка (и `.jfif`), RAW, текст, код, PDF, 3D,
      аудио, веб, папка, диск — по разу.
- [ ] Занятый файл (PowerShell держит без общего доступа) в панели — «кто
      держит», не «просмотр недоступен»; двойной просмотр: у каждой
      половины в левом нижнем углу свои звёзды и резкость, в правом —
      гистограмма (звёзды без мыши — 30 %, гистограмма в полную силу),
      клик по звезде — только этому снимку; футер — сводка, хелперы, RAW,
      без звёзд и гистограммы; лупа на одной половине двигает вторую;
      полоса оценок без слова «Оценка», сброс — стрелкой с подсказкой.
- [ ] **Полный экран**: `Enter` / `Space` на одном снимке, на двух
      (рядом), на трёх и больше (стрелки только по выделенным), на
      смешанном выделении (`Enter` открывает); картинка до краёв, первая
      без надписи «выберите файл» и без паузы на JPEG 45 Мп; снимок без
      полосы и гистограммы, мышь вниз — полоса слева и гистограмма справа
      за миг (у пары — у обеих сразу), цифра — вспышка на 1,5 с, в том
      числе повторная и на занятом сайдкаре (плашка «Не записано…» внизу на
      4 с); `Ctrl` + `Z` — оценка назад со вспышкой; `Z` — лупа держится,
      мышь водит, у пары вторая следует, `Z` — снять; `Alt` + `Space`,
      `F10` — ничего; звёзды мышью, `Shift` + цифра — метка, `Alt`, хелперы
      и **RAW** с полосы (RAW и в панели после выхода); на лупе полоса и
      гистограмма уходят; видео со спутником — полоса над транспортом;
      `Esc` — один снимок оставляет список на последнем, пара и выделение —
      выделение как было.
- [ ] **`Shift` + стрелки на полном экране**: справа встаёт соседний,
      дальше листается правый мимо левого; `←` оставляет левый, `→` —
      правый, без мелькания левого во весь экран; на краю списка ничего не
      происходит; из двух цифра ставит оценку снимку под мышью; под
      фильтром по звёздам оценка, выводящая снимок из фильтра, не сбивает
      стрелки.
- [ ] **`Delete` на полном экране**: с вопросом (включён в «Файловых
      операциях») и без — снимок в корзину, на экране следующий; с
      последнего — предыдущий; последний оставшийся — окно закрывается;
      `Shift` + `Delete` — вопрос всегда, навсегда; из пары — удаляется тот,
      что под мышью, второй остаётся один; `Ctrl` + `Z` — файл вернулся в
      список; зажатый `Delete` удаляет один снимок; `Esc` после удаления —
      список на последнем показанном; в архиве и корзине — ничего.
- [ ] **Курсор на полном экране**: мышь стоит 1,5 с — курсора нет, в том
      числе над снимком, который увеличивается лупой; сдвиг — курсор (лупа
      над таким снимком) сразу; листание стрелками при стоящей мыши курсор
      не возвращает; `Alt` + `Tab` в другое окно — там курсор обычный.
- [ ] **Картинка посередине**: в панели просмотра широкий кадр в высокой
      панели и высокий в широкой — посередине по обеим осям, на полном

## Предрелизный прогон

Дополняет PRERELEASE.md; порядок — от дешёвого к дорогому, регрессия на
любом шаге останавливает релиз.

1. **База**: `check.bat run`, `deps.ps1` без циклов, `metrics.ps1` снимок,
   доки сверены (FINALIZING, п. 5).
2. **Релизная сборка**: `publish.ps1`, размер и SHA, `size-report.ps1`
   против PERFORMANCE (категории не выросли без причины).
3. **Первый запуск и обновление**: чистая машина (Sandbox) — SmartScreen,
   без `state.json`, умолчания, первая папка; поверх прошлой версии —
   `state.json` и кэш.
4. **Функциональный прогон** на песочнице релизным exe: «Всегда» + все
   разделы чек-листов; автоматизированная часть — харнессом, остальное
   руками.
5. **Окружения** — раздел выше, хотя бы DPI и один «странный» том.
6. **Замеры** — таблица ниже, все строки; плюс 30-минутный soak: случайная
   навигация по песочнице — память выходит на плато, handles стабильны, лог
   без `ERROR`, CPU в простое ~0 %.
7. **Итог**: числа — `measurements/<версия>.md` (PRERELEASE, шаг 6),
   находки разложены по спискам, exit-критерии: 0 открытых P0 / P1,
   `WARN` / `ERROR` в сессиях релизного прогона — ноль, метрики в порогах.

## Метрики и пороги

Порог = базлайн прошлой версии (PERFORMANCE, `measurements/`) + 20 %; хуже
— регрессия. Первые базлайны для новых строк снимаются первым прогоном.

| Метрика | Как снять | Порог / базлайн |
|---|---|---|
| Первый кадр | `Startup: first frame N ms`, три запуска релизного exe | ~1650–2050 мс (PERFORMANCE) |
| Неответ UI | `PERF ui.stall` | одиночные < 400 мс, частые < 100; на холодной папке — сотни, не секунды |
| Первый экран | `First screen painted in N ms` по профилю `photos` холодно / тепло | базлайн снять |
| Шаблон плитки | `LAYOUT <вид> container: N visuals` | Tiles 8, Icons 8 (место под бейдж оценки, J4), Gallery 9 (без оценки) |
| Реализации на навигацию | `COUNT layout.new: N in K passes` | K = 1 |
| Раскладка в простое | харнесс: проходы за 5 с без ввода | 0 |
| Миниатюры RAW | `bg.thumb-shell` / `RawThumbnail`, мс на файл | ~3 мс WinRT, 75 через оболочку — регресс |
| Память | `SYS` или харнесс: `WorkingSet64`, `PrivateMemorySize64` — пик и плато после 200 навигаций | smoke 344 / 225 МБ; плато — снять |
| GC | `GC.CollectionCount(0/1/2)`, `GetTotalAllocatedBytes` за окно, `GetGCMemoryInfo` (LOH, % в GC) | gen2 не растёт линейно с навигациями; аллокации на навигацию — снять |
| Handles, потоки | `Process.HandleCount`, `Threads.Count` в soak | стабильны после разогрева |
| CPU | `TotalProcessorTime` дельта: в простое 10 с | ~0 %; таймеры останавливают себя |
| Диск | размер `thumbs` до / после, `bg.thumb-disk-write` | в пределах лимита, подрезка срабатывает |
| Закрытие | `OnClosing` → смерть процесса | окно исчезает сразу; процесс < 2 с |
| Лог | размер файла сессии, повторяющиеся строки | нет заливки одинаковыми исключениями |
| Поиск | время по `big` (5000 файлов) и `docs` с кэшем / без | 0,2 с обход репозитория; кэш ×5 |

**Строка `SYS` в логе** (`SystemVitals`): heartbeat `UiStallWatch` раз в
5 с и на каждый `ui.stall` пишет `SYS ws=… private=… gen=0/1/2 alloc=+N
loh=… handles=… threads=… cpu=… gcpause=+N` (МБ, мс) — замеры и в живых
сессиях, не только в харнессе. Глубже — `dotnet-counters`, `dotnet-trace` /
PerfView, dotTrace из Rider: по требованию, не в прогон.

## Автоматизация — харнесс

Решение 2026-09-02: автоматизировать всё, что даёт адекватный результат;
оконный харнесс в репо — первым: те же кодовые пути, что у пользователя,
~70 % чек-листов, Claude не трогает экран. Отвергнуто: фейковая
`IFileSystem` на всё приложение — App и `Preview/` читают `System.IO`,
миниатюры — шелл, живая проверка работы с файлами теряется. Позже: UIA
(FlaUI) на релизном exe в Windows Sandbox — настоящий ввод и DnD с
Проводником; `--scenario` внутри продукта — только если понадобится
релизный бинарник без UIA. Проверки вне рабочей машины — PLAN T.

`tests/Wander.Harness` — консольный STA-проект со ссылкой на `Wander.App`:
настоящие `App`, `MainWindow`, `MainViewModel`, окно за экраном
(`App.Headless`), сценарий из JSON, артефакты в `artifacts\<имя>-<время>\`
(`report.md`, `screenshots\NN-имя.png`, `metrics.json`, `data\` с логом и
`state.json` прогона). Ввод синтезируется на UI-поток; экран и мышь не
трогаются. `HarnessApp : App` после базового `OnStartup` подменяет сервисы
(ниже), показывает `MainWindow` сам (`InitializeComponent` не зовётся —
BAML ищется в сборке наследника; словари вливаются руками) и стартует
`ScenarioRunner` на `ApplicationIdle`.

```pwsh
.\tools\check.bat qa                              # сборка + selfcheck + smoke-walk, минуты
$h = "tests\Wander.Harness\bin\Debug\net10.0-windows10.0.19041.0\Wander.Harness.exe"
& $h selfcheck                                    # генераторы против читателей Core
& $h sandbox D:\tmp\sb --profiles photos,raw      # песочница руками
& $h run tests\Wander.Harness\Scenarios\smoke-walk.json [--sandbox dir] [--out dir] [--rebuild] [--in-place]
```

Коды: 0 — прошло, 2 — шаг упал (скриншот `fail-N` и причина в отчёте),
70 — упал сам харнесс. `check.bat qa` — отдельный режим, в обычный
`check.bat` не входит: минуты против секунд.

`selfcheck` проверяет генераторы теми классами, которыми их читает
приложение: превью и ориентация из CR3 / DNG / JPEG
(`RawPreviewExtractor`, `MetadataExtractor`), `needle42` из пяти
zip-документов (`ZipDocumentExtractor`), четыре кодировки
(`EncodingProbe`), fb2 с обложкой, теги `tone.wav` (`AudioTags`), «в кубе
12 треугольников» для всех трёх мешей (`MeshFile`), `texture.tga` пиксель в
пиксель против картинки, из которой сделан (`TgaDecoder`), ресурс версии у
`cmd.exe` и `version.dll` (`WindowsExecutableInfo`). Плюс архивы профиля
`archives`: открывает ли шелл **этой** машины каждый из них как папку и
отдаёт ли размер записи — это состояние ассоциаций, не код, и красный шаг
в сценарии `archives` иначе выглядел бы виной приложения. Формат, чью
ассоциацию забрал сторонний архиватор, — строка в отчёте, не падение.
Смысл — отличать сломанный сценарий от кривого тестового файла.

Фикстуры проверяются там же и по тому же правилу: `SandboxBuilder` помнит,
что откуда скопировал (по имени их не найти — имя у фикстуры произвольное, а
расширение может совпасть с генерируемым), и `selfcheck` читает их теми же
классами — теги и обложку у аудио, текст у настоящих docx / epub. Формат, для
которого читателя у нас нет (pdf, doc, webp, zip), только перечисляется:
подменённая фикстура ломается тихо — трек без тегов выглядит как трек без
тегов, и скриншот в `preview-formats` правдоподобен в обоих случаях.

**Что подменяется.** `ILogger` → `CapturingLogger`; `IDialogs` →
`ScriptedDialogs` (ответ по виду диалога, выбор по виду — `AnswerChoice`:
`DeleteInUse` по умолчанию «отмена», `ExitWithOperations` — «принять»;
конфликты по политике, каждый вопрос попадает в отчёт); `IAppStateStore`
не подменяется — пишет в изолированный корень.

`CapturingLogger` слушает событие `FileLogger.Written`, а не свои
собственные вызовы: сервисы из `PlatformBootstrapper` получают логгер в
конструкторе и больше не ищут его в локаторе, поэтому логгер,
зарегистрированный поверх, их строк не видит — и `assert-log noErrors`
пропустил бы их ошибки. Событие поднимается под замком записи: подписчик
не логирует и не блокирует.

Пути в логе прогона настоящие: харнесс сразу после окна включает
`Settings.LogPaths` (у человека по умолчанию метки), и `assert-log` находит
пути песочницы. Первые строки сеанса, до этого, — метками.

**Окно не должно оказаться на экране.** `App.Headless` — окно за экраном
(`Left = -32000`; координаты — в конструкторе `MainWindow`:
`ShowActivated = false` учитывается до показа), не в панели задач,
геометрия не читается и не пишется, крах — лог и `Shutdown(1)`. Ставят
смок и харнесс (`internal set`, `InternalsVisibleTo("Wander.Harness")`); в
`App.OnStartup` флаг только включается (`Headless |= IsSmokeRun`):
присваивание затёрло бы флаг харнесса, и окно вышло бы на рабочий стол с
фокусом. `HarnessApp` перепроверяет флаг и отказывается работать при
выключенном, а позицию окна пишет в лог:
`HARNESS window at (-26214, -26214), taskbar=False, active=False`.

**Диалоги тоже.** WPF ставит окно с `CenterOwner` при владельце в
(−32000, −32000) ровно в (0, 0) — на рабочий стол человека
(`ShowActivated = false` с `ShowDialog` работает). Поэтому каждое окно
приложения зовёт `App.ParkIfHeadless(this)` в конструкторе; новое окно
обязано тоже. `App.WatchWindowsWhenHeadless` пишет в лог каждое окно и
попап (`HEADLESS …`, на экране — `WARN`), эти строки — в отчёт прогона.
2026-09-16 одно окно всё же мелькнуло на кадр, какое — неизвестно; отсюда
правило «сценарии только по просьбе» ниже.

**Свой рабочий стол** (2026-09-29). Окно за экраном и без активации всё
равно забирало системный фокус: при первом переносе клавиатуры внутри
окна (редактор имени на шаге `new-folder`) WPF отдаёт окну Win32-фокус,
окно активируется и выходит в foreground — у человека видео в браузере
выходило из полного экрана.
`WS_EX_NOACTIVATE` не годится: с ним WPF клавиатуру не даёт вовсе
(`AcquireFocus` ждёт Win32-фокуса в потоке), а шаги смотрят именно её.
Поэтому `run` запускает себя заново на отдельном рабочем столе Windows —
`HarnessDesktop`: `CreateDesktop` «WanderHarness», `STARTUPINFO.lpDesktop`,
та же консоль, тот же вывод и код выхода. Foreground у каждого рабочего
стола свой, и окно прогона — WPF, шелла, WebView2 — на экран человека не
попадает. Второй процесс — в job с `KILL_ON_JOB_CLOSE`: прогон, убитый
снаружи, не оставляет приложение, которого никто не видит. `--in-place` —
сценарий в этом же процессе, на рабочем столе запуска: для отладчика.
Проверка — наблюдатель за `GetForegroundWindow` раз в 10 мс (только
чтение): до правки окно харнесса вышло в foreground на шаге 3 `file-ops`,
после — ни разу за десять сценариев; шаги, время и скриншоты те же. Smoke
(`--smoke`) под тем же наблюдателем foreground не взял (один прогон) — как
и старт сценария до первого шага с клавиатурой.

**Поля сценария**: `name`, `sandbox` (папка под `%TEMP%\wander-sandbox`),
`profiles[]`, `state` (таблица профилей; кладёт `Program.SeedState`),
`stopOnFailure`,
`stepTimeoutMs`, `steps[]`. Комментарии `//` разрешены.

tolerance, onScreen: false}` (строка на экране; `kept` — там, где её
оставил последний `place`, под каким бы именем и среди каких бы строк она
ни была; место читается с контейнера строки, не из арифметики вида),
`bookmark {op: add|remove, path}`, `search {name, text, subfolders,
binaries, searchTimeoutMs | box}` (`box` — набрано в поле над списком:
живой фильтр и обход подпапок, который его продолжает),
`soak {minutes, maxWorkingSetGrowthMb, maxHandleGrowth, seed}`,
`assert-log {contains | regex | absent | noErrors [+ allow[]], scope:
step|all}`, `assert-entries {count | min | max | contains | absent |
selected, scope: model|visible}`, `assert-path {is, crumbs[]}`,
`assert-pane {minList}` (ширина окна, панели просмотра и остатка под
список — в отчёт; `minList` роняет шаг, если списку осталось меньше),
`drop {paths[], target, effect: Copy|Move|Link}` (drop прямо во вьюмодель,
минуя WPF: маршрут записи архива в извлечение, подтверждения, прогресс,
undo; цель только в песочнице), `measure name`, `sleep ms`, `note text`.

У любого шага — `ifOpensAsFolder` с путём архива: шаг идёт, только если
приложение открывает этот архив папкой на этой машине; при WinRAR или
7-Zip на ассоциации — строка `skipped` с причиной, и в журнале батчей
такой шаг не считается. Спрашивается приложение, а не реестр: научится
Wander открывать формат сам — шаг пойдёт без правки сценария.

`command` и `key` ходят через `CanExecute` и через
`Window.InputBindings`, как настоящая строка меню и настоящий хоткей:
недоступная команда не выполняется, а пишет строку в «Notes» отчёта — так
проверяется, что внутри архива или корзины она именно не срабатывает.
Синтетическое событие клавиши мимо `InputBindings` пролетает (WPF сверяет
их внутри input manager), поэтому раннер сверяет их сам — но только когда
событие никто не обработал. `Enter` в таблице обрабатывает сам список
(`FileListView.List_PreviewKeyDown`: `DataGrid` гасил бы клавишу до
хоткея); `focus-keys` жмёт его в таблице, `archives` — в плитках.

`tree-expand` идёт по уровням — `ChevronToggled` на каждый и ожидание, пока
уровень прочитан (`LevelState.Loaded`): ветка читает детей с диска в
момент раскрытия, и путь на шесть уровней вниз до этого просто не
находится.

`post` и `assert-state` проверяют взаимодействие без WPF-ввода: событие
уходит в `WorkspaceController` тем же путём, что от вью, состояние
читается из модели; `assert-focus` — что сделал исполнитель. Окно
харнесса никогда не активно, поэтому активация — `post WindowActivated`,
а не ожидание: так проверяется перечитывание раскрытого при возврате в
окно. Отложенный до активации перенос клавиатуры живёт в исполнителе
окна, а харнессу исполнитель отвечает сразу — он проверяется глазами
(«Фокус», «Окно в фоне»). Логику цели харнесс не повторяет —
`tree-target` сообщает факты, цель выводит модель.

`assert-entries scope: visible` считает то, что показывает список, а не
`Entries`: **маска имени фильтрует вид, а не `Entries`** — после
`search name` вьюмодель держит всю папку, и проверка по ней проходит,
сработал поиск или нет. Поиск по содержимому кладёт результаты прямо в
`Entries`, там `scope` не нужен.

`preview-format` — для форматов, которые никто не генерирует: они приезжают
из `tests/Fixtures/` по расширению, и на машине без фикстуры сценарий обязан
пройти. Берёт первое совпадение по имени, поэтому годится только там, где
генератор такого расширения не пишет: `.pdf` в `docs` — это сгенерированный
`manual.pdf`, у которого свой шаг. Чего не нашлось, перечислено в отчёте
списком «эту ветку панели не открывали».

`assert-log noErrors` + `allow[]` — сценарий, который **нарочно** вызывает
ошибку (занятый файл, безвозвратное удаление), называет её. Именно
называет: ожидаемая ошибка остаётся проверяемой, а не становится уровнем,
на который перестали смотреть.

`soak` меряет плато **от конца первой минуты**, а не от старта: первая
минута — это заполнение кэша миниатюр, и на ней провалился бы любой
прогон. Отсюда минимум три минуты (одна на прогрев, две на наблюдение);
предрелизные тридцать — это `"minutes": 30` при тех же порогах.

списком «посмотреть глазами».

**«Тишина»** = `IsListLoading == false`, строка `First screen painted` для
папки, в которую навигировали (ждём до 5 с), и ничего в логе 400 мс.
Скриншот — `RenderTargetBitmap` визуального дерева: WebView2 (HWND) в нём
пустой.

**Прогоны.** Числа харнесса — Debug плюс сам харнесс в том же процессе:
базлайн харнесса, не приложения. Ожидаемое в чистом прогоне: `ERROR` —
только нарочные (`locked.txt` в `file-ops`, извлечение из архива с
паролем), `WARN` — только «Permanent delete», которым сценарий убирает за
собой; окна — только главное, за экраном. Числа по версиям — сценарии, пик
WS, gen2, хэндлы, soak-30 — в [measurements/](measurements/README.md).
Последний полный прогон — `measurements/0.5-dev.md`.

**Кто что делает** (команда и правило раздела — WORKFLOW.md: Фабле —
решения и риск, Опус — механика):

| Роль | Кто |
|---|---|
| Спроектировать сценарии под правку, разобрать падение, оценить скриншоты на UX-регрессию, разведочный «ручной» прогон через харнесс шаг за шагом | Фабле |
| Прогнать набор, сверить лог и метрики с порогами, собрать отчёт, разложить находки по спискам | Опус |
| Всё с настоящим Проводником, мышью и глазом; экзотические тома; решение «релиз / не релиз» | человек |

Claude никогда не ведёт настоящий рабочий стол: харнесс — только окно за
экраном; UIA — только внутри Sandbox / VM, где чужого экрана нет.

**Когда что гоняется.** Чем дороже прогон, тем ближе он к концу работы, а
не к каждой правке.

| Повод | Что запускается |
|---|---|
| Любая правка кода | `check.bat` |
| Тронуты XAML, ресурсы, регистрация сервисов, старт | + `check.bat run` |
| Тронуты генераторы песочницы или состав `tests/Fixtures/` | `selfcheck` (секунды) |
| Правка в области, у которой есть сценарий (матрица «трогал → проверь») | этот сценарий, `--rebuild` если менялся состав песочницы — по слову «прогони автотесты <сценарий>» |
| Не воспроизводится по коду: «прыгает фокус», «пропала миниатюра», «что там в панели» | сценарий-однодневка рядом с нужной папкой, находки — `note` в отчёт — по просьбе |
| Финализация куска работ («финализируй») | `check.bat run`; `check.bat qa` и сценарии задетой фичи Claude называет и ждёт слова «прогони» |
| **Подготовка к релизу версии** (`X.Y.0`, PRERELEASE.md) | lint Rider по `src` + весь набор + `soak` с `"minutes": 30` + замеры версии |
| **Подготовка к патч-релизу** (`X.Y.Z`, PRERELEASE.md, «Ветка патча») | lint изменённых файлов, `check.bat run`, `check.bat qa`, сценарии задетого по матрице; `soak` — если тронуты память, кэши, миниатюры, сторож |

**Сценарии харнесса запускаются по словам** — слова, кто запускает и что
кладёт в отчёт: WORKFLOW, «Автотесты»; причина — абзац «Диалоги тоже».

**Чек-лист для человека** — в приложении, автоматический (PLAN N, не
решено): после фичи Claude добавляет пункты «что посмотреть глазами»,
приложение отмечает само то, что видит, остальное — человек; можно
дописывать и пропускать. Пока его нет — пункты в отчёте Claude в чате.

## Что ещё берут из практики QA

- **Находка = шаги, ожидание, факт, строка версии (`v… R, коммит, дата`),
  лог сессии, скриншот.** Для лога, который читать самому, — в «Отладке и
  сбросе» «Писать настоящие пути к файлам» и «Записывать клавиши, клики и
  выделение» (по умолчанию пути — метки, действий нет). Severity: P0
  потеря данных / падение, P1 не работает фича, P2 неудобно, P3 косметика.
- **Теги набора**: smoke (минуты) / regression (час) / release (день);
  флаки считаются и чинятся, не «перезапустил».
- **Базлайны по релизам** — `measurements/`, по файлу на версию; тренд
  важнее одного числа.
- **Сценарии потери данных**: kill на середине копии, диск заполнен (VHDX
  50 МБ), `state.json` при внезапном закрытии, два экземпляра Wander на
  одном кэше.
- **Первый запуск / обновление / удаление** (портативный: удалить папку
  данных) — отдельный проход, не «и так работает».
- **Доступность-минимум**: клавиатурой всё, DPI, контраст; Narrator и
  `AutomationProperties` — когда дойдут руки.
- **Безопасность превью**: html с JS и внешними ресурсами, имена с `..`,
  циклы junction, будущие архивы — zip-бомба и `../` в записях.
