# Wander — финализация скоупа

Что сделать, когда кусок работы закончен: фича доведена, спринт закрыт,
серия правок по теме завершена. Мелкий багфикс из трёх строк этого не
требует. Каждый пункт — из реальной болячки: незамеченный баг в свежем
коде, доки, которые врут, «сделано» наполовину, забытая находка.

## 1. Зелёная проверка

```pwsh
.\tools\check.bat run
```

Именно с `run`: smoke ловит сломанный XAML, необъявленный ресурс, падение
на старте; окно за экраном, ничего не появляется. Зелёная **целиком**:
«один тест мигает, он всегда мигал» — невыполненная работа (чинить обычно
тест).

## 2. Перечитать собственный диф

Свежий код читается один раз — сейчас. Искать:

- **Правила проекта.** Новая операция с файлами: `SystemPathGuard`, лог,
  `IUndoableAction`, подтверждение с Cancel по умолчанию. Отступление —
  осознанное и записанное.
- **Слои.** Core не знает про Windows и UI.
- **Потоки.** Что попало на UI-поток: перечисление, обход дерева, диск в
  конструкторе вьюмодели или обработчике настроек.
- **Обходы деревьев.** Есть ли предел глубины? Junction на предка даёт
  бесконечную цепочку **различных** путей — множество посещённых не спасает.
- **Временные файлы и кэши.** Что останется, если операция упала на
  середине; попадёт ли под чистку и лимит.
- **Отмена.** Ранний `return` по токену не оставил ли флаг (спиннер,
  «занято»).
- **Формат-строки.** Пользовательский ввод — аргумент, никогда шаблон.

## 3. Проверить то, что тестами не покрыто

Тесты только на Core. Список для прокликивания составить **до** показа —
QA.md («трогал → проверь» и чек-листы), разделы, которых коснулся диф;
найденное дописать туда. В
отчёте: проверено сборкой и тестами / проверено руками / не проверялось и
почему. Честный список лучше «вроде работает».

## 4. Разложить по спискам

| Что получилось | Куда |
|---|---|
| Работает, часть продукта | **DONE.md** — переносом из PLAN |
| Обязательная цель, не сделана | **PLAN.md** |
| Обсудили, отложили, знаем зачем | **BACKLOG.md** |
| Мелочь по дороге | **TECHDEBT.md** |
| Решили не делать | **REJECTED.md** — с причиной |

Закрытый пункт **уезжает** в DONE, не остаётся зачёркнутым (короткая строка
со ссылкой — если держит контекст соседей). В DONE — **как работает
сейчас**, не как делали; история — CHANGELOG и гит. Списки не чистить
самостоятельно.

## 5. Сверить доки с кодом

- **GUIDE.md** — новые жесты, настройки, изменившееся поведение; и то, что
  **исчезло**.
- **ARCHITECTURE.md** — новый механизм, абстракция, папка, отступление от
  правила.
- **CHANGELOG.md** — `Unreleased`, языком пользователя; если фича по дороге
  изменилась — поправить уже написанную запись, не дописывать опровержение.
- **README.md** — «в планах» про сделанное, «пока не умеет» про то, что
  умеет.
- **Числа** — тесты, строки ресурсов, версии: устаревшее число учит не
  доверять соседним фразам.

## 6. Оставить дерево человеку

Гит на чтение. Результат незастейджен, в отчёте: что сделано и почему так
(если неочевидно); что **не** сделано из запрошенного и почему; что
проверено, что осталось руками; открытые вопросы.

## Чего не делать

Рефакторить «заодно» (в TECHDEBT); прятать проблемы (баг в своём свежем
коде — чинить и говорить); дописывать фичи (новое — следующий скоуп).

Скоуп заканчивается релизом — дальше RELEASING.md.
