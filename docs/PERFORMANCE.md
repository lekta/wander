# Wander — вес, скорость, поставка

Цифры и выводы, чтобы не мерить заново и не спорить по памяти. Машина:
Windows 11 26200, x64, SSD, прогретый кэш; версия 0.2.1-beta. Абсолютные
значения машинозависимы, сравнивать варианты между собой. Вес, поставка и
путь до первого кадра — 2026-08-27 харнессами; «Замер 2026-08-31» — первый
прогон релизной сборки по RELEASING.

## Чем мерить

- **Состав exe** — `tools\size-report.ps1 [-Keep]`: публикует папкой, жмёт
  каждый файл gzip, раскладывает по категориям.
- **Старт** — строка лога на `ContentRendered`: `Startup: first frame 1583
  ms after process start`. Только с опубликованного exe. Считается от
  старта процесса (включает рантайм); `Loaded` срабатывает ~900 мс раньше
  первого кадра — мерить по нему значит обманывать себя.
- **Память** — пиковый working set снаружи (`Process.WorkingSet64` в цикле).

## Вес

Портативный exe — **73,8 МиБ** (self-contained, один файл, сжатие).

| Категория | Распак. | Сжато | Доля |
|---|---|---|---|
| Прочая BCL (`System.*`, 198 файлов) | 54,3 МБ | 23,8 МБ | **32,9 %** |
| WPF | 44,9 | 19,1 | 26,5 % |
| Ядро CLR | 24,1 | 10,6 | 14,6 % |
| WinForms (не используется) | 24,6 | 8,1 | 11,2 % |
| Проекция WinRT (рендер PDF) | 23,7 | 5,9 | 8,1 % |
| Отладочные компоненты | 5,9 | 2,6 | 3,6 % |
| NuGet-зависимости | 4,0 | 1,3 | 1,9 % |
| Сателлиты локализации .NET | 1,6 | 0,5 | 0,7 % |
| **Код Wander** | 1,1 | 0,5 | **0,6 %** |

- **Trimming закрыт**: `NETSDK1168: WPF не поддерживается с обрезкой` —
  44 % файла (BCL + WinForms) трогать нечем; WinForms едет потому, что
  self-contained копирует `Microsoft.WindowsDesktop.App` целиком.
- **WinRT 5,9 МБ** — цена рендера PDF (`PdfPageImage`, `Windows.Data.Pdf`);
  на TFM без версии SDK четыре ошибки компиляции.
- **Урезано** (79,1 → 73,8 МиБ, `Wander.App.csproj`):
  `CopyDocumentationFilesFromPackages=false` (766 КБ XML WebView2);
  `SatelliteResourceLanguages=en;ru` (5,3 МБ; `ru` нужен — тексты
  исключений .NET доходят до пользователя).

## Скорость запуска

| До чего | мс от старта |
|---|---|
| рантайм поднят, логгер пишет | 250 |
| окно `Loaded` | ~610 |
| **первый кадр** | **~1650** |

| Вариант | Размер | Первый кадр |
|---|---|---|
| self-contained, сжатый (текущий) | 73,8 МиБ | ~1650 |
| + ReadyToRun | 92 МиБ | ~1620 |
| без сжатия | 175 МиБ | ~1640 |
| framework-dependent | 28 МБ + файлы | ~1350 |

**Формат бандла ради скорости менять бессмысленно**: даже отказ от
self-contained — 300 мс из 1650. ReadyToRun при сжатии бесполезен —
+19 МиБ, распаковка съедает экономию на JIT.

**Где время** (харнесс, создание контролов в чистом WPF-процессе):
`new AvalonEdit.TextEditor()` — **138 мс** первый раз, `new WebView2()` —
21 мс; оба создаются при разборе XAML `PreviewPane` даже при скрытой
панели, там же четыре `.xshd` — ~160 мс снимаются ленивым созданием
(BACKLOG). `FolderTreesController.LoadRoots` синхронно спрашивает
`HasSubdirectories` по дискам до окна (TECHDEBT). Оставшиеся ~850 мс —
первая отрисовка WPF (BAML `MainWindow.xaml`, шаблоны, шрифты, JIT);
нужны точки замера в фазе рендера.

## Замер 2026-08-31: первый прогон релизной сборки

Первый кадр — 1878, 2026, 2051 мс против ~1650 (2026-08-27). Не регрессия
кода как таковая: тот замер был до галереи, оценок, спутников, окна поиска
и на другой стартовой папке (сейчас 27 элементов с обложками и оверлеями);

## Миниатюры RAW мимо оболочки

Жалоба «галерея открывается с задержкой» (2026-08-29). Харнесс: 40 CR3,
256 px, холодный `thumbcache`:

| Путь | Один поток | 8 потоков | Худший |
|---|---|---|---|
| `IShellItemImageFactory` (было) | **75 мс/файл** | не масштабируется | 350 |
| Встроенный JPEG + GDI+ | 20 | 19 | 36 |
| Встроенный JPEG + WinRT `BitmapDecoder` | 20 | **3** | — |

Выводы в коде: у RAW внутри готовый JPEG — `RawThumbnail` для Large и
Medium, ориентация из контейнера (40 из 40 совпали с оболочкой); GDI+
сериализуется на блокировке — WinRT `Windows.Graphics.Imaging` даёт
масштабированный DCT-декод без пакета и без WPF в Platform; ворота
`AsyncIcon` 2 → 4. Экран из 24 ячеек: ~900 → 50–100 мс. JPEG остались на
оболочке (быстро, пишет в общий кэш). Потеряно: оверлей ярлыка на самом RAW.

`Folder listed in 812 ms: 1043 shown, 12 hidden — путь` при > 300 мс.
Счётчики `COUNT layout.*` и `LAYOUT … visuals` — DONE, «Диагностика».

## Память

Пик за `--smoke`: self-contained сжатый — 344 МБ working set / 225 private;
framework-dependent — 211 / 156. Разница — распакованные сборки живут в
памяти вместо отображения с диска: сжатие экономит 100 МБ на диске и стоит
~130 МБ на экземпляр.

## Закрытие

Между `OnClosing` и смертью процесса ~1430 мс (COM shell-расширения,
финализация, рантайм). `MainWindow.OnClosing` делает `Hide()` после
сохранения геометрии, до освобождения COM — окно исчезает сразу.
`Environment.Exit(0)` не сделан намеренно: пропускает флаши, неправ при
незавершённой операции.

## Поставка

Сейчас — портативный self-contained exe (`publish.ps1`). **Framework-
dependent отложен**: 28 МБ, −300 мс, −130 МБ памяти, но нужен .NET 10
Desktop Runtime (инсталлятор ~58 МБ, на диске ~172, в Windows не входит,
.NET 10 свежий — у случайного пользователя его нет); apphost покажет диалог
со ссылкой — удар по «скачал и запустил». Промежуточный вариант — обе
сборки в релизе ценой второго артефакта.

Влияние веса: на гит нулевое (`bin/`, `obj/`, `publish/` в `.gitignore`;
пак 1,8 МБ, дерево 4 МБ); релиз — 74 МБ на ассет и на скачивание, в историю
не попадает; локально дерево с выхлопом > 300 МБ, заметная часть —
протухшие `bin/*/net10.0-windows` и `*_wpftmp*`, `dotnet clean` не убирает.
